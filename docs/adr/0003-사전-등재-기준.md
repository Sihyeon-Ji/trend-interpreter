# ADR 0003. 사전 등재 기준: 유래가 적힌 참고 문서가 있는 밈만 싣고, 커뮤니티 글은 지표로만

상태 **확정** · 결정일 **2026-09-29** · 관련 [ADR 0001 서비스 방향](0001-서비스-방향.md) · [Plan 03 리스크](../plans/03-term-risk.md) · [Plan 04 대시보드](../plans/04-target-regions-and-keyword-dashboard.md) · [Plan 12 사전 전수 대조](../plans/12-dictionary-crosscheck.md)

## 배경

사용자 결정(2026-09-29): 블루스키·디시인사이드 같은 곳의 글을 사전에 넣지 않는다. 사람들이 아무렇게나 쓴 글까지 모두 세게 되고 뜻을 알려 주지도 않는다.
유래가 적힌 참고 문서(나무위키 같은 곳)에 오른 말만 사전에 싣고, 커뮤니티는 뒤에서 **얼마나 쓰이는지 재는 지표로만** 쓴다.

결정 전의 코드와 운영 데이터(2026-09-29)는 다음과 같았습니다.

| 확인한 것 | 값 |
| --- | --- |
| 커뮤니티 근거 | 6,244건 — bsky.app 3,177 · naver:kin 867 · naver:cafearticle 842 · reddit 710 · lemmy.world 240 · 디시인사이드 178 · news.ycombinator.com 92 · youtube.com/comments 74 |
| 참고 문서 근거 | 확인된 표제어 148개 가운데 54개에 위키 근거가 없음 |
| 자동 등재 규칙 | 표제어가 든 독립 출처 2곳 + 1차 근거. 커뮤니티 글도 독립 출처로 세서 커뮤니티 글 하나와 기사 하나만으로 자동 등재될 수 있었음 |
| 리스크 이유 | `pipeline/risk.py`의 `quote()`가 걸린 근거 문장을 그대로 인용 → 블루스키·디시 문장이 사전 항목과 추천 화면에 나감 |
| 화면 | 대시보드 표의 '주로 보인 곳' 칸과 사전 항목의 '주로 보인 곳' 줄이 커뮤니티 사이트 이름을, 출처 표·추천 근거 링크가 커뮤니티 글 제목·링크를 보임 |

## 결정

### 1. 사전 등재 기준

자동으로 사전에 싣는 말(`verified_auto`)은 **참고 문서**에 표제어가 든 문서가 있어야 합니다. 판정은 규칙 코드(`verification.gate`)가 하고,
표제어가 실제로 들어 있는지는 `match.mentions()`로만 봅니다. 모델 출력은 이 판정에 쓰지 않습니다.

| 참고 문서 | 도메인 |
| --- | --- |
| 나무위키 | `namu.wiki` |
| 위키백과 (모든 언어판) | `*.wikipedia.org` |
| Know Your Meme | `knowyourmeme.com` |
| pixiv 백과사전 | `dic.pixiv.net` |
| 萌娘百科 | `zh.moegirl.org.cn` |

- 위키·웹 근거이고 주소가 그 도메인의 문서여야 합니다. 나무위키 실시간 검색어(검색 순위), 홈페이지 주소, 표제어가 없는 문서는 참고 문서가 아닙니다.
- 기존 게이트 규칙(독립 출처 2곳, 1차 근거, 풀이가 원문에 있는가, 자기확신)은 그대로 두고 이 규칙을 더합니다.
- 문서가 없으면 검수 대기(`needs_review`)로 가고, 검수 화면에 사유 "참고 문서(나무위키·위키백과·Know Your Meme 등)에 유래가 없어 사람이 확인한 뒤에만 실립니다"가 붙습니다.
  사람이 볼 일이 없는 것으로 보고 큐에서 닫는 사유(표현이 아님·뜻이 빔 등)가 아니므로 검수 큐에 남습니다.
- **예외 길은 사람의 승인입니다.** 검수자가 승인하면 문서가 없어도 실립니다(`verified_human`). 태국어·타갈로그어 위키백과에는 밈 분류가 없는 등([Plan 04](../plans/04-target-regions-and-keyword-dashboard.md) 결과)
  참고 위키가 드문 지역의 말이 이 길로 들어옵니다.

### 2. 커뮤니티·SNS 글은 지표로만

| 구분 | 내용 |
| --- | --- |
| 대상 | 수집기가 `community`로 넣는 글(디시인사이드·더쿠·에펨코리아·인스티즈·루리웹·클리앙·뽐뿌·네이버 카페·지식iN·Bluesky·Reddit·유튜브 댓글·Dcard·PTT·Pantip·Kaskus·Togetter·ガールズちゃんねる 등)과, 기사·웹 문서로 들어온 같은 사이트와 SNS(X·Threads·Instagram·Facebook)의 글 |
| 세는 곳 | 마지막 쓰임, 뉘앙스(긍정·중립·부정) 수, 주간 쓰임·생애주기·확산 단계(`track`), 리스크 판정(`risk`), 검증 게이트의 독립 출처 수 |
| 내지 않는 곳 | 사전 항목 출처, 검수 화면 근거, 대시보드 카드의 최근 근거, 추천 근거 링크, 질문 답의 출처 이름·건수, 나라 화면 '검색이 늘어난 이유' 근거, 그래프 API 근거, 실시간 찾아보기 |

- 구글 뉴스는 한국 커뮤니티 글을 기사로 주기도 하고(출처 이름 '디시인사이드' 등), 조사 모델이 커뮤니티 글 링크를 근거로 들기도 해서 근거 종류만으로는 가를 수 없습니다.
  판별은 `collectors/community.is_community_post` 한 곳에서 합니다(사이트는 그 도메인이거나 하위 도메인일 때만).
- 대시보드 표의 '주로 보인 곳' 칸과 사전 항목의 '주로 보인 곳' 줄을 없앱니다. API의 `KeywordCard.communities`는 예전 화면이 깨지지 않게 칸만 남기고 늘 비웁니다.

### 3. 리스크 이유

- 이유에는 기사·쇼츠·문서 문장만 인용합니다(네이버 검색 결과 제외).
- 걸린 근거가 커뮤니티 글이면 글을 옮기거나 사이트 이름을 대지 않고 건수·비율만 적습니다. 예: "커뮤니티 글에서 혐오·차별 맥락으로 쓰인 경우 3건", "커뮤니티 글의 40%가 부정적인 맥락".
- 판정 규칙([Plan 03](../plans/03-term-risk.md) 규칙표)은 그대로이고, 커뮤니티 글도 전처럼 판정에 셉니다.

### 4. 수집 범위

- Lemmy(`lemmy.world`)와 Hacker News는 목표 지역([ADR 0001](0001-서비스-방향.md) §3) 밖의 영어권 커뮤니티라 수집을 멈춥니다. 이미 모은 글은 지우지 않고 지표로 둡니다.
- Bluesky·Reddit·네이버·구글에 색인된 커뮤니티 글·유튜브 댓글은 계속 모읍니다.
- 실시간 찾아보기(사전에 없는 말을 채팅에서 그 자리에서 찾기)는 위키백과·위키낱말사전만 읽습니다. 찾아본 곳이 이용자에게 출처로 보이기 때문입니다(전에는 Lemmy·Bluesky도 읽었습니다).

### 5. 이미 실린 말

- 코드가 자동으로 내리지 않습니다. 현행 뜻이 이미 확인된 말(`verified_auto`·`verified_human`)을 다시 조사할 때는 참고 문서 규칙을 적용하지 않습니다. 다른 게이트 규칙은 그대로 적용됩니다.
- 기존 확인 항목은 [Plan 12](../plans/12-dictionary-crosscheck.md)의 전수조사로 참고 위키와 대조하고, 문서가 없는 말은 사용자가 확인한 뒤에만 검수 대기로 돌립니다.

## 하지 않기로 한 것

- **커뮤니티 글 수집 중단**: 쓰임·확산·리스크를 재는 데 필요합니다.
- **커뮤니티 사이트 이름을 순위·요약으로 보이는 것**: '주로 보인 곳' 같은 칸을 두지 않습니다.
- **기존 확인 항목의 일괄 강등**: 참고 문서가 없는 54개도 전수조사와 사용자 확인 전에는 그대로 둡니다.
- **모델이 '문서가 있다'·'유래가 맞다'고 판정하는 것**: 문서가 있는지는 규칙 코드가, 뜻이 문서와 맞는지는 사람이 봅니다.
- **니코니코 대백과 수집과 pixiv 백과사전의 봇 확인 우회**: 니코니코 대백과는 이 서버의 요청을 막고, pixiv 백과사전은 대부분 봇 확인 뒤에 있습니다.

## 보완 (2026-09-30, 사용자 결정)

- **참고 문서가 있으면 그것만으로 싣는다.** 나무위키·위키백과·Know Your Meme·pixiv 백과사전·萌娘百科 가운데 한 곳에 표제어가 든 문서가 있으면 게이트는 '독립 출처 2곳', '1차 근거(쇼츠·뉴스·데이터랩)', '모델 자기확신' 을 보지 않는다(`verification.gate`의 `documented`).
  커뮤니티 글을 근거에서 뺀 뒤로 출처 2곳 규칙을 채우던 것이 사라져, 나무위키 문서만 있는 한국 밈이 모두 검수 대기로 갔다.
  이 결정을 실제 판정에 다시 적용하니(모델 호출 없이, `scripts/regate.py`) 트윈의 검수 대기 69개가 실렸다(151 → 221).
- **커뮤니티·SNS 글은 게이트의 어떤 셈에도 들지 않는다.** Bluesky·디시인사이드·더쿠·Reddit 등(`collectors.community.is_community_post`)은 몇 곳이든 출처로 세지 않는다.
- 내용 검사는 그대로다: 빈 뜻, 모델이 든 링크에 표제어 없음, 풀이가 원문에 없음, 현행 뜻과 충돌.
- 위키 밈 분류에서 가져온 말([Plan 16](../plans/16-wiki-meme-catalog-and-tendency.md))은 편집자가 밈으로 분류한 것이므로 모델의 '표현이 아님' 판단으로 막지 않는다.
  분류 밖의 말(일반 위키백과 문서에서 온 회사·제품 등)은 그대로 막는다.
- 이미 실린 말을 다시 조사할 때는 출처 규칙으로 강등하지 않는다. 기존 항목은 Plan 12 의 '문서 없음 14일' 규칙으로 사람이 정리한다.
- Know Your Meme 은 문서 주소·제목만 쓰는 조건으로 켜기로 했다(2026-09-30, Plan 12).
