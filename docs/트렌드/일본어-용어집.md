# 일본어 화면 용어집과 문체 규칙

작성일 **2026-10-12** · 담당 **ktwoo(김태우)** · 상태 **화면 문구 반영 완료 – 일본어 화자 검토 전** · 계획 [문구 흐름 남은 일과 일본어 화면 B절](../plans/ktwoo-copy-flow-and-japanese-ui.md#b-일본어-화면)

화면 문구(`apps/trend-web/lib/i18n.ts`, `components/stage/copy.ts`, `lib/labels.ts`)의 일본어판을 쓰고 고칠 때 이 문서를 따른다. 새 키를 더할 때도 같다.

## 1. 기준

- **영어판을 바탕으로 옮긴다.** 한국어판과 뜻이 다르면 한국어판을 따른다(한국어판이 원본이다).
- **밈·유행어 원문은 번역하지 않는다.** 표제어·별칭·문구 속 밈 이름은 원래 글자 그대로 둔다. 뜻·유래·뉘앙스만 언어별로 둔다.
- **내부 용어를 이용자 화면에 내지 않는다.** 에이전트·게이트·확신도·점수·판 번호·모델 이름(관리 화면과 '이 서비스는 어떻게 만들어지나요'는 한국어판·영어판이 이미 이름을 쓰는 곳만 그대로).
- 말투는 일본 기업용 B2B SaaS 화면. 정중하되 겸양 표현(〜させていただきます)은 쓰지 않는다.

## 3. 표기

- 구두점은 전각 「、」「。」, 물음표·느낌표는 「？」「！」, 쌍점은 「：」.
- 괄호는 전각 「（）」. 화면의 버튼·메뉴 이름을 가리킬 때는 「」.
- 낱말 나열은 「・」, 문장 속 나열은 「、」.
- 라틴 글자·숫자는 반각. 일본어와 라틴 글자·숫자 사이에 띄어쓰기를 넣지 않는다. 라틴 낱말 바로 뒤의 숫자만 반각 공백(Instagram 2件, X 2件).
- 범위는 「〜」(1〜2分, {a}〜{b}秒). 쪽 범위 「{from}〜{to}件」.
- 가타카나 장음: ユーザー, サーバー, フィルター, レビュアー, パスワード, カテゴリ, ブラウザ(관례).
- 자리표시자 `{name}` 은 그대로 둔다.
- 조수사: 목록 항목·말·밈·문구·근거·문장은 「件」, 시장 「市場」, 나라 「か国」, 지역 「地域」, 그 밖 秒·分·週·日·回·人.
- 날짜·숫자는 `ja-JP`(10月12日, 2026年10月12日, 2026/10/12 14:30, 1,234). 시간대는 한국어판과 같은 UTC+9(Asia/Tokyo).
- 줄은 구(文節) 단위로 바꾼다(`app/globals.css` 의 `:lang(ja) { word-break: auto-phrase }`, Chromium). 일본어 화면 안의 한국어 원문은 한국어처럼 낱말 단위(`keep-all`).
- 좁은 칸(390 폭의 탭·단추·선택 상자)에 들지 않으면 뜻을 해치지 않는 선에서 줄인다. 예: 둘러보기 탭 使用中·下火·要注意, 말투 親しみ, 열 머리 4週の言及.

## 6. 서버 글의 언어

- **사전 뜻(뜻풀이·유래·뉘앙스).** 일본어판(`translations.lang='ja'`)이 있으면 보인다. 없으면 사전 항목은 원문 뜻과 「翻訳なし」 안내를, 목록 카드는 영어 화면처럼 '아직 일본어 설명이 없다'는 표시를 보인다. 원문 뜻에 가나가 있으면(일본어 표제어) 원문을 그대로 보인다.
- **요청 때 모델이 화면 언어로 쓰는 글**(제품 요약·카피 설명·카피 검사의 AI 의견·브리핑 요약·'やさしく言い換えると')은 일본어 화면에서 일본어로 쓴다(10-13, `trend_agents/ui_lang.py`). 웹 API 경로가 서버에 `ja` 를 보내고, 프롬프트 끝에 일본어로 쓴 지시를 붙인다(`ui_lang.rule`). 모델이 그래도 다른 말로 쓰면 그 칸만 모아 한 번 옮기고(`generate.relanguage`, 제품 요약·카피 설명), 옮긴 것도 일본어가 아니면 지우되 영어 설명은 남긴다. 브리핑 요약은 밈 이름 밖에 한글이 섞이면 버리고 규칙 문장을 쓴다. 10-13 시험(Flash Lite, 10건): 제품 요약 3/3·카피 설명 3시장·AI 의견 2/2·쉽게 풀어 쓰기가 일본어로 나왔다. 운영(Vertex Flash)에서 다시 확인한다.
- **파이프라인이 미리 쓴 서버 글**(`Text2`: 급증 이유·나라별 차이·현지 밈 설명·주제 요약)은 일본어판(`ja`)이 있으면 그것을, 없으면 영어판을 보인다(`i18n.text2`, 10-14). 있던 글의 일본어판은 Sonnet 으로 채웠고(`scripts/spikes_ja.py`·`topics_ja.py`), 새 글은 spikes·topics 단계가 함께 쓴다.
- **사전에 묻기(챗봇)** 는 일본어 화면에서 일본어로 답한다(10-14). 웹이 `lang=ja` 를 보내면 지시문의 답 언어 줄(`ask.LANG_LINE`)과 코드가 쓰는 고정 문장(`ask.MSG`)이 일본어가 되고, '없다'는 답을 잡는 검사(`_DENIES`)에 일본어 꼴을 더했다. 되묻기 검사(`_ASKS_BACK`)는 아직 한국어 꼴만 본다.
- 리스크 이유·검수 큐의 제안·근거 발췌처럼 데이터로 들어온 한국어 글은 그대로 보인다(관리 화면).
- 디자인 시안(`/lab/*`)은 한국어·영어로만 만들었다. 일본어 화면에서는 영어로 연다(`LabLocale`).

## 7. 검토 기록

일본어 화자의 검토는 아직 없다. 확신이 없는 문구는 [§8](#8-확신이-없는-문구)에 모은다.

**1차(10-12, 넣으면서).** `i18n.ts` 는 세 묶음으로 나눠 옮기고 합친 뒤 묶음 사이의 표기를 맞췄다 – 仕組み/しくみ, データ収集/データ収集日時, 반대말 対義語/反対語, 저속한 말투 下品な言葉づかい/下品な言い回し, 말투와 안 맞음, 이 말로 바꾸기, 입력 고치기, 만들지 못함. 일본어판에 한글이 섞이지 않았는지, 자리표시자가 영어판·한국어판과 같은지, §5의 쓰지 않는 표기가 없는지는 단위 시험(`tests/japanese.spec.ts`)이 본다.

**화면 확인(10-12, 1440·390).** 가로 넘침은 없었다. 390 폭에서 깨진 것을 고쳤다 – 말투 단추 親しみやすさ 가 두 줄(→ 親しみ), 만드는 순서 넷째·셋째 칸이 두 줄(→ 再チェックする·承認後に公開する), 둘러보기 탭이 두 줄(→ 使用中·下火·要注意), 목록 열 머리 4週間の言及 이 두 줄(→ 4週の言及). 1440 폭의 관리 '리스크' 선택 상자가 잘린 것(→ ルール（{level}）). 큰 제목이 '…作 / ります' 처럼 낱말 가운데서 끊기던 것은 구 단위 줄바꿈으로, 일본어 화면 안의 한국어 원문이 낱말 가운데서 끊기던 것은 한국어 `keep-all` 로 고쳤다. 문장 사이 띄어쓰기(。 뒤 공백)와 반각 괄호도 일본어 꼴로 바꿨다.

**2차(10-12, 무작위 120키 되짚기).** 두 사전의 1,414키에서 시드 20261012로 120키를 뽑아 일본어 → 한국어로 되짚었다. 뜻이 어긋난 것은 없었다. 같은 개념의 표기가 다른 것 둘을 고쳤다 – `ex_using` 今使われている → 使用中(둘러보기 탭과 같게), `tb_mentions` 4週間の言及 → 4週の言及(열 머리끼리 같게). 길이로 화면을 깨는 것은 표본 안에서 더 나오지 않았다(위 화면 확인에서 고친 넷은 표본 밖). 한국어 원문이 사실과 다른 곳(`pg_me_nick_help` 의 '왼쪽 메뉴' – 지금 화면은 위 막대)은 원문을 따랐다.
