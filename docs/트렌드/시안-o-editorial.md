# 디자인 시안 '에디토리얼형' (`/lab/o-editorial`)

마케터를 위한 **주간 밈 잡지**. 판(시장)을 고르면 그 시장의 이번 주 호가 열린다: 커버 밈 한 장, 지난번에 본 뒤로 달라진 것, 그리고 꼭지 넷
(지금 쓰이는 밈 · 요즘 더 찾는 밈 · 식어 가는 밈 · 브랜드는 조심). 밈 하나를 누르면 특집 기사(`/lab/o-editorial/m/[termId]`)가 된다.
지금 앱 화면은 그대로 두고, 동료 검토용으로 `/lab` 아래에만 더했다.

| 경로 | 내용 |
| --- | --- |
| `/lab/o-editorial?regions=KR` | 이번 주 호 (판: KR·JP·TW·HK·TH·VN·ID·PH·MY·SG, `all` 통합판, `GLOBAL` 전 세계판) |
| `/lab/o-editorial/m/[termId]` | 밈 특집 기사 |
| `/lab/o-editorial/list/{rising,fading,caution}` | 꼭지 전체 (30개씩 쪽) |
| `/lab/o-editorial/search?q=` | 찾기 (올리기 직전 '써도 되나' 확인) |
| `/lab/o-editorial/api/cards?ids=` | 스크랩한 밈의 지금 상태 (읽기 전용, 화면에 필요한 칸만) |

파일: `apps/trend-web/app/lab/o-editorial/**`, `components/lab/o-editorial/**`, `lib/lab/o-editorial.ts`(문구·표시 규칙·계산),
`lib/lab/o-editorial-data.ts`(한 판의 데이터를 한 번에), `lib/lab/o-editorial-server.ts`(뜻 첫 줄·출처 다듬기, 서버 전용),
`app/lab/o-editorial/editorial.css`(모든 선택자가 `.lab-o-editorial` 아래). 공용 파일은 읽기만 했다.

## 서체와 크기

- **Pretendard Variable 하나.** 앱이 이미 싣는 글꼴이고 한글 굵기가 100–900 까지 다 있다. 포스터 느낌은 새 글꼴이 아니라
  **900 굵기 + 자간 −0.045em + 줄 간격 0.94** 로 만든다. 한·일·중·태 이름은 `lang` 을 달아 제 글꼴로 그린다(자간은 −0.02em 로 느슨하게).
- **이름은 칸 폭에 맞춰 선다.** `font-size = clamp(최소, 100cqi ÷ 가장 긴 줄의 폭(em), 상한)` — 컨테이너 쿼리 단위.
  상한: 커버 232px, 기사 184px, 특집 포스터 72px, 포스터 44px(휴대폰 32px). 줄은 서버가 나눈다: 띄어쓰기 있는 이름은 낱말 사이,
  일본어·중국어·태국어는 ICU 낱말 경계(`Intl.Segmenter`) 사이에서만, 줄 첫머리 금칙 글자(ー ぅ 、…)·히라가나 한 글자 조사는 앞에 붙인다.
  줄은 '그 칸이 상한 크기로 담는 폭' 안에 드는 가장 적은 줄 수로 — 크기가 늘지 않는데 줄만 느는 일이 없게.
- 꼭지 제목 800 · 30–44px · −0.035em. 뜻 첫 줄(lede) 500 · 20–27px · 1.45. 본문 17px · 1.65, 기사 소제목 26px/800.
  메타 13px 회청, 테이프 13px/600. 숫자는 `tabular-nums`(고정폭 글꼴을 따로 쓰지 않는다). `word-break: keep-all`.

## 원칙

1. **이름이 곧 그림.** 대시보드 146개 밈 가운데 영상 근거(`short`)가 있는 것은 0개다. 사진 없는 경우가 기본이므로 대체 화면이 아니라
   타이포그래피 자체를 그림으로 만들었다. 유튜브 쇼츠 근거가 있을 때만 `i.ytimg.com` 미리보기를 주소로 싣는다(파일을 받지 않는다).
2. **판정은 백엔드, 화면은 글로 옮길 뿐.** 목록 나누기·단계·리스크는 백엔드 규칙 그대로. 이 시안이 새로 세는 것은 네이버 곡선의
   최근 4주 대 그 전 4주 변화뿐이고, 한 창에 20일이 안 되면 '자료 부족' 이라고 쓴다.
3. **한 화면에 큰 소리는 하나.** 울트라마린 면과 칸을 채우는 이름. 나머지는 흰 바탕에 먹 글자와 가는 선으로 조용히.
4. **얇은 시장은 얇다고 말한다.** 0개 판도 숨기지 않고, 커버가 없으면 왜 없는지와 갈 곳(통합판·다른 판)을 준다.
5. **움직임은 한 번.** 커버 이름이 줄마다 올라서고 검색 곡선이 그어진다. `prefers-reduced-motion` 이면 멈춘다.

| **요즘 더 찾는 밈** | `GET /terms/{id}/generations` 네이버 나이대 곡선(한국어로 검색된 말만). 셋 이상 나이대에 자료가 있고, 절반 넘는 나이대에서 15% 이상, 가운데 값도 15% 이상 는 것 | 성장을 보여 줄 수 있는 유일한 촘촘한 시계열. 검색이 늘었다고 다시 유행하는 것은 아니라고 적는다 |

고르지 않은 것: 점수·연속 방문 같은 게임 장치, 알림(데이터가 없다), 주간 추이 막대(`weekly` 가 거의 0 이라 믿을 수 없다).
만들기는 커버·기사의 **이 밈으로 만들기**(`/recommend?term=`, 확인된 밈이고 사용 자제가 아닐 때만)와 머리의
**내 제품에 맞는 밈 추천받기**(`/recommend?regions=<판>`)로 이어 준다.

## 참고에서 가져온 것 (브랜딩은 가져오지 않음)

- **캐릿(Careet)**: 트렌드를 '이번 호' 로 묶어 읽히는 잡지 틀, 꼭지 이름을 쉬운 한국어로, 사전 항목을 기사처럼.
- **TikTok Creative Center**: 지역이 머리 — 판 고르기가 곧 호의 제목. 순위 줄 옆에 추이.
- **Pinterest Trends**: 순위 목록 + 고른 것의 자세한 보기 → '요즘 더 찾는 밈' 의 순위 줄과 나이대 막대.
- **Exploding Topics · Glimpse**: 차트를 주인공으로, 성장률을 숫자로 → 커버 바닥의 네이버 곡선, ±% 막대. 단, 실제 곡선이 있을 때만.
- **Know Your Meme**: 항목 구조(유래·퍼짐·출처) → 기사 절 순서.
- **Google Trends KR · 썸트렌드**: 나이대별 곡선을 같은 날로 읽는 작은 그림 여러 개와 표로 보기.

## 일부러 피한 기본값

- 크림 바탕 + 세리프 + 테라코타, 검정 바탕 + 형광 초록 — 대신 흰 종이 + 울트라마린 한 면.
- 대문자 눈썹 라벨, 고정폭 글꼴 데이터 라벨, 가운뎃점으로 이은 메타 줄(출처 제목 앞 '네이버 뉴스 · ' 도 떼어 냈다), 링크 끝의 '→'.
- 같은 모서리·같은 그림자의 카드 격자, 그라데이션 — 포스터는 위쪽 선 하나로 구획하고 그림자·둥근 모서리가 없다(단추·테이프만 2–4px).
- 큰 숫자 + 작은 라벨 KPI 머리 — 첫 화면의 주인공은 숫자가 아니라 밈 이름.
- 번호 표시는 실제 순위인 '요즘 더 찾는 밈' 에만.
- 한 낱말만 색·기울임으로 강조한 제목, 섹션마다 올라오는 등장 효과.

## 검토 기록

앞 세션(r1–r3): 토큰·커버·꼭지·기사·지난번 이후·스크랩·찾기·목록·오류/빈 상태를 짓고 390/1024/1440 에서 세 번 찍어 고쳤다.
이번 세션(캡처는 `data/work/lab/o-editorial/shots/`의 r4–r6):

- **r4** (r3 캡처 비평): 출처가 파란 밑줄 30줄이라 본문보다 시끄럽다 → 먹색 제목·옅은 밑줄, 같은 문서·같은 기사 한 번만, 8개 + 더 보기.
  '네이버 뉴스' 로 적히던 기사는 언론사 주소로, 'Wikipedia: ' 같은 머리말 제거. 유래의 근거가 협업 기사였다 → 참고 위키 먼저.
  '나라마다' 표가 휴대폰에서 세 칸으로 눌렸다 → 나라·현지 이름을 머리로 쌓는 목록. 전 세계판 커버 뜻이
  'Point of view (disambiguation) — …' 로 깨졌다 → 망가진 줄임말 풀이는 빼고 뜻만. 지난번 이후 목록의 새 밈에 주의·사용 자제 표시,
  0개 칸은 흐리게. 검색이 몰린 말이 없는 판에 '아래에서 보세요' 라고 쓰던 빈 커버 문구를 나눔. 사실 상자가 따라다니지 않는
  좁은 화면에서는 바로 위 머리와 겹치는 두 번째 '이 밈으로 만들기' 를 숨김.
- **r5**: 1024 에서 판 줄이 두 줄로 꺾이며 구분선이 줄 머리에 걸렸다 → 1200 미만은 옆으로 미는 한 줄 + 끝 흐림.
  일본어 이름이 글자 수로 잘려 'クリー/ピーパ/スタ', 'きのこ/たけの/こ戦争' → ICU 낱말 경계·금칙·조사 붙이기, 가장 적은 줄 수 규칙.
  포스터 줄 나눔 기준을 3.2em → 5em(휴대폰 포스터가 상한 크기로 담는 폭)으로: 'Nice boat' 가 한 줄로.
  r4 의 출처 순서가 스키비디 토일렛의 위키백과를 '더 보기' 뒤로 밀었다 → 참고 문서는 늘 기사보다 앞, 이름이 제목인 문서가 맨 앞.
  휴대폰 출처는 날짜·출처를 한 줄로. 키보드 초점이 이름보다 스크랩 단추를 먼저 만났다 → DOM 순서를 바꾸고 위치는 그대로.
  나라마다 머리의 나라 이름과 현지 이름 사이가 벌어졌다 → 격자 정렬 수정.
- **r6 (거울 앞에서 하나 빼기)**: 기사 '쓰는 법' 의 파란 선 인용('쉽게 말하면') — 옆 상자와 같은 말이 한 화면에 두 번, 이름 포스터 다음의
  두 번째 큰 소리였다. 뺐다. 태블릿에서 본문 폭으로 넓어진 사실 상자를 두 칸으로. 마지막 점검: 390·1024·1440, 한국어·영어,
  13개 경로에서 옆 넘침 0, 콘솔 오류 0, 원문 글자 이름에 lang 없는 곳 0.

## 알려진 한계

- 이 워크트리에는 `/lab` 초안 목록 화면이 없다 — '초안 목록' 링크는 목록 화면이 합쳐진 뒤에 산다.
- 호는 파이프라인이 돌 때마다 바뀐다. '지난 호' 를 다시 펼칠 기록(주간 스냅숏)은 백엔드에 없다 — 지금은 '지난번 방문 이후' 로 대신.
- 현재 데이터에 영상 근거가 없어 포스터 미리보기 경로는 실데이터로 확인하지 못했다.
- 이름 맞춤은 글자 폭 어림셈(측정 아님)이고, 일본어 낱말 경계는 ICU 사전 + 몇 가지 규칙이라 가끔 어색하게 끊는다.
- 방문 기록·스크랩은 이 브라우저에만 있다(지우면 처음부터). 로그인 계정에 옮기는 것은 제품 결정이 필요하다.
- 검색이 몰린 말은 밈이 아닐 수 있다(그렇게 적었다). 유래가 '유튜브' 처럼 얇거나, 관련 없는 위키 문서가 근거에 섞인 것은 데이터 그대로 보인다
  (제목에 밈 이름이 없는 참고 문서는 뒤로 보낸다).
- 찾기는 사전 전체를 받아 이름·다른 표기·뜻으로 거른다(시안 규모에서만 괜찮다).
