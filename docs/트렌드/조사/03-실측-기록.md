## 로컬 Gemma 세대 판정 – ✅ (품질·속도 차이 큼)

`uv run scripts/test_gemma_local.py <model>` · 문장 4개 · Ollama 구조화 출력(`format=json schema`)

| 문장 | gemma3n:e4b | gemma4:12b (thinking 기본) | gemma4:12b (`think=False`) |
|---|---|---|---|
| 럭키비키 / 원영적 사고 | 20s, 유래 정확 | 10s, 유래 정확 | 정확 |
| 킹받네요 / 갓생 | 20s, 정확 | 20s, 정확 | 정확 |
| 중립 문장 (유행어 없음) | **30s conf 0.80 (과신)** | all, 정확 | 정확 |
| 알잘딱깔센 / 저메추 | 알잘딱깔센 정확, **저메추 = "저렇게 해" 오답 conf 0.95** | 저메추 = "저녁 메뉴 추천" 정확 | 정확 |
| 지연 (모델 로드 후) | 2.4 ~ 3.4 s | 28 ~ 50 s (thinking 1.2k 토큰) | **≈ 7 s**, 140 토큰, 25 tok/s |

결론:
1. **작은 모델은 유행어 '탐지'는 되지만 '뜻 설명'은 환각한다** – 그것도 높은 확신도로. 설명·유래는 Gemini + 축적 데이터 근거로만 낸다. 로컬 모델의 역할은 탐지·분류·마스킹으로 한정.
2. Gemma 4 는 thinking 기본 ON. 구조화 출력·분류 용도엔 `think=False` 필수 (7배 빠름, 결과 동일). 코드 반영 완료.
3. 세대 라벨(10s vs 20s)은 실행마다 흔들린다. 모델 의견이 아니라 **데이터랩 연령대 곡선으로 보정**해야 한다. eval 셋에 세대 라벨 골드 필요.
4. confidence 가 전부 1.00 – 캘리브레이션 안 됨. 임계값으로 쓰려면 별도 스코어링 필요.
5. 실시간 판정 앞문이라면 12B(7s)는 애매, e4b(2~3s)가 낫다. 정확도-속도 트레이드오프는 앞문 결정 뒤에.

### Spanner Graph (에뮬레이터) – ✅ `uv run scripts/test_spanner_graph.py`

환경: colima(brew) 위 Docker, `gcr.io/cloud-spanner-emulator/emulator:latest`, `google-cloud-spanner` 3.71.

| 확인 항목 | 결과 |
|---|---|
| `CREATE PROPERTY GRAPH` + 노드 4·엣지 4 테이블 DDL | 통과 (에뮬레이터가 그래프 DDL 지원) |
| `ARRAY<FLOAT32>(vector_length=>768)` 임베딩 컬럼 | 통과 |
| GQL `MATCH (t:Term)-[:HAS_MEANING]->(m)-[:SUPPORTED_BY]->(e)` + `valid_to IS NULL` 필터 | 현행 v2 만 반환, 근거 2건 조인 |
| 버전 이력: v2 삽입 시 v1 `valid_to` 닫기 (트랜잭션) | `[1, closed], [2, open]` |
| `VARIANT_OF` 한 홉으로 변형 → 대표형 | 자만추하다 → 자만추 |
| `USED_BY` 세대 확산 순서 | GQL 안의 `ORDER BY`(변수·별칭·독립문 3가지)를 **에뮬레이터가 전부 무시** → `SELECT … FROM GRAPH_TABLE(… COLUMNS(…)) ORDER BY` SQL 래핑으로 정렬 확인. 실서비스 Spanner 는 GQL ORDER BY 지원이므로 에뮬레이터 한정 제약으로 보임 |

주의: 에뮬레이터는 인메모리라 재시작하면 비워진다. 상시 수집 원본은 SQLite 에, 사전은 GCP 무료 체험 인스턴스에 두는 이유.
첫 실행 실패 원인은 DDL 파일 첫 줄 주석이 첫 CREATE 문과 한 덩어리로 잘려 버려진 파싱 버그(수정).
