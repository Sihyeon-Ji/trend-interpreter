# 화면 디자인 개편 (2026-09-29)

관련 [ADR 0001](../adr/0001-서비스-방향.md) · [프론트 방향(09-14)](프론트엔드.md) · 브랜치 `feat/ui-redesign`

## 왜 바꾸나

- 제품 방향이 09-28 ADR 0001 로 '세대 통역' 에서 **마케터·크리에이터용 트렌드 리포트와 콘텐츠 생성**으로 바뀌었다. 흐름은
  **살펴보기 → 추천받기 → 만들기**다. 화면 구조는 아직 예전 그대로다: 지도가 첫 화면, 상단 메뉴 5개, 960px 한 칼럼.
  ADR 0001 결과 항목은 "첫 화면은 마케터·크리에이터 기준으로 다시 쓰고, 기존 지구본 보드는 대시보드의 지역 선택 화면으로" 라고 적었다.
- 09-29 캡처 실측: 키워드 화면은 카드 최대 90장을 3열로 쌓아 데스크톱 7,969px·휴대폰 20,685px 이다. 훑어볼 수가 없다.
  추천 → 만들기는 한 칼럼에 이어 붙어 지금 몇 번째 단계인지 보이지 않는다.
- 사용자 요구: "섹터 구분 없이 호불호 없는 대기업식 UI/UX". 09-14 에 같은 요구로 Notion '앱' 쪽 시각 언어를 골랐다.

## 결정

- **시각 언어는 09-14 결정을 잇는다.** 흰 바탕·검정 글자·가는 선, primary 는 검정, 링크는 파랑. 파스텔 틴트 면·색 띠·카드 그림자·
  장식 글리프·큰 마케팅 제목은 여전히 쓰지 않는다. 호불호가 갈리는 것은 색·장식이지 구조가 아니다.
- **바꾸는 것은 구조다.** 왼쪽 메뉴가 있는 앱 틀, 같은 규칙의 페이지 머리, 표 중심 목록, 단계가 보이는 추천 흐름, 상태 표시 규칙.
- **첫 화면(`/`)은 트렌드 대시보드**, 지구본은 `/map`(세계 지도)이 되어 대시보드의 지역을 고르는 화면이 된다. `/trends` 는 `/` 로 넘긴다.
  (09-16 '지도가 첫 화면' 결정은 09-28 ADR 0001 이 대신한다.)

```text
│ 최근 변화   │                                         │

│ 관리 · 로그인 │                                         │

```

- 사이드바 240px, 옅은 바탕. 현재 메뉴는 흰 바탕 + 먹 글자. 휴대폰은 위 막대의 메뉴 단추가 서랍을 연다.
- 내용 폭: 데이터 화면 최대 1200px, 읽는 화면(사전 항목·메시지 해석)의 본문 최대 720px. 모두 **왼쪽 정렬**, 표의 숫자만 오른쪽.
- 페이지 머리: 제목(24/600) → 한 줄 설명(15, 짙은 회색) → 오른쪽에 갱신 시각·보조 작업. 제목 위에 라벨을 얹지 않는다.

## 원칙

1. 모든 화면은 "이 밈을, 이 나라에서, 지금 써도 되나" 에 답한다 — 단계·리스크·근거를 열지 않고 본다.
2. 목록은 표로. 같은 모양의 카드 모자이크를 쓰지 않는다. 자세한 것은 사전 항목에서 본다.
3. 화면마다 검정(primary) 버튼은 하나.
4. 표제어는 원문 그대로가 주인공이다 — 자르지 않고 `lang` 을 붙인다(한글·가나·한자·태국 글자가 섞인다).
5. 번호는 진짜 순서에만 쓴다(추천의 1 제품 → 2 밈 고르기 → 3 결과물).
6. 가운뎃점(·)으로 여러 사실을 한 줄에 잇지 않는다 — 칸과 라벨로 나눈다.
7. 비었을 때·실패했을 때는 무엇을 하면 되는지 한 문장으로 알린다.

## 화면 사이 규칙 (2차, 09-29)

1차 검토(페이지 9개)를 종합하며 정했다. 여러 화면이 같은 값을 다르게 보이던 것을 한 벌로 맞춘다.

- **지역은 여러 곳을 고른다.** 대시보드·사전·최근 변화·추천·세계 지도가 같은 규칙이다: '전체' 에서 한 곳을 누르면 그곳만,
  다른 곳을 누르면 더하고, 고른 곳을 누르면 빼고, 다 빼면 '전체'. 주소는 `?regions=KR,JP`(칩 순서로 고정, 모르는 값은 버림).
  동남아 여러 나라를 한 캠페인으로 묶는 경우가 있고 백엔드도 여러 지역을 받는다. 대시보드 검토는 '하나만' 을 제안했지만,
  그 검토가 본 결함은 겉모양(고른 칩을 검정으로 칠해 하나만 고르는 단추처럼 보임)이었다.
- **고른 표시**는 2px 파랑 테두리(그림자가 아니라 border) + 먹 500 + 체크 표시(여러 개 고르는 칩은 네모, 톤처럼 하나만 고르는 칩은 동그라미)
  + 화면 읽기용 '선택됨'. 칩·탭·단계 번호·배지는 칠하지 않는다 — 검정 채움은 화면의 주요 버튼 하나뿐.
- **목록 셋은 Plan 04 대로.** '지금 쓰이는 밈' 과 '식어 가는 밈' 은 사용 자제를 뺀 모든 밈을 나눠 갖고, 주의 밈은 표시와 함께 거기 남는다.
  '주의가 필요한 밈' 은 주의·사용 자제를 모아 보는 목록(사용 자제 먼저, 사용 자제는 여기에만)이고, 겹친다는 것을 탭 아래 한 줄로 밝힌다.
  칩 건수 = 쓰이는 + 식는 + 사용 자제. 12주 언급이 0 이고 마지막 쓰임이 90일을 넘은 말은 '식어 가는 밈'. 목록은 자르지 않고 30개씩 쪽으로 나눈다.
- **쓸 때 조심**은 칸마다 값이 하나다: 사용 자제·주의·근거 부족(Plan 03 의 판단 보류, 배지) / 특이 사항 없음 / 확인 전(글자).
  근거 부족 배지는 중립 톤 — 판단하지 못한 말이 '특이 사항 없음' 보다 약해 보이지 않게.
- **단계**는 퍼진 정도 배지 + 추세 낱말. 배지는 확산만 오름 색, 태동·주류는 중립, 식상은 흐리게.
- **실패와 예시.** api 모드에서 서버가 실패하면 예시 데이터로 바꿔 넣지 않고 그 자리에 '불러오지 못했습니다' + 다시 불러오기.
  예시 모드는 앱 틀의 안내 줄 하나와, 머리의 갱신 시각 자리에 '예시' 배지. 예시 사전도 쓸 때 조심·퍼진 정도 값을 채운다.
- **화면 사이 이동.** 지역을 고른 화면에서 사전 항목으로 가면 `?regions=`(항목의 수가 같은 지역 기준), 추천 결과에서 가면
  `?from=recommend`(항목이 '이 밈으로 만들기' 를 내지 않는다). 대시보드의 검정 버튼 '내 제품에 맞는 밈 추천받기' 는 `/recommend?regions=`(목표 지역만),
  '지도에서 지역 고르기' 는 `/map?regions=&list=`. 사전 항목의 '이 밈으로 만들기' 는 `/recommend?term=`.
- **한 밈 한 벌.** 세계 지도의 지역별 주의 수·대표 밈(`/dashboard?summary=1`)과 최근 변화 행의 단계·쓸 때 조심(`/dashboard/cards?ids=`)은
  백엔드가 전체에서 센 값이다 — 대시보드 첫 쪽(30개)에서 찾으면 그 밖의 밈이 빠졌다. 세계 지도의 '나라를 건너간 밈' 도 대시보드처럼
  표제어 자체가 욕설·성적 표현인 것은 내지 않는다.
- **이름.** 메뉴의 '오늘의 변화' 는 48시간을 보여 주므로 '최근 변화'. 칸 이름은 표현 · 단계 · 최근 4주 언급 · 마지막 쓰임 · 주로 보인 곳 · 쓸 때 조심.

## 검토

페이지마다 에이전트가 데스크톱·휴대폰 캡처와 코드를 보고 이 문서 기준으로 검토하고, 고친 뒤 다시 찍어 같은 검토를 되풀이한다.
캡처는 예시 모드(모델 없이 추천 → 만들기까지)와 원작자 서버 실데이터 둘 다.

- 1차(09-29): 페이지 9개 검토 → 종합(앱 틀·공용 부품·충돌 25건·화면 사이 규칙) → 6개 묶음(대시보드·추천·사전 항목·최근 변화와 나라·
  해석과 사전과 계정·지도와 관리)을 병렬로 고치고 한 브랜치에 합친 뒤 위 규칙으로 맞췄다.
