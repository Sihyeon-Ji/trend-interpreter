# 화면 디자인 개편 (2026-09-29)

관련 [ADR 0001](../adr/0001-서비스-방향.md) · [프론트 방향(09-14)](프론트엔드.md) · 브랜치 `feat/ui-redesign`

## 왜 바꾸나

- 제품 방향이 09-28 ADR 0001 로 '세대 통역' 에서 **마케터·크리에이터용 트렌드 리포트와 콘텐츠 생성**으로 바뀌었다. 흐름은
  **살펴보기 → 추천받기 → 만들기**다. 화면 구조는 아직 예전 그대로다: 지도가 첫 화면, 상단 메뉴 5개, 960px 한 칼럼.
  ADR 0001 결과 항목은 "첫 화면은 마케터·크리에이터 기준으로 다시 쓰고, 기존 지구본 보드는 대시보드의 지역 선택 화면으로" 라고 적었다.
- 09-29 캡처 실측: 키워드 화면은 카드 최대 90장을 3열로 쌓아 데스크톱 7,969px·휴대폰 20,685px 이다. 훑어볼 수가 없다.
  추천 → 만들기는 한 칼럼에 이어 붙어 지금 몇 번째 단계인지 보이지 않는다.
- 사용자 요구: "섹터 구분 없이 호불호 없는 대기업식 UI/UX". 09-14 에 같은 요구로 Notion '앱' 쪽 시각 언어를 골랐다.

## 결정

- **시각 언어는 09-14 결정을 잇는다.** 흰 바탕·검정 글자·가는 선, primary 는 검정, 링크는 파랑. 파스텔 틴트 면·색 띠·카드 그림자·
  장식 글리프·큰 마케팅 제목은 여전히 쓰지 않는다. 호불호가 갈리는 것은 색·장식이지 구조가 아니다.
- **바꾸는 것은 구조다.** 왼쪽 메뉴가 있는 앱 틀, 같은 규칙의 페이지 머리, 표 중심 목록, 단계가 보이는 추천 흐름, 상태 표시 규칙.
- **첫 화면(`/`)은 트렌드 대시보드**, 지구본은 `/map`(세계 지도)이 되어 대시보드의 지역을 고르는 화면이 된다. `/trends` 는 `/` 로 넘긴다.
  (09-16 '지도가 첫 화면' 결정은 09-28 ADR 0001 이 대신한다.)

## 앱 틀

```text
데스크톱(1024px 이상)                                        휴대폰
┌──────────┬─────────────────────────────────────────┐       ┌───────────────────────────┐
│ 트렌드 통역 │ 페이지 제목                    [주요 작업]  │       │ ☰  트렌드 통역       한 · EN │
│           │ 한 줄 설명                    갱신 시각   │       ├───────────────────────────┤
│ 대시보드    │ ──────────────────────────────────────── │       │ 페이지 제목                 │
│ 밈 추천     │ 도구 줄 (지역 · 탭 · 검색)                 │       │ 한 줄 설명                  │
│ ───────── │ 내용 (표 · 목록 · 패널)                    │       │ 도구 줄 (가로로 밀어 봄)      │
│ 사전       │                                         │       │ 목록 (한 줄씩)               │
│ 메시지 해석  │                                         │       └───────────────────────────┘
│ 세계 지도   │                                         │
│ 오늘의 변화  │                                         │
│           │                                         │
│ 관리 · 로그인 │                                         │
└──────────┴─────────────────────────────────────────┘
```

- 사이드바 240px, 옅은 바탕. 현재 메뉴는 흰 바탕 + 먹 글자. 휴대폰은 위 막대의 메뉴 단추가 서랍을 연다.
- 내용 폭: 데이터 화면 최대 1200px, 읽는 화면(사전 항목·메시지 해석)의 본문 최대 720px. 모두 **왼쪽 정렬**, 표의 숫자만 오른쪽.
- 페이지 머리: 제목(24/600) → 한 줄 설명(15, 짙은 회색) → 오른쪽에 갱신 시각·보조 작업. 제목 위에 라벨을 얹지 않는다.

## 원칙

1. 모든 화면은 "이 밈을, 이 나라에서, 지금 써도 되나" 에 답한다 — 단계·리스크·근거를 열지 않고 본다.
2. 목록은 표로. 같은 모양의 카드 모자이크를 쓰지 않는다. 자세한 것은 사전 항목에서 본다.
3. 화면마다 검정(primary) 버튼은 하나.
4. 표제어는 원문 그대로가 주인공이다 — 자르지 않고 `lang` 을 붙인다(한글·가나·한자·태국 글자가 섞인다).
5. 번호는 진짜 순서에만 쓴다(추천의 1 제품 → 2 밈 고르기 → 3 결과물).
6. 가운뎃점(·)으로 여러 사실을 한 줄에 잇지 않는다 — 칸과 라벨로 나눈다.
7. 비었을 때·실패했을 때는 무엇을 하면 되는지 한 문장으로 알린다.

## 페이지

| 경로 | 구성 |
| --- | --- |
| `/` 대시보드 | 머리(제목·설명·갱신 시각·'지도에서 고르기') → 지역 칩(건수) → 탭 셋(지금 쓰이는·식어 가는·주의, 건수가 탭 이름에) → 표(키워드·단계·언급 추이·마지막 쓰임·주로 쓰는 곳·리스크). 행을 누르면 사전 항목. 휴대폰은 한 줄 목록 |
| `/recommend` 밈 추천 | 단계 표시 + 두 칸(왼쪽 입력, 오른쪽 결과). 결과물은 탭(인스타그램·X·숏폼 대본·썸네일) |
| `/dictionary` · `/dictionary/[id]` | 검색·필터 줄 + 표 / 표제어 머리 + 본문 + 오른쪽 요약·목차 |
| `/explain` · `/map` · `/updates` · `/country/[code]` | 같은 머리·도구 줄 규칙 |
| `/login` · `/me` · `/admin/*` | 로그인만 가운데 작은 패널. 관리는 하위 탭(검수·리스크·수집 현황) |

## 검토

페이지마다 에이전트가 데스크톱·휴대폰 캡처와 코드를 보고 이 문서 기준으로 검토하고, 고친 뒤 다시 찍어 같은 검토를 되풀이한다.
캡처는 예시 모드(모델 없이 추천 → 만들기까지)와 원작자 서버 실데이터 둘 다.
