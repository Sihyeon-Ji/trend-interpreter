후보 ID·이름

## 한 문장 정의

**누가** `[대상 사용자]`가 **어떤 자료·상황** `[입력]`을 제공하면,
**어떤 반복 작업** `[현재 문제]`을 줄이고 **어떤 검증 가능한 결과** `[출력·효과]`를 받습니다.

## Hard gate

하나라도 `아니오`이면 점수 계산 전에 차단 사유와 해결 기한을 정합니다.

| 질문 | 예/아니오/미확인 | 증거 |
| --- | --- | --- |
| 행사 기간에 시작한 fresh project인가 | | |
| 공식 여섯 테마 중 하나에 명확히 들어가는가 | | |
| 2주 안에 end-to-end prototype을 만들 수 있는가 | | |
| 합법적으로 사용할 수 있는 대표 데이터가 있는가 | | |
| Gemini 또는 Gemma가 핵심 문제 해결에 필요한가 | | |
| Cloud Run 또는 Firebase에 배포할 수 있는가 | | |
| 실제 화면으로 3분 미만 demo가 가능한가 | | |
| 위험한 자동 실행에 사람 승인·제한을 둘 수 있는가 | | |

## 공식 심사 점수

각 행은 0~5점으로 평가하고 `가중 점수 = 점수 ÷ 5 × 배점`으로 계산합니다.
점수 옆에 사용자 인터뷰·데이터·prototype·경쟁 제품 링크 같은 증거를 적습니다.

| 공식 기준 | 배점 | 0~5 | 가중 점수 | 판단 근거 |
| --- | ---: | ---: | ---: | --- |
| Gen AI가 문제 해결에 직접 기여 | 15 | | | |
| 기능적·기술적으로 타당한 구현 | 15 | | | |
| 확장성과 후속 발전 가능성 | 10 | | | |
| 문제·테마 정렬 | 10 | | | |
| 사용자·산업·사회 영향 | 15 | | | |
| 기존 해결책 대비 독창성 | 12 | | | |
| 피상적이지 않은 Gen AI 활용 | 13 | | | |
| 사용성·접근성 | 5 | | | |
| 구성 요소와 AI 경험의 응집력 | 5 | | | |
| **합계** | **100** | | | |

## 별도 delivery risk

이 표는 공식 100점에 섞지 않습니다. 위험이 높으면 점수가 높아도 범위를 줄이거나 보류합니다.

| 위험 | 낮음/중간/높음 | 완화 방법·증거 |
| --- | --- | --- |
| 데이터 접근·권리·개인정보 | | |
| 외부 API·MCP·기관 연동 | | |
| 실제 모델 품질·오탐·환각 | | |
| 비용·할당량·응답 시간 | | |
| 3분 demo 안정성 | | |
| 팀 역량·남은 일정 | | |

## 최소 evidence pack

- 공개·비식별 대표 입력 3~5개
- 입력별 기대 결과와 만들면 안 되는 주장
- 현재 수작업 시간·실패율 또는 비교 가능한 기준선
- 경쟁 제품 3개와 우리가 다르게 해결하는 한 문장
- 3분 demo 장면 5개 이내
- 가장 큰 실패 상황과 사용자에게 보일 복구 방법
