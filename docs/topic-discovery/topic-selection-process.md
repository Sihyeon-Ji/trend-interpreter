# 주제 선정 절차

[공식 요건 기준선](../submission-requirements/official-requirements-baseline.md)과
[심사 점수표](candidate-scorecard-template.md)를 사용해 팀의 한 가지 주제를 결정합니다.

## 원칙

- 좋은 기술보다 먼저 반복되는 실제 문제와 대상 사용자를 확인합니다.
- 데이터가 없는 후보는 모델 선택 전에 보류합니다.
- 공식 100점과 delivery risk를 분리합니다.
- 모델이 빠져도 같은 가치가 나는 기능은 Gen AI 활용 근거가 약합니다.
- 이미 Google이나 상용 제품이 해결한 영역은 더 좁은 미해결 작업이 있어야 합니다.
- 최종 선택은 팀 결정이며 개인 점수 평균만으로 자동 확정하지 않습니다.

## 진행 순서

1. [후보 등록부](candidate-register.md)에서 후보별 소유자와 한 문장 정의를 확인합니다.
2. 소유자가 후보 점수표와 최소 evidence pack을 작성합니다.
3. Hard gate의 `미확인`을 데이터·사용자·기술 spike로 검증합니다.
4. 각 팀원이 독립적으로 공식 심사 점수를 매기고 근거 없는 점수는 제외합니다.
5. 후보별 점수 중앙값, 점수 범위, delivery risk를 함께 봅니다.
6. 상위 3개만 3분 demo storyboard와 2일 이내 기술 spike를 만듭니다.
7. 실제 결과를 다시 채점해 하나를 선택하고 나머지는 보류합니다.
8. 결정일·참석자·선택 이유·버린 가정·재검토 조건을 아래 형식으로 기록합니다.

## 완료 기준

- hard gate가 모두 `예`이거나 승인된 완화 계획이 있습니다.
- 최소 3개의 실제·공개·비식별 입력과 기대 결과가 있습니다.
- 경쟁 제품 대비 차이를 한 문장으로 설명할 수 있습니다.
- 3분 미만 demo에서 입력·AI 처리·검증·사용자 결과가 보입니다.
- Cloud Run 또는 Firebase 배포 경로와 비용 상한을 설명할 수 있습니다.
- 팀 전원이 선택·보류 이유와 다음 역할을 확인했습니다.

점수가 높은데 데이터·권리·demo 가능성이 확인되지 않은 후보는 선택하지 않습니다.
