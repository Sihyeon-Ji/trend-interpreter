Clearance 유사 프로젝트 조사

"Agent Warden" 원안을 상용 제품, Google 자체 기능, 오픈소스, 해커톤 출품작 네 축으로 대조했습니다. 결론은 원안 그대로는 위험하고, 방향을 조금 틀면 오히려 빈자리가 선명하다는 것입니다. 기준일 2026년 9월 10일.

결론Google 자체 기능상용·오픈소스·해커톤빈자리 5개피벗안아키텍처데모 시나리오이름리스크출처
01 · 결론

원안의 80%는 Google이 이미 출시했습니다. 나머지 20%가 우리 자리입니다

원안 그대로 가면

"우리 Agent Gateway가 이미 하는 건데요"

원안의 핵심이었던 권한 초과 도구 호출 차단, 프롬프트 인젝션 탐지, 민감 데이터 유출 방지, 비용 폭주 탐지는 Agent Gateway, Model Armor, Semantic Governance, Agent Anomaly Detection이 전부 커버합니다. 심사단에 Google Cloud 리더가 앉아 있으니 혁신 25점에서 무너집니다.

  • Zenity, Palo Alto, CrowdStrike, Microsoft Agent 365가 같은 그림으로 수천억 원을 투자 중
  • Microsoft 오픈소스 툴킷이 OWASP 10개 항목 전부를 커버한다고 공표
  • "Warden" 이름은 이미 4개 AI 보안 제품이 사용 중
  • All Things Agentic 해커톤(10월 8일 마감)에 Fortified Enterprise Fleet 트랙이 있어 비슷한 출품작이 쏟아질 시점
방향을 틀면

Gateway를 대체하지 않고, Gateway 위에 "자율성 사다리"를 올린다

Google의 판정은 ALLOW / DENY 두 가지뿐이고, 이상 탐지는 비동기 알림에 그칩니다. 업계 전체가 인정한 미해결 문제는 "정상 행동의 기준선", "에이전트 간 위임 검증", "유령 에이전트", "규제 증거"입니다. 이 넷을 하나의 Service Extension으로 묶으면 Google 스택을 가장 깊게 쓰는 팀이 됩니다.

  • 싱가포르 MAS가 2026년 7월 발표한 SAFR 프레임워크와 구조가 정확히 맞음. 파이널 장소가 싱가포르
  • 한국 AI 기본법(2026년 1월 시행)의 고영향 AI 기록 의무와 연결
  • Best Use of Google Cloud AI Tools 특별상 구조는 그대로 유지
  • 이름은 Clearance(가칭)으로 교체 제안

04 · 빈자리 5개

업계와 규제기관이 직접 지목한 미해결 문제

우리가 만든 주장이 아니라 VentureBeat의 RSAC 2026 분석, Gartner, OWASP, MAS가 문서로 남긴 것들입니다. 덱에서 그대로 인용할 수 있습니다.

GAP 1

자율성이 이진값이다

Google Semantic Governance는 ALLOW/DENY, Anomaly Detection은 알림. 어떤 벤더도 "이 에이전트가 이 종류의 행동을 얼마나 스스로 해도 되는가"를 실적으로 조절하지 않습니다. OWASP는 이를 Least Agency, 즉 "자율성은 기본값이 아니라 획득하는 것"으로 명명했습니다.

ASI02ASI10
OWASP Agentic Top 10 2026 · MI9 논문의 graduated containment
GAP 2

정상 행동의 기준선이 없다

RSAC 2026에서 CrowdStrike, Cisco, Palo Alto 세 회사가 모두 에이전트 탐지·대응을 출시했지만 "어떤 API 호출과 데이터 접근이 정상인가"의 기준선은 아무도 제공하지 않았다는 분석. Exabeam이 7월에 SIEM 쪽에서 일부 대응했지만 사후 분석입니다.

GAP 3

에이전트 간 위임과 자기 정책 수정을 검증하지 못한다

RSAC 2026에서 5개 신원 프레임워크가 나왔지만 세 가지가 미해결: 에이전트가 자기 행동을 통제하는 정책을 스스로 수정하는 것, 100개 에이전트 체인에서 사람 승인 없이 위임되는 것, 기존 OAuth/SAML에 에이전트 간 신뢰 원시가 없는 것.

GAP 4

유령 에이전트가 자격증명을 쥐고 있다

버려진 파일럿 프로젝트의 에이전트들이 유효한 자격증명을 유지하고, 오프보딩 검증 메커니즘이 없다는 지적. Agent Registry는 스킬 폐기 상태는 있지만 휴면 에이전트 탐지는 없습니다.

GAP 5

규제기관이 원하는 형태의 증거가 없다

MAS SAFR(2026.7.3)는 에이전트 거버넌스를 네 요소로 정의합니다: 무엇을 승인받았는지 확인하는 신원 계층, 규칙 저장소, 모든 제안 행동을 실행 전에 규칙과 대조하는 엔진, 모든 결정을 기록하는 감사 로그. 한국 AI 기본법(2026.1.22 시행)은 금융 신용평가 등 11개 고영향 영역에 기록·설명 의무를 부과합니다. 이 형식으로 증거를 내주는 도구는 없습니다.

Clearance: 에이전트가 자율성을 "획득"하게 하는 Agent Gateway 확장

Gateway 옆에 붙고, Observability 아래에서 배우고, 사람 앞에 선다

Google 제공, 그대로 사용 Clearance가 만드는 것 사람이 결정하는 곳
기술 40점에서 이기는 포인트. 동기 경로(Service Extension → Ladder Engine)와 비동기 경로(Observability → BigQuery → Drift Analyst)가 분리되어 있어 Gateway 지연을 건드리지 않습니다. 판정 로직은 결정론적 코드이고, Gemini는 계약 초안·드리프트 설명·증거 서술처럼 "언어가 필요한 곳"에만 씁니다. 심사위원이 "LLM이 보안 판정을 내리면 그 LLM은 누가 지키나"라고 물을 때 이 분리가 답이 됩니다.
07 · 데모 시나리오

3분 영상과 싱가포르 라이브 데모 공용 대본

은행 운영 플릿 5개 에이전트. 심사위원이 직접 "공격자"가 되어 지원 티켓에 인젝션 문장을 넣게 하면 라이브에서 기억에 남습니다.

0:00

평상시

Refund Agent가 L3에서 $500 이하 환불을 자동 처리. 콘솔에 사다리 현황과 오늘 처리 건수. "Google Gateway가 이미 허용한 호출입니다. 우리는 그 위에서 얼마나 스스로 해도 되는지를 결정합니다."

0:35

공격

고객 지원 티켓 본문에 심어진 지시문이 Refund Agent의 목표를 탈취(ASI01). Refund Agent가 Payments Agent에게 "한도 없이 임의 계좌로 송금" 작업을 A2A로 위임 시도. Lineage Verifier가 자식 범위가 부모 권한을 벗어남을 감지(ASI07). Ladder Engine이 HOLD 판정과 동시에 Refund Agent를 L3에서 L1로 강등.

1:20

사람의 결정

Officer Console 승인 큐에 항목이 뜸. Gemini가 트레이스에서 직접 쓴 설명: "이 에이전트는 30일간 위임을 한 적이 없고, 요청 금액은 기준선의 40배입니다." 에이전트 자신의 출력이 아니라는 점을 강조(ASI09). 심사위원이 DENY 클릭. 해시 체인에 기록.

1:55

유령 정리

Fleet Reaper가 47일간 트래픽 없는 intern-pilot 에이전트를 발견. 유효한 Agent Identity가 남아 있음을 표시. 폐기 제안을 심사위원이 승인하면 Identity 비활성화.

2:20

규제 증거

"Export SAFR evidence pack" 클릭. MAS SAFR 4요소(신원, 규칙 저장소, 실행 전 평가, 감사 로그)에 매핑된 PDF가 생성. 마지막 장면에 "Singapore, July 2026" 문구. 파이널이 열리는 도시의 규제기관 문서입니다.

2:45

아키텍처와 마무리

다이어그램 한 장. "Gateway를 대체하지 않습니다. Gateway가 파트너에게 열어둔 자리에 자율성 사다리를 올렸습니다." 리포지토리와 eval 결과 표 노출.

08 · 이름

"Warden"은 이미 넷이 쓰고 있습니다

wardengateway.com(에이전트용 보안 게이트웨이), aiwarden.com(LLM·MCP 게이트웨이), Warden AI(런던, AI 어슈어런스), trywarden.com. 게이트웨이 계열이라 심사위원이 검색하면 바로 혼동됩니다. 대안 세 개입니다. 상표 검색은 등록 전에 팀에서 한 번 더 확인하세요.

추천

Clearance

보안 인가 등급. "에이전트도 clearance를 획득해야 한다"는 한 문장으로 콘셉트가 설명됨. 사다리 레벨을 "clearance level"로 부르면 UI 용어까지 일관됨. 보안 심사위원에게 즉시 통하는 어휘.

Leeway

"허용 여지". 실적에 따라 여지가 늘고 줄어드는 느낌이 자율성 사다리와 맞음. 부드럽고 발음 쉬움. 보안 뉘앙스는 약함.

Latitude

"행동의 자유 폭". 에이전트에게 주는 latitude를 조절한다는 표현이 자연스러움. 단 Latitude.sh(호스팅), Latitude AI(포드 자율주행)와 겹침.

09 · 리스크와 대응

덱과 리포에서 선제적으로 답해야 할 질문

  • "Microsoft 툴킷도 approve 판정과 신뢰 점수가 있지 않나?" 리포 README에 비교표를 넣습니다. 차이는 실적 기반 자동 승강, A2A 위임 체인 검증, 유령 에이전트, 규제 증거, 그리고 Google Gateway 네이티브 확장이라는 점입니다.
  • "단계적 자율성은 MI9 논문에 있는 개념인데?" 숨기지 말고 인용합니다. "개념은 학계에 있었고, Google Agent Platform 위에서 동작하는 첫 구현이 우리"라고 말하는 쪽이 신뢰를 얻습니다.
  • "Agent Anomaly Detection이 있는데 Drift Analyst가 왜 필요한가?" Anomaly Detection은 US 리전 프리뷰, 비동기 알림, Agent Runtime 전용입니다. Drift Analyst는 그 파인딩을 신호로 받아 사다리 레벨로 변환합니다. 대체가 아니라 소비자입니다.
  • Service Extension 콜아웃의 지연 예산. Ladder Engine은 Firestore 캐시와 결정론적 규칙만 써서 수십 ms 안에 답하고, Gemini 호출은 동기 경로에 절대 넣지 않습니다. 이 수치를 eval 표에 넣습니다.
  • Agent Gateway Service Extension 접근 가능 여부. 프리뷰 기능이라 프로젝트 권한 신청이 필요할 수 있습니다. 9월 둘째 주 안에 확인하고, 막히면 동일 인터페이스의 Cloud Run 프록시로 폴백하되 덱에는 Gateway 연동 설계를 그대로 싣습니다.
  • All Things Agentic 출품작과의 유사성. 10월 8일 이후 갤러리를 반드시 훑어 겹치는 팀이 있으면 비교 슬라이드를 추가합니다.
  • 화면이 심심해 보일 위험. 데모 1:20 장면의 강등 애니메이션과 위임 그래프에 UX 시간을 몰아줍니다. 나머지 화면은 표로 충분합니다.
