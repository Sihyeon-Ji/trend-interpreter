## 조사 범위와 한계

- "AI Builder Cup", "Builder Cup 2026", "aibuildercup", 주제어 `ai-builder-cup` 등으로 찾은 저장소 중 9월 이후 만들어진 것을 모았다. 다른 대회(Agentic Cinema, Build with AI: Code for Communities, Hummingbot 등)와 빈 저장소를 빼니 **대회 프로젝트로 볼 만한 공개 저장소는 18개**였다.

- 수치(커밋·파일·테스트 파일 수)는 작업량의 대리 지표일 뿐 품질이 아니다. AI 활용 깊이는 README로 판단했고 코드를 실행해 보지는 않았다. 배포 링크는 README에 적힌 것이고 접속해 확인하지 않았다.

## 선두 팀에서 보인 것

1. **제출물이 이미 갖춰져 있다.** Gapline은 10-03에 배포 데모, 제출 영상, 영어 데모 영상, 발표 PDF, 평가 문서(`docs/EVALUATION.md`), 직접 배포 안내를 README 맨 위에 링크했다. ReadiCheck는 심사용 운영 주소와 작업용 주소를 나눠 적었다.
2. **"규칙이 정하고 모델은 설명한다"는 이제 흔한 설계다.** Baton("Rules decide, Gemini reads and explains, people accept"), Nightingale("AI interprets. Verified data decides."), ReadiCheck("The model plays and explains. It never decides alone."), ContextRail(판정은 결정적 관문, Gemini는 UNVERIFIED 조언), Foreman이 같은 말을 한다. 우리 README의 "Rules decide, models write"만으로는 차별점이 안 된다.
3. **문제를 실제 근거로 연다.** Gapline은 9월 3일 대법원 판결(사건 번호)과 제작 비용·기간 출처로 시작한다.
4. **멀티모달과 실시간이 많다.** 영상 이해 + 음성 합성(Gapline), Gemini Live 음성 통화(ReadiCheck), 사진 관찰(Nightingale).
5. **비용 상한을 화면·문서에 밝힌다.** Gapline은 방문자 하루 US$5 상한을 README에 적었다.
6. **ADK·A2A를 쓰는 팀이 있다.** ReadiCheck(ADK 에이전트 트리·평가셋), Foreman(ADK + A2A).

## 우리의 위치

**강점**

- **엔지니어링 깊이는 공개 저장소 중 가장 크다.** 커밋·테스트 파일 수, CI 병렬화, 배포 안전 테스트(후보 리비전 → 검사 → 트래픽), Terraform, Cloud SQL 백업·복원 검증, 운영 DB 갱신 도구까지 있는 팀은 보지 못했다.
- **데이터 규모와 사람 승인 지점.** 표제어 11,292개, 뜻 1만여 개, 검수 대기열과 검수 기록(107건), 버전 이력. 다른 팀은 합성 데이터·고정 시나리오가 대부분이다.
- **Gemma 파인튜닝은 우리만 했다.** 공개 저장소에서 Gemma를 README에 언급한 팀은 2곳(Chop, Baton)이고 파인튜닝은 없었다. 다만 우리 결과(QLoRA, 판별력 미확인)를 정직하게 보여야 강점이 된다.
- **JAPAC 다국가.** 6개국 + 미국 시장, 나라별 해석. 대부분 한 나라·한 시나리오다.

**약점**

- **제출물이 비어 있다.** 영상·덱 미착수, 테마 미정, 저장소 비공개. 선두 팀은 이미 링크를 걸었다.
- **배포된 화면에서 AI가 덜 보인다.** 수집 쪽 AI는 화면에 안 보이고, 영어판 뜻이 121개뿐이라 영어 화면이 비어 보인다. 선두 팀은 한 번 누르면 AI가 일하는 흐름을 보여 준다.
- **평가 문서가 영어로 정리돼 있지 않다.** 평가 결과는 `docs/` 여러 곳에 한국어로 흩어져 있다. Gapline은 `docs/EVALUATION.md` 하나로 보인다.
- **문제 근거가 README에 약하다.** 브랜드가 밈을 잘못 써서 생긴 실제 사례·비용 같은 근거가 없다.

## 테마 선택

공식 여섯 테마 중 우리 서비스는 **Media, Content & Digital Experiences**(콘텐츠 이해·현지화 품질)에 가장 가깝다. 대회 브리프도 이 테마에서 "생성 이후의 검증·현지화 품질"을 승부처로 든다. 다만 공개 저장소 중 가장 완성도가 높은 Gapline이 같은 테마다. 마케팅 쓰임을 앞세우면 **Retail & Commerce**(고객 경험)도 가능하지만, 브리프가 피하라고 한 대화형 쇼핑봇과 거리를 둬야 한다. 테마는 팀이 정할 일이고 제출 체크리스트 항목이다.

## 제출 전 제안 (우선순위)

1. **테마 확정**과 README 첫 줄에 테마 명시.
2. **README 맨 위에 링크 묶음**: Live demo · Demo video · Pitch deck · Evaluation · Architecture. 저장소 공개 전환(Plan 11)과 함께.
3. **영어 `docs/EVALUATION.md` 한 장**: 목록 거르기 규칙, 게이트, 리스크 규칙, 감사관 진단(형식 100%, 판별력 미확인), 사람 검수 수. 정직한 수치가 오히려 신뢰를 준다.
4. **데모 영상**: [시나리오 초안](../제출/데모-영상-시나리오.md). 영어판 데모 밈 준비가 먼저다.
5. **문제 근거 한 단락**: 브랜드의 밈 오용 사례와 비용(출처 포함)으로 README를 연다.
6. **차별점 문장 바꾸기**: "Rules decide, models write" 대신 우리만 가진 것 – 1만 개 규모의 근거 있는 다국가 밈 사전, 사람 검수 기록, Gemma 파인튜닝 실험 – 을 앞세운다.
7. **비용 상한 공개**: 운영 Gemini 월 상한($20)을 README에 적는다.
