# Plan 02. 생애주기 데이터 보강과 출처 순서 판정

작성일 **2026-09-28** · 상태 **구현(검토 대기)** · 근거 [ADR 0002 §1](../adr/0002-고도화-방안.md) · 선행 [Plan 01](01-import-latest-trend-data.md)(파일이 늦으면 현재 데이터로 시작) · 목표일 **2026-10-02**

## 목표

대시보드와 추천이 "지금 써도 되는 밈인가"를 말하려면 생애주기가 채워져 있어야 합니다. 현재 용어 613개 중 406개가 `unknown`이고,
뜨는 중·정점은 7개뿐입니다. 이 계획은 `unknown`을 줄이고, 이미 수집하는 출처의 **첫 등장 순서**로 마케터가 이해하는 단계를 붙입니다.

## 현재 구조

- `pipeline/track.py`가 뉴스 제목·쇼츠 해석·트렌드 검색어에서 용어 언급을 주 단위로 세어 `mentions_weekly`에 저장합니다(최근 12주).
- `lifecycle.py`의 `stage()`가 주간 언급 수로 `emerging·rising·peak·steady·declining·dormant·unknown`을 정합니다.
- 근거(`evidences`)에는 출처 종류(`community`, `short`, `news`, `web`, `wiki`, `datalab`)와 관측 시각이 있습니다.

## 할 일

1. **`unknown` 원인 조사.** 언급이 0인 용어가 추적 대상에서 빠진 것인지, 매칭 규칙(`match.mentions`)이 놓친 것인지 표본 30개로 확인하고 결과를 이 문서에 적습니다.
2. **추적 보강.** 커뮤니티 근거(`evidences.kind='community'`)도 주간 언급에 합산하고, 추적 대상을 검증 용어 전체로 넓힙니다.
3. **확산 단계 판정 추가.** `lifecycle.py`에 출처 첫 등장 시각을 받는 규칙 함수를 추가합니다. 저장은 새 컬럼으로 하고, 스키마 변경은 `storage/migrations/002_*.sql`로 합니다.

   | 확산 단계 | 규칙 |
   | --- | --- |
   | 태동 (`underground`) | 커뮤니티 근거만 있음 |
   | 확산 (`spreading`) | 쇼츠·유튜브 근거가 생기고 기존 단계가 `emerging` 또는 `rising` |
   | 주류 (`mainstream`) | 뉴스 근거가 3건 이상이고 기존 단계가 `peak` 또는 `steady` |
   | 식상 (`fading`) | 뉴스 근거가 있고 기존 단계가 `declining` 또는 `dormant` |

4. **이유 서술.** 단계는 코드가 정하고, 화면용 한 줄 이유("뉴스에 오르기 시작해 캠페인에 쓰기엔 늦을 수 있음")는 템플릿으로 만듭니다. LLM이 단계를 정하지 않습니다.
5. **API·화면 노출.** 용어 응답(`views.TermRecord`)에 확산 단계와 이유를 추가하고 계약 파일을 다시 생성합니다.

## 완료 기준

- 검증 용어 중 `unknown` 비율이 30% 이하이며, 전후 비율을 이 문서에 기록합니다.
- 확산 단계 규칙마다 인메모리(임시 스키마) 테스트가 있습니다.
- 사전 항목 화면에 확산 단계와 이유가 보입니다.

## 하지 않는 것

X·인스타그램·틱톡 근거로 단계를 나누지 않습니다. 수집하지 않는 플랫폼입니다.

## 결과 (2026-09-28, 원작자 서버의 최신 데이터 기준)

**1. `unknown` 원인.** 표본 30개 전부 같은 원인이었다. 추적 대상에는 들어 있었지만(12주 칸 있음) **언급 수가 0**이었다.
`track`이 원본 뉴스 제목·쇼츠 해석·검색어만 세고, 조사 단계가 모은 근거(커뮤니티 글·뉴스 기사, 날짜 있음)는 세지 않았다.
`가즈아`는 뉴스 근거 25건, `delulu`는 커뮤니티 25건·뉴스 25건이 있는데도 언급 0이었다. 매칭 규칙(`mentions`) 문제는 아니었다.

**2. 근거를 그대로 더하면 틀린다.** 근거는 우리가 조사할 때만 모인다. 주간 추이에 그대로 넣으면 모든 표제어의 마지막 두 주가 0이 되어
'지는 중'이 되고(마지막 조사 이후는 '안 봤음'인데 '0건'으로 읽힘), 조사한 주에만 근거가 몰려 2017년 유행어 `가즈아`가 '오르는 중'이 됐다.
그래서 역할을 나눴다.

- 모양(뜨는 중·오르는 중·정점)은 꾸준히 모으는 원본(뉴스·쇼츠·검색어)으로만 판정한다.
- 원본에 언급이 없으면 조사 근거로는 **가장 최근 쓰임 시각**만 본다: 14일 안 `steady`, 60일 안 `declining`, 그보다 오래면 `dormant`(`lifecycle.recency_stage`).
- 쓰임 근거는 커뮤니티·뉴스·쇼츠만. 위키·웹(설명 문서), 데이터랩(지수), 네이버 결과(약관상 표시 전용)는 세지 않는다.

| 검증 용어 135개 | 전 | 후 |
| --- | --- | --- |
| unknown | 62 (45%) | 3 (2%) |
| declining / dormant / steady | 34 / 39 / 0 | 62 / 36 / 34 |

**3. 확산 단계** (`lifecycle.diffusion`, `terms.diffusion` 열, 마이그레이션 002): 태동 53 · 주류 14 · 식상 58 · 판단 보류 10 · **확산 0**.
확산은 "쇼츠 근거 + 언급이 오르는 중"인데, 가짜 '오르는 중'을 걷어낸 뒤로 오르는 중인 용어가 없다. 억지로 채우지 않았다.
뜨는 신호가 더 필요하다: 나무위키 실시간 검색어·쇼츠 해석 대상 확대·검색어 급등(spikes)을 원본 추이에 넣는 것이 다음 후보다.

**3-1. 태동 규칙 보정 (Plan 04 작업 중 발견).** 태동 53개 중 50개가 위키백과·나무위키 문서가 있는 말이었다(43개는 위키 분류에서 받은 알려진 밈).
'The cake is a lie'(2007)·'Surprised Pikachu'(2018)가 '태동'으로 대시보드 맨 앞에 섰다. 백과사전 문서가 있으면 이미 자리 잡은 말이므로 태동에서 뺐다
(`track.usage_kinds` 의 `documented`). 결과: 태동 3 · 판단 보류 60 · 주류 14 · 식상 58.

**4·5. 이유와 화면.** 단계는 코드가 정하고, 이유 한 줄은 `lib/i18n.ts`의 `diffusion_*_why` 문구(한국어·영어)다. 사전 항목 정보 상자에 '퍼진 정도'로 보인다.
