## 1. 왜 하나

Gemma는 사전을 만드는 배치 단계(분류·리스크·쓰임 낱말·번역·문서 대조)에서 쓰이지만, 모두 수집 서버(PC)나 Kaggle에서 돈다. 배포본만 보는 심사위원은 Gemma가 실제로 도는 순간을 볼 수 없다. 이 계획은 그 순간을 배포본 안에서 보이게 한다.

## 3. 할 일

설계는 [Plan 14의 1·2단계](archive/14-gemma-visible-in-deployment.md#1-라이브-분류-버튼)를 그대로 따른다. 요약하면 다음과 같다.

1. **GPU 준비.** 운영 GPU VM을 Terraform으로 띄울 수 있게 하고(평소에는 꺼 둠), cold start 504를 고친다(gateway deadline 늘리기 또는 적재 끝난 뒤 ready). 데모 전에 켜서 예열하고 끝나면 끈다.
2. **1단계 – `POST /terms/{term_id}/live-risk`.** 최신 기사 문장을 모아 `pipeline/risk.py`와 같은 프롬프트·규칙으로 분류하고, 배치 결과와 나란히 보인다. 공개 사전에는 쓰지 않는다. GPU가 준비되지 않았으면 '준비 안 됨'으로 알리고 기다리게 하지 않는다. 실행 기록에는 시각·용어 ID·문장 수·시간·결과 수준만 남긴다.
3. **2단계 – `/admin/status` 수동 실행.** 검수자만, 용어 1~5개에 `risk`(먼저)·`fit`·`translate`·`crosscheck` 중 하나. 첫 판은 결과를 화면에만 보이는 미리보기로 하고, 검수 큐 연결은 여유가 있을 때 한다.
4. **데모·README.** 결과에 맞춰 영상 장면과 README의 Gemma 설명을 고친다([제출 데모·영상·발표 자료(담당 미정)](unassigned-submission-demo-and-deck.md)와 맞춘다).

## 4. 정할 것 (시작 전에)

| 결정 | 선택지 | 비고 |
| --- | --- | --- |
| 버튼 권한 | A 관리자만 / B 누구나(하루 한도) | A가 비용·악용 위험이 적다 |
| GPU 가동 | 데모·녹화 때만 켬 / 심사 기간 내내 켬 | L4 시간당 약 $1 수준(도쿄 실제 SKU 확인 필요). 켜 두면 요청이 없어도 과금 |
| 지출 상한 | 예: 이번 작업 전체 $30 | 예산 알림은 자동 차단이 아니다. 예약 종료를 켠다 |
| 모델 | 기본 `gemma4:12b`(평가 없이 채택) | 감사관 v5 등 학습 모델은 쓰지 않는다(Plan 06 중단) |
| 2단계 첫 판 | 미리보기 / 검수 큐 | 미리보기 권장 |

GCP 자원 생성과 비용이 드는 실행은 사용자(지시현) 확인 뒤에 한다.

## 5. 완료 기준

- 준비된 GPU에서 버튼을 누르면 분류·판정이 제한 시간 안에 끝나고 배치 결과와 나란히 보인다. GPU가 꺼져 있으면 상태 안내가 나오고 화면이 멈추지 않는다.
- 관리자가 고른 용어에 `risk`를 수동 실행하면 이전 값과 새 값의 차이가 보이고 공개 값은 바뀌지 않는다.
- GPU를 멈춰도 웹·API가 정상 응답한다.
- 운영 로그·실행 기록에 문장·모델 출력 원문이 없다.
- 실제 버튼 실행 한 번과 그 청구를 확인한다. 헬스 체크 통과만으로 완료로 보지 않는다.

10-14까지 1단계를 끝내지 못하면 멈추고, 영상에서는 0단계 화면과 수집 서버·Kaggle 기록으로 Gemma를 설명한다.
