## 1. 왜 하나

Gemma는 사전을 만드는 배치 단계(분류·리스크·쓰임 낱말·번역·문서 대조)에서 쓰이지만, 모두 수집 서버(PC)나 Kaggle에서 돈다. 배포본만 보는 심사위원은 Gemma가 실제로 도는 순간을 볼 수 없다. 이 계획은 그 순간을 배포본 안에서 보이게 한다.

| 항목 | 상태 |

## 3. 할 일

설계는 [Plan 14의 1·2단계](archive/14-gemma-visible-in-deployment.md#1-라이브-분류-버튼)를 그대로 따른다. 요약하면 다음과 같다.

1. **GPU 준비.** 운영 GPU VM을 Terraform으로 띄울 수 있게 하고(평소에는 꺼 둠), cold start 504를 고친다(→ 설치기 예열로 고침, `a3cb2bd`). 데모 전에 켜서 예열하고 끝나면 끈다.
2. **1단계 – `POST /terms/{term_id}/live-risk`.** 최신 기사 문장을 모아 `pipeline/risk.py`와 같은 프롬프트·규칙으로 분류하고, 배치 결과와 나란히 보인다. 공개 사전에는 쓰지 않는다. GPU가 준비되지 않았으면 '준비 안 됨'으로 알리고 기다리게 하지 않는다. 실행 기록에는 시각·용어 ID·문장 수·시간·결과 수준만 남긴다.
3. **2단계 – `/admin/status` 수동 실행.** 검수자만, 용어 1~5개에 `risk`(먼저)·`fit`·`translate`·`crosscheck` 중 하나. 첫 판은 결과를 화면에만 보이는 미리보기로 하고, 검수 큐 연결은 여유가 있을 때 한다.
4. **데모·README.** 결과에 맞춰 영상 장면과 README의 Gemma 설명을 고친다([데모 영상(sng_j)](sng_j-demo-video.md)와 맞춘다).

## 4. 정할 것 (시작 전에)

| 결정 | 선택지 | 비고 |
| --- | --- | --- |
| 버튼 권한 | A 관리자만 / B 누구나(하루 한도) | A가 비용·악용 위험이 적다 |
| GPU 가동 | 데모·녹화 때만 켬 / 심사 기간 내내 켬 | L4 시간당 약 $1 수준(도쿄 실제 SKU 확인 필요). 켜 두면 요청이 없어도 과금 |
| 지출 상한 | 예: 이번 작업 전체 $30 | 예산 알림은 자동 차단이 아니다. 예약 종료를 켠다 |
| 모델 | 기본 `gemma4:12b`(평가 없이 채택) | 감사관 v5 등 학습 모델은 쓰지 않는다(Plan 06 중단) |
| 2단계 첫 판 | 미리보기 / 검수 큐 | 미리보기 권장 |

**정한 것(10-10, ejchoi).** 버튼은 관리자(검수자)만 누른다. GPU는 데모·녹화 때만 켜고 끝나면 끈다 – 그 밖에는 버튼이 '준비 안 됨'으로 알린다. 이번 작업 전체 지출 상한은 $30이고 예약 종료와 함께 쓴다. 모델은 기본 `gemma4:12b`, 2단계 첫 판은 미리보기다.

GCP 자원 생성과 비용이 드는 실행은 사용자(지시현) 확인 뒤에 한다.

## 4-1. 1단계 구현 (10-10, 로컬 – 운영 미배포)

| 부분 | 내용 |
| --- | --- |
| API | `POST /terms/{term_id}/live-risk`(검수자 토큰만). `pipeline/live_risk.py` |
| 흐름 | GPU readiness를 3초만 확인 → 꺼져 있으면 기록 없이 `not_ready` → 표제어 나라 뉴스판에서 기사 제목 30건을 받아 표제어가 든 것만 최대 12건(`risk.PER_TERM`) → 5건 미만이면 `too_few`(모델 안 부름) → `risk.PROMPT`로 GPU gateway의 Gemma에 분류 → `risk.judge_labeled`(배치 `judge`에서 떼어 낸 같은 규칙)로 수준 |
| 공개 값 | 용어의 리스크·근거 분류 표(`evidence_labels`)를 바꾸지 않는다. 결과는 화면에만 |
| 기록 | migration `022_live_risk_runs.sql` – 시각·용어·상태·문장 수·걸린 시간·수준·모델만. 문장·모델 출력 원문 없음 |
| 한도 | 용어별 10분 캐시, 한 번에 하나(돌고 있으면 `busy`) |
| 웹 | 사전 항목의 '지금 다시 분류해 보기' 칸 – 검수자 세션일 때만. 지금 분류와 공개 판정을 나란히, 같은지·다른지, 분류한 제목 목록, 걸린 시간·모델 |
| 시험 | `tests/test_live_risk.py` 5개(GPU 꺼짐·정상 분류와 공개 값 불변·원문 미기록·캐시·기사 부족·동시 실행·실패·검수자 전용), e2e 2개(검수자 버튼 → GPU 꺼짐 안내, 비로그인에는 버튼 없음) |

## 4-2. 확인이 필요한 것 (10-10)

운영에 올리기 전에 정하거나 확인해야 한다. GCP 자원과 비용이 드는 일은 지시현 확인 뒤에 한다.

| 항목 | 누가 | 내용 |
| --- | --- | --- |
| 운영 GPU VM 띄우기 | 지시현 확인 → ejchoi | `infra/gcp/hybrid/gpu.tf`·`services.tf`가 `var.gpu`를 주면 VM·내부 IP·gateway 토큰 secret과 API의 `GPU_GATEWAY_*` 환경변수를 함께 만든다. 운영 tfvars에 `gpu`(boot image·모델 release·TLS secret·token version)를 채워야 한다. 평소에는 꺼 두고 데모·녹화 때만 켠다(10-10 결정) |
| 첫 적재 504 | ejchoi | staging의 504는 설치기 예열(`a3cb2bd`)로 고쳤다 – gateway는 모델이 올라간 뒤에 뜬다. 운영 VM을 켠 뒤 `/ready`가 200이 되기까지 걸리는 시간을 재서 데모 전 몇 분 앞에 켤지 정한다. 그 사이 버튼은 3초만 기다리고 `not_ready`로 답한다 |
| 분류 한 번의 시간 | 실측 필요 | gateway는 요청당 deadline 30초, API가 요청하는 출력은 512토큰(gateway 최대), 프롬프트는 12,000자까지다. 제목 12건 분류가 L4에서 30초 안에 끝나는지, 출력이 512토큰 안에 드는지 실제로 재야 한다. 넘으면 문장 수를 줄인다 |
| 지출 상한 $30 | 지시현 확인 | 예산 알림과 VM 예약 종료를 설정한다. 알림은 자동 차단이 아니다 |
| 배포 시점 | ejchoi | migration `022`(새 표 하나)가 API 시작 때 운영 DB에 적용된다. 운영 데이터 작업(게시·갱신)이 끝난 뒤 배포한다 |
| 완료 확인 | ejchoi | 실제 버튼 실행 한 번과 그 청구를 확인해야 완료다. 헬스 체크만으로 완료로 보지 않는다 |
| 2단계 | 미정 | 관리자 수동 실행(미리보기)은 아직이다. 10-14 코드 동결까지 1단계 운영 확인을 먼저 한다 |

## 5. 완료 기준

- 준비된 GPU에서 버튼을 누르면 분류·판정이 제한 시간 안에 끝나고 배치 결과와 나란히 보인다. GPU가 꺼져 있으면 상태 안내가 나오고 화면이 멈추지 않는다.
- 관리자가 고른 용어에 `risk`를 수동 실행하면 이전 값과 새 값의 차이가 보이고 공개 값은 바뀌지 않는다.
- GPU를 멈춰도 웹·API가 정상 응답한다.
- 운영 로그·실행 기록에 문장·모델 출력 원문이 없다.
- 실제 버튼 실행 한 번과 그 청구를 확인한다. 헬스 체크 통과만으로 완료로 보지 않는다.

10-14까지 1단계를 끝내지 못하면 멈추고, 영상에서는 0단계 화면과 수집 서버·Kaggle 기록으로 Gemma를 설명한다.
