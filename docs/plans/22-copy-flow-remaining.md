작성일 **2026-10-10** · 담당 **팀원(지정 필요)** · 상태 **시작 전** · 코드 동결 **10-14** · 제출 **10-18**

[계획 목록](README.md) · 이어받은 계획 [Plan 20](archive/20-copy-check-localization-flow.md)(방향·흐름·화면 원칙) · 일본어 화면은 [Plan 23](23-japanese-ui.md) · 데모는 [Plan 25](25-submission-demo-and-deck.md)

## 1. 방향 (Plan 20에서 정한 것)

제품의 중심은 **마케터가 낼 문구를 시장에 맞게 검사하고 고쳐 쓰는 흐름**이다. 트렌드·지도는 그 재료다. 시장은 한국·일본·영어권. 판정은 규칙, 문장은 모델, 근거 인용, 사람 승인을 유지한다. 흐름은 ① 넣기 → ② 검사 → ③ 제안 → ④ 시장별 고쳐 쓰기 → ⑤ 승인 → ⑥ 모르는 말 조사다. 이유와 테마·심사 근거는 [Plan 20 §2](archive/20-copy-check-localization-flow.md#2-왜-이-방향인가)에 있다.

화면은 10-08 r-stage('무대')로 바뀌었다(`apps/trend-web/components/stage/`, `app/stage.css`). Plan 20 §10의 n-redesign 원장은 `/lab/n-redesign`에만 남았고, 그 '누가 정했나' 표지는 `stage/bits.tsx`의 Actor(rule·ai·human)로 이어졌다.

## 3. 우선순위 (10-14까지)

데모 영상([Plan 25](25-submission-demo-and-deck.md))이 쓰는 장면부터 한다.

1. **⑤ 승인 기록 서버 저장.** 영상의 '사람이 승인해야 나간다' 장면이 실제 기록이 되게 한다. 로그인한 검수자만 승인, 승인한 문구·시장·밈·시각·검수자를 저장, `/admin`에 목록. 공유 링크는 여유가 있으면.
2. **④ 재검사 범위.** 모든 카피를 다시 검사하고, 걸린 카피는 승인 버튼을 막거나 고쳐 쓰기를 제안한다.
3. **`/check`와 `/drafts` 정리.** 옛 화면을 남길지, 새 흐름으로 합칠지.
4. 여유가 있으면 ⑥, 워드 클라우드 규칙, '지도에서 보기'.

## 4. 정할 것

- 승인 권한(검수자만 / 로그인한 누구나), 공유 링크 공개 여부, 승인 기록 보존 기간.
- 첫 화면에서 문구 입력을 검사로 보낼지(Plan 20 원안), 지금처럼 모두 초안으로 보낼지.
- 포스터 생성을 켤지(비용).
- 밀린 검수 큐(Plan 20 §9, 당시 1,739건)를 정리할 규칙.

## 5. 지키는 것

- 이용자 화면에 내부 용어·모델 이름·점수를 내지 않는다(`apps/trend-api/AGENTS.md`).
- 승인 기록과 운영 로그에 이용자 문구 원문을 남기지 않는다. 저장이 필요하면 접근 통제한 표에 두고 보존 기간을 정한다.
- 디자인은 r-stage 규칙을 따른다.

## 6. 완료 기준

- 배포본에서 문구를 넣으면 검사 → 시장별 고쳐 쓰기 → 모든 카피 재검사 → 검수자 승인까지 가고, 승인 기록이 서버와 `/admin`에 남는다.
- `docker compose run --rm --build check`와 `e2e`가 통과하고, `release/gcp` 배포 뒤 운영에서 한 번 확인했다.
