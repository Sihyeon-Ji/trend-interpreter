## 현재 결론

**지난 이틀의 진척은 크다. 특히 사전 공급·전수 대조·검수·감사와 운영 준비 코드가 늘었다.** 이전에 없던 Plan 12의 문서 대조와 승인 흐름이 구현됐고, Plan 01의 실데이터 이관·복원 리허설 기록이 생겼다. Plan 16의 일괄 등재와 성향 분석, Plan 06의 Kaggle 추론·학습 실험도 추가됐다.

그러나 **Trend 운영 배포, 승인 배치의 안전한 운영 게시, 현재 Gemini 요청 경로의 품질 평가와 사람 판정은 아직 완료되지 않았다.** 사전이 늘면서 생애주기·리스크 정보가 빈 항목도 추천에 많이 들어온다. 따라서 기능 코드의 진척과 제출·운영 완료도를 같은 숫자로 합산하지 않는다.

| 현재 분류 | 계획 | 수 | 의미 |
| --- | --- | ---: | --- |
| 주요 기능 구현, 데이터·품질·운영 검증 남음 | 02·03·04·07·08·12 | 6 | 관련 코드와 이번 자동 검사 확인. 02·12의 과거 완료 판정은 당시 데이터 범위에 한정 |
| 부분 구현 또는 실행 기록 있음 | 01·05·06·09·15·16 | 6 | 이관·편집·평가·수집·운영 준비의 진척은 있으나 전체 완료 기준은 남음 |

이 분류는 **16개 계획의 현재 상태를 나눈 것**이다. `6/16`을 구현률로 읽거나, 규모가 서로 다른 계획에 같은 가중치를 주어 전체 백분율을 만들지 않는다. 기존 보고서와 같은 방식으로 완료 조건의 충족 근거를 제시한다.

## 이번에 직접 확인한 것

작업 시작 시 `develop`의 작업 트리는 깨끗했다. 코드·테스트·계획·Compose·Terraform·릴리스 workflow를 대조하고 다음 명령을 실행했다.

| 검증 | 09-29 점검 | 10-01 이번 실행 |
| --- | --- | --- |
| `docker compose run --rm --build check`: Trend API | 189 통과 | **306 통과**(+117), 실패 0 |
| 같은 명령: 공통 테스트 | 8 통과·1 건너뜀 | 8 통과·1 건너뜀 |

처음에는 Docker daemon이 꺼져 세 명령 모두 시작하지 못했다. Docker를 시작한 뒤 위 명령을 다시 실행해 모두 완료했다. API·relay 검사에는 라이브러리 사용 중단 예고 경고가 각각 1개 있었으며 실패는 없었다.

**e2e의 범위:** Compose 웹 기본값인 `DATA_MODE=sample`에서 실행했다. 관리자 세션 설정이 있어 검수 화면·수정안 표시·상태/리스크 탭도 이번에는 실행됐다. 실제 운영 API에 승인 쓰기를 한 검증이나 실모델 사진 이해를 검증한 것은 아니다. 36개에는 `reviewDecision` 거르개를 검사하는 2개도 포함된다.

**외부 상태의 읽기 전용 실측:**

- `gh repo view`: 저장소 `PRIVATE`, 기본 브랜치 `develop`.
- `gh api …/environments/gcp`: `protection_rules=[]`, `deployment_branch_policy=null`.
- `gh api …/actions/permissions/workflow`: 기본 토큰 권한 `read`, PR 승인 권한 `false`.
- `gcloud run services list`(프로젝트 `stunning-crane-508614-c1`, `asia-northeast1`): `builder-cup`, `builder-cup-alert-relay` 두 서비스만 있고 둘 다 준비 상태 `True`. Trend 웹·API는 없다. 목록의 준비 상태는 실제 AI 호출이나 사용자 흐름 성공을 뜻하지 않는다.
- `gcloud sql instances list`: `trend-project`가 `RUNNABLE`, PostgreSQL 18, `db-perf-optimized-N-8`. 자동 백업과 PITR는 모두 `False`. 앱 연결·실데이터 적재·복원 성공은 이번 조회로 확인하지 않았다.

**데이터 실측의 한계:** 이 Mac checkout에는 `apps/trend-api/data/`가 없다. 문서에 기록된 수집 서버 `192.168.100.22`로 읽기 전용 SSH 접속을 시도했지만 연결 시간 초과였다. 아래 사전 건수·이관 결과·모델 품질 수치는 **문서에 남아 있는 해당 시각의 측정 기록**이며 이번에 DB나 원본 평가 JSON으로 재집계한 값이 아니다. 기본 개발 모델은 mock이며 이번 점검에서 유료 모델을 호출하지 않았다. 수집 서버·운영 DB·GCP 설정은 변경하지 않았다.

### 01. 이관이 실행 대기에서 리허설 검증으로 진척

[이관 스크립트](../../../apps/trend-api/scripts/migrate_sqlite_to_postgres.py)와 [테스트](../../../apps/trend-api/tests/test_sqlite_import.py)에 빈 DB를 요구하는 `--fresh`, 사용자 자료 제외 `--skip-user-data`, 확산 필드 보정과 긴 뉴스 주소 처리의 검증이 있다.

[Plan 01 결과](../01-import-latest-trend-data.md#결과-2026-09-29-2302-kst-스냅숏--1915-회차-뒤)는 09-29 23:02 사본의 용어 745개·근거 15,807개·뜻 767개를 별도 PostgreSQL로 이관하고, 32개 표 중 31개의 건수와 행 내용 일치, 뉴스 주소 6건 제외, 건강 점검 경고 없음, `pg_dump`·복원 일치를 기록한다. 완료 기준 3개 중 앞의 두 개는 **별도 프로젝트 당시 기록**으로 확인됐고, SQLite 수집 중단·PostgreSQL 전환은 미충족이다.

당시 API 모드 e2e는 19 통과·10 실패·2 건너뜀이었다. 문서는 실패가 예시 데이터 전제 때문이라고 설명한다. 이번 sample 모드 36개 통과가 이 API 모드 실패를 해결했다는 증거는 아니다. 10-01의 확대 사전 전체가 이관됐다는 기록도 없다.

### 02. 예전 완료 기록과 현재 데이터 범위를 구분해야 함

[생애주기](../../../apps/trend-api/src/trend_agents/lifecycle.py)·[track](../../../apps/trend-api/src/trend_agents/pipeline/track.py)·화면·규칙 테스트는 구현됐다. 계획은 09-29 14:36의 `unknown` **1/152(0.7%)**를 근거로 완료라고 쓴다.

그러나 Plan 09의 3차 추천 표본은 **48/60(80%)가 unknown**이다. 이는 추천 표본이며 전체 사전의 unknown 비율은 아니다. 전체 기준인 30% 이하를 현재도 만족한다고 말할 수 없다. 현재 `track.run`은 원본 언급과 최근 쓰임 근거로 판정하며, 새 `term_pageviews`를 읽거나 위키 분류 연도를 생애주기에 연결하지 않는다. **당시 완료는 인정하되, 확대 사전의 시기 보강과 전체 비율 재집계가 필요하다.**

### 03. 리스크 평가 준비가 구체화됐지만 사람 평가는 여전히 없음

리스크 규칙·사람 결정 보존·[측정 스크립트](../../../apps/trend-api/scripts/risk_sample.py)·[평가 테스트](../../../apps/trend-api/tests/test_risk_sample.py)가 있다. 저장소의 [고정 표본 CSV](03-term-risk-sample.csv)는 20행이며 이번 직접 집계에서 **검수자 수준과 검수자 이름 모두 0행**이었다.

옛 16/20 일치율은 현재 고정 표본의 점수가 아니다. 현재 표본은 오판 사례를 필수로 포함해 재추첨했고 운영 수준을 바꾸지 않고 CSV에서만 일치율을 잰다. 위키의 민감한 뜻풀이·정치/사회 분류를 주의로 처리하는 규칙도 추가됐다. 다만 3차 추천의 **51/60 리스크 판단 보류**를 위험이 없다는 결과로 읽지 않는다.

### 04. 해외 공급이 늘었으나 균형과 API 모드 검증은 남음

[지역 규칙](../../../apps/trend-api/tests/test_regions.py), [대시보드 API 검사](../../../apps/trend-api/tests/test_ui_dashboard.py), 지역 선택·카드 열기 e2e가 이번 검사에 포함됐다. 지역별 매체·사용 지역에 따라 사전과 대시보드가 같은 규칙을 쓰도록 보강됐다.

문서의 10-01 카드 기록은 **KR 1,764·JP 411·TW 529·HK 64**, 반면 **TH 5·VN 4·ID 5·PH 5·MY 2·SG 1**이다. 이 숫자는 현재 DB 재집계가 아니다. 검색어 수집과 사전 후보 확보는 다른 조건이다. 10개국 검색어 수집의 과거 기록만으로 추천 공급을 완료했다고 판단하지 않는다. API 모드 웹 흐름의 별도 검증, YouTube 하루 사용량, 디자인 선택이 남는다.

### 05. 운영 준비 코드가 늘었지만 배포 완료 기준은 대부분 미충족

새 [maintenance.py](../../../apps/trend-api/scripts/maintenance.py)는 사용자 문장 보존 정리·마지막 정상 게시 점검·정상/실패/오래됨 종료 코드를 제공한다. `/meta`는 수집 성공이 아닌 마지막 정상 `board`·`dashboard` 게시로 갱신 시각과 `stale`을 판단한다. Gemini 호출마다 내용 없는 `gemini_call` 이벤트를 남긴다. 이 동작은 [운영 신호 테스트](../../../apps/trend-api/tests/test_ops_signals.py)로 이번에 검증했다.

그러나 [release workflow](../../../.github/workflows/release-gcp.yml)에 Trend application job이 없고 `scripts/deploy-trend.sh`도 없다. [Terraform](../../../infra/gcp/main.tf)에는 Trend 서비스·Cloud SQL 자원 선언이 없으며, 현재 Cloud SQL은 콘솔에서 만든 Terraform 밖 자원이다. 예약 유지보수·Discord 경보·Trend 지표 연결, 비공개 API 호출 인증, 후보 revision·복구·동시성 설정은 남았다.

Cloud SQL은 이번에 가동을 확인했지만 백업/PITR가 꺼져 있고 앱 연결을 확인하지 않았다. 실배포 뒤 재시작 보존·PC 중단 읽기·Gemini 켬/끔을 Vertex 요청 수와 함께 검증해야 한다. 개별 문서의 옛 '유지보수 스크립트·호출 로그가 없다'는 표는 이제 낡았다. **코드는 일부 준비됐고 운영 연결은 미완료**가 현재 판정이다.

### 06. 현재 실험 경로는 Kaggle이며 요청 경로도 진척

[Kaggle 노트북](../../../models/kaggle/gemma_risk_labeling.ipynb), [실행 도구](../../../models/kaggle/run_kaggle.py), [리스크 표본 내보내기](../../../apps/trend-api/scripts/export_risk_sample.py)가 있다. 문서는 10-01 합성 2개 용어·10문장, `gemma4:12b`, T4 x2, 292초, 두 호출 정상·Output 수령을 기록한다. 이번에는 그 실행 산출물을 읽지 못했으며 **재개·실표본·팀원 계정 실행은 문서상 미검증**이다. 리스크 추론 노트북은 아직 계획의 사전 언어판·국가별 해석 편집 배치 전체가 아니다.

번역과 단계 실행에 실제 모델 ID를 남기는 코드와 [모델 ID 테스트](../../../apps/trend-api/tests/test_model_ids.py)가 추가됐다. 이전 보고서의 '`/ask`는 로컬 모델만 사용'도 현재 코드와 다르다. `CHAT_BACKEND` 기본값은 `gemini`이고 [ask._chat](../../../apps/trend-api/src/trend_agents/pipeline/ask.py)은 [Gemini 도구 호출](../../../apps/trend-api/src/trend_agents/pipeline/gemini.py)을 먼저 사용한다. 다만 실패 시 로컬 폴백이 남아 있어 **PC가 꺼진 운영에서 실제 동작·사용자 원문 전달 경계는 별도 검증**해야 한다.

승인 배치를 운영 DB에 멱등 게시하는 도구·오래된 배치 보호·게시 이력은 아직 없다. 새 이관 옵션은 이 게시 경계를 대신하지 않는다. 운영 유지보수 부품은 구현됐지만 예약·운영 연결은 Plan 05에 달려 있다.

### 07·08. 추천·생성의 기능 검증은 강화, 실제 품질 완료는 아님

[추천 점수](../../../apps/trend-api/src/trend_agents/pipeline/recommend.py)는 제품과 분야가 맞지 않는 후보를 제외하고, 제품과 겹친 느낌에만 톤 점수를 주도록 개선됐다. 근거 없는 후보·사용 자제·저속한 말투 제외, 쓰는 나라 표기와 생성 가능 지역 검사가 있다. 이번 e2e는 **사진만 입력하기**, 추천→만들기, **검사에서 뺀 안의 본문 미노출**, 중단·휴대폰 흐름을 통과했다.

[생성 테스트](../../../apps/trend-api/tests/test_generate.py)는 기본 1회·재생성 최대 2회와 통과안 보존을 검증한다. 다만 추천 5개와 생성 세 결과물은 모든 실요청에서 보장되지 않는다. 실제 사진·현재 Gemini 경로·사람의 뜻/사용 가능성 판정은 여전히 남았다.

### 09. 측정 횟수와 평가 도구는 진척, 품질 승인과 제출 데모는 대기

[Plan 09](../09-generation-quality-evaluation.md)의 기록은 같은 20사례에서 끝까지 수행 **1차 8/20 → 2차 5/20 → 3차 12/20**이다. 3차는 KR·JP·TW 각각 네 제품이 완료되고 TH·ID는 0이다. 2차→3차 추천 수는 21→60으로 증가했다.

이는 사전과 규칙이 바뀐 실행들이며 고정 DB에서 한 요소만 바꾼 비교가 아니다. 3차의 추천 생애주기 unknown 48/60·리스크 보류 51/60과 함께 읽어야 한다. **수행 성공률 60%는 추천 적합도나 생성 정확도 60%가 아니다.**

새 [eval_editing.py](../../../apps/trend-api/scripts/eval_editing.py)와 테스트가 번역 원문 보존·뜻 버전·현지 밈 근거 앵커·모델별 결과를 읽기 전용으로 잰다. [편집 평가 기록](../../트렌드/평가.md)은 09-29 23:58 사본에서 옛 뜻 번역 24건, e4b 현지 밈 212개 중 인용한 공개 근거에 있는 81개와 커뮤니티에만 있는 113개 등을 구분한다. 이 도구와 구체적인 실패 분석은 이전보다 진척이다.

Gemini·사진 평가, 독립 사람 판정, 같은 스냅샷의 전후 비교, 배포 서비스의 데모 3개는 없다. `README.md`·`README.kr.md`에도 아직 현 추천·생성 평가 방법과 측정하지 않은 항목을 담은 제출용 절이 없다.

### 10. 그래프 코드의 추가를 계획의 완료로 세지 않음

현재는 검색어의 인물·위키·근거·용어 이웃 API와 [그래프 읽기 테스트](../../../apps/trend-api/tests/test_graph_read.py), 콘텐츠별 나라 밈·짝을 찾는 [content_agent](../../../apps/trend-api/src/trend_agents/pipeline/content_agent.py), `/graph` 화면이 있다. 이전보다 인접 기능은 늘었다.

그러나 `DERIVED_FROM`·`RELATED_TO` 용어 관계와 문장 근거 ID, 질문·추천의 한 단계 원조 추적, 원조가 답에 포함된 사례 5개는 없다. 콘텐츠의 `content_pairs`와 검색어의 `IS_TERM` 관계는 이 계획이 요구하는 용어 관계와 구분한다. 선택 계획이므로 제출 필수 진척에 억지로 포함하지 않는다.

### 11·13·14. 실행 대기의 성격이 서로 다름

- **11:** 이번에도 private·승인 규칙 없음이다. WIF 조건에 `assertion.environment == 'gcp'` 제약이 없고, 공개 전 전체 이력/개인정보 재검사와 실제 외부·collaborator 검증이 남는다. 일정상 제출 직전 작업이지 즉시 공개하라는 뜻은 아니다.
- **13:** Cloud SQL 체험 종료의 수동 전환 계획은 있다. 이번 RUNNABLE 조회가 전환 완료나 비용 수용의 증거는 아니다. 정확한 종료 시각·비용 결정·전환/이전/종료와 데이터 연속성 검증은 미실행이다. 이 점검에서는 비용을 추정하거나 자원을 변경하지 않았다.
- **14:** 초안이다. 문장별 Gemma 분류/모델 이름 표시·라이브 분류 endpoint·관리자 수동 risk 비교 실행·해당 GPU 서비스가 구현됐다는 근거가 없다. 현재 리스크 화면의 `live` 옵션은 API 저장 여부를 뜻하며 Gemma 라이브 분류가 아니다. 배포 버튼 실행·서비스 중단·청구 확인이 필요하다.

### 12. 이번 기간의 가장 뚜렷한 구현 진척

[crosscheck 단계](../../../apps/trend-api/src/trend_agents/pipeline/crosscheck.py)·[전수조사 스크립트](../../../apps/trend-api/scripts/crosscheck_dictionary.py), 참고 문서 수집, `review_queue.kind`·결정 이력·승인 시 새 뜻 버전이 구현됐다. 문서 없음과 접속 실패를 구분하고, 대기 중 공개 뜻을 유지하며, 오래된 검수 페이지의 token/meaning/kind 불일치를 거부하고 같은 제안을 되살리지 않는 테스트가 이번에 통과했다.

Plan 12 기록은 **165개 판정: 일치 46·고칠 것 76·위키끼리 다름 3·밈이 아님 18·문서 없음 22**다. 그중 수정안 65건 승인, 갈린 문서 3건 선택, 제외 제안 10건 중 7건 제외·3건 유지, 문서 없음은 14일 재탐색 뒤 사람에게 물어보는 처리가 기록돼 있다. 이는 원본 DB로 이번에 재확인하지 않은 **당시 전수 범위**다.

사용자 결정으로 일부 conflict는 3회 일치·발췌·문서 제목 규칙을 모두 넘으면 자동 새 판을 허용하며, 사람 승인 뜻은 보호한다. 따라서 옛 '모든 변경에 사람이 필요'를 예외 없는 현 규칙으로 쓰지 않는다. 새 위키 일괄 등재 전체가 이 165개 전수조사를 통과한 것도 아니다. 팀 PostgreSQL의 결과 반영과 확대된 현재 판별 대조 범위 확인은 남았다.

### 15. 페이지뷰 저장과 생애주기 활용 사이에 간격이 있음

`010_usage_source.sql`, 모델 추정과 네이버 실측 구분, 실측만 세대 막대를 표시하는 [규칙 테스트](../../../apps/trend-api/tests/test_rules.py)가 있다. `016_content_agent_and_pageviews.sql`, 월별 조회수 수집·저장·정점 조회 테스트와 [backfill](../../../apps/trend-api/scripts/pageviews_backfill.py)도 있다. 그러므로 계획 상태의 '1단계 1번만 구현'은 코드 진척을 다 담지 못한다.

그러나 현재 `track`에 페이지뷰 연결이 없고, 해외 표제어에 추이가 붙은 수·그중 생애주기가 바뀐 수는 Plan 15에 기록되지 않았다. 연구 자료 문서의 25,481개 페이지뷰 행은 표제어 수도, 생애주기가 바뀐 수도 아니다. Pinterest 수집기와 Google Trends alpha 계정 경로는 대기다.

### 16. 데이터 공급·감사·성향 분석 구현, 마지막 완료 집계가 남음

나무위키 분류 트리·Fandom·위키데이터·Trend A Word·위키백과 언어판, [catalog](../../../apps/trend-api/src/trend_agents/pipeline/catalog.py)·가벼운 조사·[audit](../../../apps/trend-api/src/trend_agents/pipeline/audit.py)·[성향 분석](../../../apps/trend-api/scripts/meme_tendency.py)이 있다. 분류/나라/연도는 출처에서 읽고 감사 실패를 바로 자동 제외하지 않으며, 규칙·표본 평가 도구도 추가됐다.

기록의 최신 시각을 구분하면 **00:30 확인 3,926개 → 06:53 확인 4,670개**, 06:53 fit 4,544개다. 같은 문서의 제목과 계획 목록은 아직 00:30 값을 가리킨다. 06:53 일괄 등재 수는 나무위키 4,902·PTT 523·홍콩 56·위키데이터 874·Trend A Word 640이다. 10:34 연구 내보내기의 **표제어 7,623개는 전체 표제어**이며 확인 4,670개와 같은 지표가 아니다.

성향 비중 표와 QLoRA 실행·시험 비교가 기록돼 있다. 첫 시험에서 좋은 파인튜닝 점수가 두 번째 시험에서는 떨어져 원본 12B 체크리스트를 선택한 경과도 포함한다. 연구 자료 문서는 감사 학습 정답을 **Claude 판정**이라고 명시하므로 이 점수를 팀원 독립 사람 검수 정확도로 세지 않는다. 이번 점검에서는 가중치·평가 JSON·모델을 재실행하지 않았다.

완료 기준 중 분류/비중을 데이터로 만드는 코드는 확인했다. 하지만 조사 대상 전체의 최종 성공·실패·검수 대기 사유 집계와 **날짜 있는 서로 다른 밈 1,000개 이상**의 현재 집계는 확인하지 못했다. 서로 다른 시각의 분류 수를 그대로 더하면 같은 용어가 중복되므로 합계로 판정하지 않는다.

현재 `meme_tendency.py:main`은 `sqlite3.connect("file:data/trend.db?mode=ro")`에 고정돼 있다. 팀의 PostgreSQL 기준에서 그대로 실행할 수 없으므로 Plan 01 전환 뒤 분석 경로를 연결해야 한다. 사람 확인 표시 항목의 검수, 시기/생애주기 보강, 분석의 API·관리 화면 노출도 남는다.
