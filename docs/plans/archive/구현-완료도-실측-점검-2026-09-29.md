## 한눈에 보기

현재 Trend 앱에서 **기능 코드가 상당히 구현된 계획은 02·03·04·07·08**이다. 다만 코드가 있다는 사실과 계획의 완료 기준을 충족했다는 사실은 다르다. 최신 데이터 재이관(01), Trend 운영 배포(05), 검수 후 운영 데이터 게시(06), 현 구조의 실모델 품질 평가(09)가 아직 연결되지 않았다. 10은 선택 계획으로 착수 전이고, 11은 제출 직전 작업이며, 12는 새 등재 게이트만 먼저 구현됐다.

| 범주 | 계획 | 판정 |
| --- | --- | --- |
| 기능 코드 구현, 완료 검증 남음 | 02·03·04·07·08 | 로컬·예시 경로와 규칙은 확인. 최신 운영 데이터·사람 판정·실모델 결과는 별도 확인 필요 |
| 기반만 준비되거나 일부 구현 | 01·05·06·09·12 | 계획의 핵심 완료 기준이 아직 충족되지 않음 |
| 실행 전 | 10·11 | 10은 선택 작업, 11은 공개·승인 설정 단계 대기 |

이 표는 임의의 백분율을 쓰지 않는다. 데이터 수집량과 모델 품질, 배포 운영은 코드 줄 수로 환산할 수 없으므로 아래에 **확인한 범위와 미충족 기준**을 각각 적었다.

## 조사 범위와 검증 방법

- 현재 브랜치: `develop`. 점검 당시 작업 트리는 깨끗했다. 저장소의 계획·API·웹·파이프라인·Terraform·GitHub Actions·테스트를 대조했다.
- `docker compose run --rm --build check`: Trend API **189개 통과**, 공통 테스트 **8개 통과·1개 건너뜀**, 알림 중계기 **10개 통과**, 웹 lint와 프로덕션 build 통과.
- `docker compose run --rm --build e2e`: **29개 통과, 관리자 흐름 2개 건너뜀**. 예시 데이터·기본 개발 설정에서 실행했다.
- `docker compose run --rm infra-check`: Terraform `fmt -check`, `init -backend=false -lockfile=readonly`, `validate` 통과. 호스트에는 Terraform 명령이 없어서 Compose 도구를 사용했다.
- 읽기 전용 조회: GitHub 저장소는 `PRIVATE`, 기본 브랜치는 `develop`, Actions 기본 토큰 권한은 `read`, `gcp` Environment의 `protection_rules`는 빈 목록이고 `deployment_branch_policy`는 없다. GCP Cloud Run `asia-northeast1`에는 `builder-cup`과 `builder-cup-alert-relay`만 조회됐다.
- Cloud SQL 인스턴스 목록은 `sqladmin.googleapis.com`이 비활성이라는 응답으로 직접 확인하지 못했다. Terraform에 Trend용 Cloud SQL 리소스가 없고 Trend 서비스도 조회되지 않는다는 근거까지만 사용한다.

**해석 한계:** Compose의 기본 설정은 유료 모델을 호출하지 않는다. 검사 통과는 실제 Gemini 접속·추천 품질·생성 품질·GPU 추론 준비·운영 DB의 현재 데이터 상태를 입증하지 않는다. 각 계획 문서의 2026-09-28~29 실데이터 수치는 **당시 측정 기록**이며 이번 실행에서 재측정한 현재값이 아니다. 이번 점검을 위해 원작자 PC의 DB나 운영 데이터를 수정하지 않았다.

## 계획별 대조

### 01. 최신 수집 데이터 재이관 – 실행 대기

SQLite→PostgreSQL [이관 스크립트](../../../apps/trend-api/scripts/migrate_sqlite_to_postgres.py)는 있다. 그러나 이 작업 공간에서 최신 `trend.db` 전달 파일은 확인되지 않았고, 원작자 파일과 로컬 PostgreSQL의 용어·근거·검수 기록을 대조한 결과도 없다. 이번 Compose 검사는 새 테스트용 DB 볼륨을 만들었으므로 이를 이관 완료의 근거로 삼을 수 없다. [계획의 완료 기준](../01-import-latest-trend-data.md#완료-기준) 세 항목은 최신 파일을 받은 뒤 다시 확인해야 한다.

### 02. 생애주기와 확산 단계 – 코드 구현, 최신 데이터 재검증 필요

[생애주기 규칙](../../../apps/trend-api/src/trend_agents/lifecycle.py), [추적 단계](../../../apps/trend-api/src/trend_agents/pipeline/track.py), `002_term_diffusion.sql`과 `005_weekly_by_region.sql`, [규칙 테스트](../../../apps/trend-api/tests/test_rules.py)가 있다. 사전과 대시보드에도 단계·이유가 노출된다. 계획 문서에는 검증 용어의 `unknown`이 **62/135(45%) → 3/135(2%)**로 줄었다는 측정이 있다. 이는 당시 DB 결과이며 01의 최신 데이터 이관 뒤에도 완료 기준인 **30% 이하**인지 확인해야 한다. 출처 근거를 주간 추이에 그대로 더하지 않고 최근 쓰임 판단에만 쓰도록 설계를 보정한 점도 코드에 반영돼 있다.

### 03. 용어별 리스크 – 코드 구현, 팀 표본 검토 필요

[리스크 분류·규칙](../../../apps/trend-api/src/trend_agents/pipeline/risk.py), `003_evidence_labels.sql`, [검수 API](../../../apps/trend-api/src/trend_agents/api/app.py), 관리자 주의 표현 화면과 관련 테스트가 있다. 사람의 수준 변경, 규칙 판정과 사람 판정의 분리, 결정자·시각 저장도 구현됐다. 문서의 개발자 1차 표본은 **16/20 일치(80%)**로, 팀원 재검토가 남아 있다. 01 이후 전체 검증 용어에 수준 또는 판단 보류가 붙는지도 새 DB에서 확인해야 한다. 현재 e2e에서 관리자 관련 2개는 건너뛰었으므로 실제 검수 화면의 이번 실행 통과로 세지 않는다.

### 04. 목표 지역·키워드 대시보드 – 화면·필터 구현, 지역 자료 보강 필요

`REGIONS_FOCUS`는 [10개 목표 지역](../../../apps/trend-api/src/trend_agents/config.py)이며, [대시보드 API](../../../apps/trend-api/src/trend_agents/api/app.py), [지역별 카드와 수치](../../../apps/trend-api/src/trend_agents/pipeline/dashboard.py), 웹 지역 선택 및 [e2e](../../../apps/trend-web/e2e/dashboard.spec.ts)가 있다. 익명 선택을 쿠키가 아닌 `?regions=` 주소로 보관하는 변경은 계획 결과 절에 설명돼 있다. 과거 측정에서는 10개국 모두 검색어가 수집됐지만, 검증 용어는 HK·VN·MY·SG에 **0개**였다. 지역별 실데이터 보강과 YouTube 하루 사용량 기록은 남아 있다. 현 데이터에서 지역 변경 시 목록과 수치가 정확히 바뀌는지도 API 모드로 재확인해야 한다.

### 05. Trend Cloud Run 배포 – 배포 기반만 준비

Trend API·웹 Dockerfile과 CI 이미지·smoke 검사는 있으나, Terraform의 Cloud SQL·Trend 서비스 계정·secret 구성, `deploy-trend.sh`, PC 독립 보존·건강 점검 작업이 없다. [릴리스 workflow](../../../.github/workflows/release-gcp.yml)에는 Trend application 배포 job이 없고 [복구 설정](../../../scripts/release_recovery.py)은 기존 `builder-cup`과 relay를 대상으로 한다. 실제 Cloud Run 조회에도 Trend 웹·API 서비스가 없었다. 따라서 `release/gcp` push로 Trend가 배포되고 재시작 후 데이터가 유지된다는 완료 기준은 충족되지 않았다. 기존 `builder-cup` 서비스는 유지 중이다.

### 06. 로컬 Gemma 편집·운영 데이터 게시 – 편집 부품 구현, 게시 체계 미구현

[로컬 모델 경로](../../../apps/trend-api/src/trend_agents/interpreters/local_chat.py), [뜻 번역](../../../apps/trend-api/src/trend_agents/pipeline/translate.py), [추천 적합도 태그](../../../apps/trend-api/src/trend_agents/pipeline/fit.py), 국가별 해석 단계 등 편집 부품은 있다. 그러나 검수된 배치를 Cloud SQL에 안전하게 게시하는 경계, 재실행·실패 배치 보호, PC가 꺼져 있을 때의 공개 읽기 검증과 독립 보존·경보는 없다. 계획 제목의 이전 Cloud Run GPU·vLLM 구상은 **철회**됐으므로 미완 항목으로 세지 않는다. 현 [파이프라인 단계 목록](../../../apps/trend-api/scripts/run_pipeline.py)은 로컬 배치이며 운영 게시 단계는 없다.

### 07. 사진·홍보 문구 기반 추천 – 기능 구현, 실서비스 품질 미확인

[추천 API](../../../apps/trend-api/src/trend_agents/api/app.py), [규칙 점수·근거 선택](../../../apps/trend-api/src/trend_agents/pipeline/recommend.py), 웹 폼, 단위 테스트와 e2e가 있다. 사진·문구 입력, 사용 자제 표현 배제, 최대 5개 추천 경로가 구현됐다. 다만 규칙은 적합한 후보가 없으면 5개를 채우지 않는다. 과거 20사례 측정에서는 태국·인도네시아 각 4사례가 **추천 0개**였다. 실제 Gemini 경로와 사람의 추천 적합도 평가는 09에서 다시 확인해야 한다.

### 08. SNS 카피·대본·썸네일 – 기능·규칙 테스트 구현, 현 구조 실모델 재평가 필요

[생성 API](../../../apps/trend-api/src/trend_agents/api/app.py), [검사와 최대 2회 생성](../../../apps/trend-api/src/trend_agents/pipeline/generate.py), 웹 결과 화면, [호출 횟수·제외 규칙 테스트](../../../apps/trend-api/tests/test_generate.py)와 추천→만들기 e2e가 있다. 부적절한 안은 결과에서 제외하므로 모든 요청에서 세 결과물이 반드시 나온다는 보장은 아직 없다. 계획에 적힌 실모델 표본은 요청 시 Gemma 검사 제거 **전** 구조의 결과다. 현재 Gemini 우선 구조의 시간·뜻 정확도·사용 가능성은 09에서 재측정해야 한다.

### 09. 추천·생성 품질 평가와 데모 – 1차 측정만 완료

[20사례 평가 스크립트](../../../apps/trend-api/scripts/eval_recommend.py)가 있고 당시 로컬 Gemma 평가에서 **20개 중 8개**가 추천부터 만들기까지 끝났다. 사람 판정 CSV는 채워야 할 칸을 비워 생성하므로, 추천 적합도·리스크 누락·뜻 정확도·바로 쓸 수 있는지에 대한 사람 결과는 아직 없다. 현 구조의 Gemini와 로컬 편집 Gemma 재측정, 동일 사례의 개선 전후 비교, 배포 서비스에서 재현하는 데모 3개도 남아 있다. 평가 스크립트는 사진 대신 홍보 문구를 사용하므로 사진 품질 표본도 별도로 필요하다.

### 10. 용어 관계 그래프 – 선택 계획, 착수 전

공통 [edges 저장소](../../../apps/trend-api/src/trend_agents/storage/dictionary_store.py)와 주제에 함께 묶인 표현을 보여 주는 사전 화면은 있다. 하지만 계획이 요구하는 용어 간 `DERIVED_FROM`·`RELATED_TO` 관계 생성, 문장 근거 ID 연결, 질문·추천의 한 단계 관계 추적 및 원조 용어가 답에 포함되는 사례 5개는 확인되지 않는다. 기존 주제 기반 관련 표현 화면을 이 계획의 완료로 세지 않는다.

### 11. 공개 저장소·GCP 배포 승인 – 실행 전

GitHub 조회에서 저장소는 **private**이고 `gcp` Environment의 필수 검토자·배포 브랜치 보호 규칙은 비어 있다. Actions 기본 `GITHUB_TOKEN` 권한은 이미 **read**다. [Terraform WIF 조건](../../../infra/gcp/main.tf)은 repository ID·owner ID·`release/gcp`·push event를 확인하지만 계획에서 요구한 `gcp` Environment OIDC subject 제약은 없다. 공개 전 이력 재검사, 공개 전환, 외부 계정·collaborator의 거부/승인 경로 실험은 아직 실행되지 않았다. 제출 직전 실행 계획이라는 일정상 지금 미실행인 것이 곧 결함이라는 뜻은 아니지만, 완료로 표시할 수는 없다.

### 12. 사전 전수 대조 – 새 등재 게이트만 구현

[참고 문서 게이트](../../../apps/trend-api/src/trend_agents/verification.py)는 새 자동 등재 항목에 문서를 요구한다. 그러나 `crosscheck_dictionary.py`, Know Your Meme 수집기, 현행 뜻을 유지하며 수정안을 따로 검수하는 승인 경로, `research` 뒤의 ‘문서 대조’ 단계와 전수 판정 결과는 없다. 현재 [검수 큐](../../../apps/trend-api/src/trend_agents/storage/dictionary_store.py)는 `draft_json`을 저장하지만, Plan 12가 요구한 **현행 확인 항목을 공개 상태로 유지하면서 수정안 승인 시 새 버전을 만드는 흐름**은 확인되지 않는다. 문서 없는 항목의 일괄 강등은 사용자 확인 전 실행하지 않아야 한다.

## `archive/`의 현재 적용성

`archive/`의 9개 계획은 문서상 **당시 완료 기록**이다. 현재 Trend 앱의 12개 계획과 번호가 같아도 별개다. 운영 알림 중계기, 변경 범위 판정, 릴리스 복구의 일부 코드는 지금도 [Terraform](../../../infra/gcp/main.tf), [relay 배포](../../../scripts/deploy-alert-relay.sh), [릴리스 workflow](../../../.github/workflows/release-gcp.yml)에 남아 있으며 이번 공통·relay 테스트와 인프라 검사를 통과했다.

반면 일부 archive 문서는 제거된 옛 `apps/api`·`deployment` 경로 또는 현재 `compose.yaml`에 없는 `doctor`, `model-eval`, `ollama-history-check`, `db-backup` 등의 명령을 가리킨다. 이들은 **역사적 완료를 보여 주지만 현재 checkout에서 그대로 재실행 가능한 운영 절차는 아니다**. Trend 앱 구현률이나 현재 검증 수치에 합산하지 않는다.
