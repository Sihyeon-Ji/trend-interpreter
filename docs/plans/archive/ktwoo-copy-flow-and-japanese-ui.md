## A. 문구 검사·현지화 흐름의 남은 일

### 1. 방향 (Plan 20에서 정한 것)

제품의 중심은 **마케터가 낼 문구를 시장에 맞게 검사하고 고쳐 쓰는 흐름**이다. 트렌드·지도는 그 재료다. 시장은 한국·일본·영어권. 판정은 규칙, 문장은 모델, 근거 인용, 사람 승인을 유지한다. 흐름은 ① 넣기 → ② 검사 → ③ 제안 → ④ 시장별 고쳐 쓰기 → ⑤ 승인 → ⑥ 모르는 말 조사다. 이유와 테마·심사 근거는 [Plan 20 §2](20-copy-check-localization-flow.md#2-왜-이-방향인가)에 있다.

화면은 10-08 r-stage('무대')로 바뀌었다(`apps/trend-web/components/stage/`, `app/stage.css`). Plan 20 §10의 n-redesign 원장은 `/lab/n-redesign`에만 남았고, 그 '누가 정했나' 표지는 `stage/bits.tsx`의 Actor(rule·ai·human)로 이어졌다.

### 3. 우선순위

데모 영상([데모 영상](../sng_j-demo-video.md))이 쓰는 장면부터 한다.

1. **⑤ 승인 기록 서버 저장.** 영상의 '사람이 승인해야 나간다' 장면이 실제 기록이 되게 한다. 로그인한 검수자만 승인, 승인한 문구·시장·밈·시각·검수자를 저장, `/admin`에 목록. 공유 링크는 여유가 있으면. – 10-12 코드 완료(§7), 배포 전
2. **④ 재검사 범위.** 모든 카피를 다시 검사하고, 걸린 카피는 승인 버튼을 막거나 고쳐 쓰기를 제안한다. – 10-12 코드 완료, 배포 전
3. **`/check`와 `/drafts` 정리.** 옛 화면을 남길지, 새 흐름으로 합칠지.
4. 여유가 있으면 ⑥, 워드 클라우드 규칙, '지도에서 보기'.

### 5. 지키는 것

- 이용자 화면에 내부 용어·모델 이름·점수를 내지 않는다(`apps/trend-api/AGENTS.md`).
- 승인 기록과 운영 로그에 이용자 문구 원문을 남기지 않는다. 저장이 필요하면 접근 통제한 표에 두고 보존 기간을 정한다.
- 디자인은 r-stage 규칙을 따른다.

### 7. 승인 기록 설계 (10-12)

| 무엇 | 정한 것 |
| --- | --- |
| 권한 | 요청은 설정된 계정만, 바로 승인·관리 화면 결정은 검수자만, 읽기 전용은 보기만. 웹 라우트(`app/api/approvals`, `lib/approval-handler.ts`)가 세션·같은 사이트를 보고 서버 토큰을 붙이고, API가 `ACCOUNTS`로 다시 본다(아니면 403). 이름은 세션에서만 |
| 한 줄 | 시장 하나: 시장, 고른 밈(term_id·표기), 제품 한 줄, 문구들(플랫폼·본문·해시태그)과 문구마다의 규칙 코드, AI 의견(시장마다 한 번), 요청한 계정·시각, 결정·결정한 사람·시각·메모 |
| 묶음 | 규칙 코드는 서버가 받은 결과를 믿지 않고 사전으로 다시 검사해 정한다. 막힘(규칙만): 사용 자제·저속한 말투(`MemeFit.voice=crude`)·욕설과 선정 표현. 읽어 볼 것: 조심·민감한 소재·판단 보류·식는 말·시장 밖·현지 표기, AI 의견 '뜻과 다름'·'판단 못 함'·받지 못함. 깨끗함: 규칙 통과와 AI 의견 '뜻에 맞음'. AI 의견은 초안 화면이 받은 것을 그대로 적는다(모델을 다시 부르지 않는다) – 그래서 위조를 막지 못하지만 막힘을 풀지는 못하고, 사람이 어차피 승인한다 |
| 결정 때 다시 검사 | 승인은 지금 사전으로 규칙을 다시 본 뒤에만. 그사이 막힌 말이 됐으면 승인하지 않고 막힘으로 옮긴다(409). 결정은 기다리는 요청에 한 번만 |
| 보존 | 본문(제품 한 줄·문구·AI 의견 문장)은 30일 뒤 지운다(`approvals.prune` – 유지보수 Job·`collect.retention`·관리 화면 조회 때). 검사 코드·사람·시각·메모는 남는다. 응답·로그에 본문을 쓰지 않는다 |
| 운영 DB 갱신·스냅숏 | `scripts/refresh_production.py`가 표째로 옮기고 `compare`가 센다. 스냅숏(`scripts/snapshot.py`)은 이 표가 들면 거부한다. 게시 역할은 이 표에 권한이 없어야 한다(`publisher_permissions`) |

- 배포 뒤 유지보수 Job 이미지(`production.tfvars.json`의 `services.api_image`)를 새 digest로 바꿔야 Job이 본문을 지운다. 그 전에도 관리 화면을 열 때마다 지운다.
- 초안을 다시 쓰면 보낸 요청은 대기열에 남는다(요청 철회는 없다). 검수자가 반려로 닫는다.
- 막힘은 요청 때(또는 마지막 승인 시도 때)의 검사 결과다. 그 뒤 사전에서 그 말이 풀려도 대기열은 막힘 그대로라 반려하고 다시 요청하게 한다.

- `check`·`e2e` 통과, `release/gcp` 배포 뒤 운영에서 확인.

## C. 완료 기록 (10-16)

- **A ⑤ 승인 기록.** 운영 배포(10-13~15)에서 쓰기 가능한 검수자 계정 `reviewer`(10-15 추가)로 승인해 운영 DB `copy_approvals` 에 승인 2건이 남았다(10-16 08:30). 읽기 전용 `judge` 는 '승인할 수 없다' 로 막힌다(데모 점검 10-14).
- **A ④ 재검사.** 모든 문구를 다시 검사하고 막힌 문구는 승인을 막는다. 10-15 에 검사가 시간 안에 안 돌아오면(504) 단계 막대를 실패로 보이고 '다시 확인' 단추를 두었고, 검사 결과에 걸린 말 이름을 붙였다('Risk not decided (Summer)'). 요청 제한은 웹 180초·API 150초로 늘렸다.
- **B 일본어 화면.** 운영에서 日本語 를 고르면 첫 화면·초안·둘러보기·사전 항목·관리 화면이 일본어로 나온다. 브라우저 언어와 `?lang=` 도 받는다(10-14). 화면 언어로 모델이 쓰는 글은 10-13 에 일본어로(용어집 §6), 사전에 묻기(챗봇)는 10-14 에 일본어로 답한다. 급증 이유·지구 주제의 나라별 차이는 일본어판(`Text2.ja`)을 둔다.
- **일본어 뜻.** 있던 말의 영어·일본어 뜻과 표제어 읽기는 사람 확인 대신 Sonnet 한 모델로 만들기로 바꿨다(10-13 사용자 결정, 규칙 검사 통과분만). 10-14 운영 DB 갱신으로 운영에 들어갔다.
- `check`·`e2e` 통과, `release/gcp` 배포 뒤 운영 확인(10-15 13:33).
