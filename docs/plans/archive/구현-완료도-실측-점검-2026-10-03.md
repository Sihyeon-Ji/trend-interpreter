## 판정 범위

현재 계획 01~17과 archive의 과거 계획 9개를 점검했다. 코드 기준은 `develop`의 `79268e0b6fdf4bca328d90c2ae338d42eee8acd0`이며, 점검 시작 때 이미 있던 GPU adapter·VM·설치 도구의 미커밋 변경도 별도로 검토했다. 이번 변경은 계획 문서 갱신이며 앱·인프라 코드는 수정하지 않았다. 점검 중 다른 작업에서 설치기의 명시적 빈 디스크 초기화·예약 내부 IP가 보강돼 gateway·인프라 검사를 마지막에 다시 실행했다.

완료는 파일 존재나 테스트 통과만으로 판정하지 않는다. **구현, 고정 실데이터, 독립 사람 평가, 실제 운영 검증**을 구분한다. 과거의 완료 기록은 당시 범위에서 보존한다. 계획마다 범위와 선행 조건이 달라 체크박스 수를 합산한 전체 백분율은 산출하지 않는다.

이번에는 GCP·GitHub·Kaggle의 현재 원격 상태를 조회하거나 변경하지 않았다. 원격 실행은 저장소의 날짜 있는 기록·manifest로 확인했으며, 유료 추론·학습·배포·알림 전송을 실행하지 않았다. Terraform 검증은 로컬 validate와 mock provider plan이며 실제 자원 plan/apply가 아니다. Graphify 산출물과 Serena 도구가 없어 소스·테스트를 직접 대조했다.

## 구현 적절성

책임 분리는 적절하다. 학습은 `models/kaggle/audit`, 서빙은 `models/serving`, 웹 인증은 서버 전용 fetch, 데이터 판정은 API 규칙으로 나뉜다. 입력/모델 해시 고정, 사람이 승인한 뜻 보호, 위험 후보 배제, 형식 실패를 평가 분모에 포함하는 방향도 유지할 가치가 있다. 다만 다음 항목은 기능 파일의 존재와 별개로 완료를 막는다.

### P1 – 승인 전 데이터를 공개 조회에서 차단하지 않음 (05·06·12·17)

[API](../../../apps/trend-api/src/trend_agents/api/app.py)의 `terms(status='all')`에는 사용자/검수자 권한 검사가 없고, `term()`은 `retired`만 차단한다. [메시지 해석](../../../apps/trend-api/src/trend_agents/pipeline/explain.py)도 verified와 needs_review를 함께 읽는다. 실제 함수에 합성 검수 대기 항목을 주입한 재현에서 상세 조회가 반환되고 `status=all`에 needs_review가 포함됐다. 운영 HTTP를 호출한 검사는 아니다.

이는 Plan 17의 '초안은 일반 조회에서 차단'과 어긋난다. Cloud Run의 웹 서비스 인증은 최종 이용자의 검수 권한을 대신하지 않는다. 공개 경로에는 승인 게시본의 동일한 필터를 적용하고, 검수 조회는 별도 권한 경계에 둬야 한다. batch/publication migration·멱등 게시·활성 게시 시각도 아직 없어 API 인증만 구현해 배포 완료로 올릴 수 없다.

### P1 – 현재 데이터로 생애주기·안전성 완료를 주장할 수 없음 (02·03·09·15·16)

확인 항목의 unknown 91.7%, 리스크 값 없음 92.9%, 사람 표본 판정 0/20이다. [track](../../../apps/trend-api/src/trend_agents/pipeline/track.py)은 `term_pageviews`와 분류 날짜를 읽지 않는다. 페이지뷰를 저장하는 것만으로 추천의 시기 정보가 개선되지 않는다.

현재 뜻에 `flagged`가 있는 verified 3,093개는 모델이 문제를 제안한 항목이며 **사람이 틀렸다고 확정한 3,093개가 아니다.** 자동 제외하지 않는 정책은 유지하되, 검수 우선순위·처리 결과·게시 적격 여부를 연결해야 한다. 나무위키 수정 시각을 실제 사용 시각으로 그대로 치환하면 옛 밈을 새 유행으로 만들 수 있으므로 문서 수정·발행·조회 정점·실제 쓰임의 의미를 구분해 보강한다.

### P1 – 의존성 보안 검사 실패 (05·11·17)

`docker compose run --rm security-check`가 종료 코드 1로 끝났다. 스캐너 결과는 **7개 패키지, 취약점 14건(critical 1·high 7·medium 6)**이며 웹/API lockfile에서 검출됐다. gateway lockfile에서는 검출되지 않았다. 이번 결과는 잠금 의존성의 알려진 취약점 검사이며 실행 경로별 악용 가능성을 재현한 결과는 아니다.

검출 대상은 `urllib3`, `brace-expansion` 두 버전, `braces`, `fast-uri`, `ip-address`, `next`다. CI가 이 검사를 필수로 실행하므로 기존 취약점이어도 현재 배포 차단이다. 의존성 갱신·호환성 회귀 검증은 후속 코드 작업이며 이번 문서 갱신에서 lockfile을 바꾸지 않았다.

### P1 – 공개 전 배포 승인 경계 미완성 (11·17)

[WIF 조건](../../../infra/gcp/main.tf)은 저장소·소유자·release ref·push를 검사하지만 `gcp` environment 조건은 없다. workflow에 environment가 있어도 다른 workflow가 같은 release 자격으로 교환하는 것을 클라우드 조건이 구분하지 못한다. 공개 전 보호 설정과 함께 environment 없는 토큰의 교환 거부를 검증해야 한다. 이번 점검은 현재 GitHub reviewer 설정을 확인하지 않았다.

### P2 – 감사의 일시 실패도 같은 뜻 판에서 재시도되지 않음 (12·16)

[audit.targets](../../../apps/trend-api/src/trend_agents/pipeline/audit.py)는 `audit_log`의 모든 `(term_id, meaning_id)`를 처리 완료로 본다. `audit_one`은 문서 본문을 얻지 못하면 `no_doc`, 재조사 예외에는 `error`를 기록한다. 같은 뜻 판에 새 문서가 생기거나 장애가 해소돼도 자동 대상에서 빠진다.

실제 `targets`에 합성 DB 응답을 주입해 기록 없음은 1개, 기록 있음은 0개로 재현했다. action·재시도 시각을 조회하지 않는 구조를 확인했다. 스냅숏의 현재 verified에 error 18개·no_doc 264개가 있다. 실패 종류별 재시도 주기와 수동 재검사 경로를 분리하고, 사람의 최종 결정은 계속 보호해야 한다.

### P2 – 메시지 재작성의 요청 예산·취소 경계가 다름 (05·06)

[explain._generate_apart](../../../apps/trend-api/src/trend_agents/pipeline/explain.py)는 `generate(con, prompt)`를 호출한다. [gemini.generate](../../../apps/trend-api/src/trend_agents/pipeline/gemini.py)의 기본 `request=False`로 파이프라인 장부와 재시도를 사용한다. 화면은 Future 대기를 12초 뒤 끝내지만 실행 중인 작업을 취소하지 않아 DB 연결·모델 작업이 뒤에서 계속될 수 있다. 사용자 요청 장부·deadline·실제 취소와 큐 상한을 맞춰야 한다. 유료 요청으로 재현하지 않고 호출 경로를 확인했다.

### P2 – 성향 분석 도구가 PostgreSQL 전환에 연결되지 않음 (01·16)

[meme_tendency.main](../../../apps/trend-api/scripts/meme_tendency.py)은 `sqlite3.connect('file:data/trend.db?mode=ro')`에 고정돼 있다. 현재 자료 분석은 가능하지만 `DATABASE_URL` 기반 팀/운영 PostgreSQL 분석을 완료한 것이 아니다. 저장소 어댑터 경로와 같은 스냅숏의 집계 일치를 확인해야 한다.

### 미커밋 GPU 작업의 추가 검증 조건 (06·14·17)

점검 시 `gpu_gateway.py`, `models/serving/.../install.py`, `infra/gcp/hybrid/gpu.tf`와 관련 설정·테스트가 작업 트리에 있었다. TLS·bearer·모델 digest 고정, 외부 IP 없는 VM·영구 디스크·2시간 종료 설정, 승인 release 설치 코드가 추가돼 로컬 검사는 통과했다. **커밋된 구현이나 실제 GCE 운영 완료로 세지 않는다.**

`local_chat` 공통 경로를 gateway로 바꾸므로 감사 외의 텍스트 작업도 같은 모델 ID라면 그 경로를 사용할 수 있다. 작업별 승인 모델 분리, 4,096 context·512 출력 토큰 제한에서 실제 감사/편집 출력의 완전성, 요청 취소 시 GPU 실행 종료, 준비된 boot image·실제 TLS/IAM·모델 설치/재시작을 통합 검증해야 한다. 도구 실행·사진은 adapter가 거부하므로 이 adapter를 일반 멀티모달·사전 질문 지원 완료로 해석하지 않는다.

## 커밋 전 후속 확인 (2026-10-03)

최초 점검 이후 `develop`에 캠페인 화면·밈 사용 게이트·GPU VM/설치/API adapter가 추가됐다(`0e156bb`, `0cf4797`, `4e237db`). 위의 미커밋 GPU 서술과 검사 수는 최초 점검 시점 기록이다. GPU 코드는 이제 커밋됐지만 실제 GCE/Cloud Run 구축·모델 승인·운영 검증 완료를 의미하지 않는다.

보안 의존성은 `urllib3 2.8.0`, `next`·`eslint-config-next 16.3.6` 및 네 가지 전이 의존성 override로 13건을 해소했다. `shadcn`은 CSS/CLI 빌드 도구이므로 devDependencies로 옮겼다. 수정판이 없는 `braces` 1건(`GHSA-vfj7-8cjw-p6xm`)은 저장소가 작성한 ESLint glob·shadcn 빌드 CLI 경로에 한정된 근거와 **2026-11-02 만료**를 `apps/trend-web/osv-scanner.toml`에 기록했다. 일반 사용자 패턴을 이 도구로 전달하는 앱 경로는 확인되지 않았다.

`docker compose run --rm security-check`는 이 설정으로 통과했다. **14건 전부가 패치됐다는 뜻은 아니며 13건 수정·1건 기한부 예외**다. 예외 만료 전에 재검토해야 한다. 승인 게시·공개 조회·WIF와 실제 운영/사람 품질 평가의 나머지 차단 조건은 유지한다.
