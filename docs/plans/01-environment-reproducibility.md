# 01. 개발환경 재현성과 진단

상태 **계획 작성 완료·구현 미착수** · 우선순위 **먼저** · [전체 계획](README.md)

## 해결할 문제와 목표

지금까지의 기동·모델 추론은 주로 한 Mac에서 확인했습니다. 다른 팀원이 clone했을 때도 개인 경로나
기존 DB 볼륨·캐시·호스트 패키지에 기대지 않고 개발을 시작할 수 있어야 합니다.
Ollama의 ‘설치됨’, ‘서버 실행 중’, ‘모델 다운로드됨’, ‘실제 추론 성공’을 따로 설명할 필요도 있습니다.

목표는 **설치가 막히면 어느 준비가 부족한지 알 수 있고, 새 환경에서 현재 명령을 재현할 수 있게 하는 것**입니다.

## 구현 범위

- 기본 개발에 필요한 Docker 엔진·Compose·포트와 현재 서비스 상태를 점검합니다.
- 선택적 Ollama 준비 상태를 별도 항목으로 보여 줍니다. 미설치는 기본 Mock 개발의 실패로 처리하지 않습니다.
- Docker에서 Mac의 Ollama에 접근할 수 있는지 확인하되, 기본 진단으로 실제 추론을 실행하지 않습니다.
- 프로젝트 루트·현재 checkout·Compose 프로젝트 이름을 확인해 잘못된 디렉터리 실행을 구분합니다.
- Mac 설치 안내에 진단 결과별 다음 행동과 예상 정상 상태를 연결합니다.

진단은 **읽기 전용**으로 설계합니다. `doctor`라는 opt-in Compose 서비스 추가를 후보로 두되,
컨테이너가 볼 수 없는 호스트 CLI·서비스 상태는 기존 호스트 명령으로 확인합니다.
호스트 상태를 보기 위해 Docker 소켓을 진단 컨테이너에 마운트하거나 관리자 권한을 주지 않습니다.

## 진행 순서

1. [현재 설치 안내](../setup-macos.md)대로 필요한 조건과 실패 메시지를 목록화합니다.
2. 자동 진단 항목과 사람이 호스트에서 확인할 항목을 나눠 읽기 전용 출력을 구현합니다.
3. 별도 checkout과 고유한 Compose 프로젝트 이름으로 기존 DB와 분리해 처음부터 기동합니다.
4. 포트 충돌을 피할 검증용 설정을 준비하고 기존 서비스·볼륨이 변경되지 않았는지 확인합니다.
5. 가능할 때 팀원 Mac 한 대에서 같은 안내를 따라 실행하고 차이를 기록합니다.

## 완료 기준과 확인 방법

| 기준 | 확인 방법 |
| --- | --- |
| Ollama 없이 기본 개발 가능 | 모델 미준비 상태에서 Mock 기동·검사 성공 |
| 개인 경로에 의존하지 않음 | 다른 checkout 경로에서 DB·API·웹 및 기본 실습 실행 |
| 새 DB 초기화 가능 | 별도 빈 볼륨에서 초기화 후 기록 생성·조회 |
| 진단이 상태를 바꾸지 않음 | 실행 전후 서비스·볼륨·패키지·모델 상태 비교 |
| 설치와 실행을 구분 | Ollama 설치/서버 중지, 모델 미설치, 서버 실행 상태별 안내 확인 |
| 실제 팀원 재현성 확인 | 다른 Mac의 OS·칩·Docker 버전과 성공/실패 기록 확보 |

같은 Mac의 새 checkout 검증은 다른 Mac 검증의 대체 증거로 표시하지 않습니다.
다른 Mac을 아직 사용할 수 없다면 마지막 항목은 미검증으로 남깁니다.

## 산출물과 제외 범위

산출물은 진단 출력, 필요한 최소 스크립트·Compose 설정, 갱신한 설치 안내, 환경별 재현 기록입니다.
실제 코드를 추가하면 실패 메시지 분기와 상태 비변경을 검증하고, 기본 `check`와 해당 기동 흐름을 확인합니다.
Windows 실제 검증, 패키지 자동 업데이트, 모델 자동 다운로드, 다른 팀원의 장비 원격 변경은 포함하지 않습니다.
