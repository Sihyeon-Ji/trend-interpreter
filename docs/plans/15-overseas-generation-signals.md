# Plan 15. 해외 세대·관심 신호: 네이버 데이터랩이 없는 나라

작성일 **2026-09-30** · 상태 **1단계 실측·추정 표시 및 검색 관심 분리 확인 – 해외 연령 실측 공급·계정 기반 확장 대기** · 근거 ADR 0003, [파이프라인 기록](../트렌드/파이프라인.md) · 목표일 **10-10** (1단계), 2·3단계는 계정이 생기는 대로

## 2026-10-08 고정 자료 재판정과 화면 경계

10-05 고정 snapshot(`20261005T124512-e56b90d`)을 해시 확인 후 격리된 PostgreSQL에 이관해 현행 `track`을 모델·외부 수집 없이 재실행했다(11,279개, 489초). verified 7,655개 중 월별 위키 조회수가 있는 말은 439개, 비한국어는 386개다. 재판정 뒤 비한국어 386개 중 **260개에 검색 관심 표시**가 붙었다(꾸준함·감소·잠잠함 가운데 하나). 이 260개의 쓰임 생애주기는 모두 `unknown`이다. 검색 관심은 별도 필드이며 조회수가 실제 쓰임을 판정한 결과가 아니다. 나머지 126개는 이 규칙으로 관심 단계를 정할 수 없었다.

같은 사본의 verified 용어에서 세대 출처가 `datalab`인 것은 한국어 99개뿐이다. 비한국어 용어에는 실측 연령 자료가 없다. 사전 응답이 출처를 버려 모델·분류가 제안한 세대를 사전 요약·목록 필터·국가별 합계·메시지 해석에서 실측처럼 다루던 경계를 고쳤다. 이제 이 자리들은 `datalab` 자료만 쓰고, 없는 해외 용어의 세대 수치·첫 관측 표는 숨긴다. 원래 뜻의 세대 추정은 관리자 검수 자료에 남는다. Pinterest 연결은 계정 준비 뒤 별도로 검증한다.

## 2026-10-06 재점검

`52eab53`의 관심도→생애주기 판정은 실측 비교에서 우연 수준이었고, `779705a`에서 `Term.interest`로 분리했다(Plan 02 검증). 아래의 위키 수정 시각·페이지뷰로 생애주기를 보강한다는 원안은 현행 완료 조건으로 그대로 적용하지 않는다. 해외 페이지뷰 수와 검색 관심 표시를 집계하고, 실제 쓰임 단계·세대 실측과 구분하는 조건으로 정리할 필요가 있다.

## 문제

- 한국어 표제어의 세대는 **데이터**가 정한다. 네이버 데이터랩 검색어 트렌드를 10대~50대 이상으로 나눠 불러 '어느 세대에서 먼저 튀었나·지금 얼마나 남았나'를 저장한다(`pipeline/naver.py`, 한국어 표제어만, 실행마다 12개).
- 해외 표제어(ja·en·zh·th…)의 세대는 **조사 모델이 쓴 추정**이 그대로 저장된다(`research.py` 가 `draft.generations` 를 usage 로 저장). '판정은 데이터, LLM 은 서술' 원칙에서 벗어나 있고, 화면에서는 한국의 실측과 구별되지 않는다.
- 관심의 크기·추이는 해외에도 신호가 있다. 이미 모으는 것은 다음과 같다.
  - Google Trends: BigQuery 공개 데이터셋 42개국 상위·급상승, 'Trending now' RSS
  - YouTube: 나라별 인기 영상
  - 위키백과: 언어판별 조회 상위, 문서별 페이지뷰(`wikipedia_search.pageviews`)
  - GDELT 쓰임 문장
  - Bluesky·Reddit: 지표로만

  빠진 것은 **나이대**다.

## 할 일

### 1단계 – 코드만으로 (지금)

1. **세대의 출처를 구별한다.** usage 한 줄마다 출처를 둔다: `datalab`(네이버 실측) · `pinterest`(2단계) · `model`(조사 모델 추정).
   이용자 화면은 실측이 아니면 세대를 '추정'으로 표시하거나 표시하지 않는다. 비교표·추천에서 세대 가중은 실측만 쓴다.
2. **위키 자료의 시기·관심과 쓰임 단계 분리(10-06 검증으로 변경).** 위키 분류의 연도·연대는 사전의 '유행 시기', 월별 페이지뷰는 '검색 관심'에만 쓴다. 원본 언급·실제 쓰임 근거가 없으면 생애주기는 `unknown`으로 둔다. 검색 관심은 `lifecycle.interest_stage` 규칙이 정하고 모델은 쓰지 않는다.
3. 테스트: 모델 추정 세대가 화면·추천 가중에 실측처럼 쓰이지 않는다. 페이지뷰가 없는 표제어는 아무것도 바꾸지 않는다.

1번 구현(2026-09-30). usage 에 `source`(마이그레이션 010)를 두고, 네이버 단계가 실측을 쓰면 그 나라의 추정 줄을 지운다. '사전에 묻기' 의 쓰임 카드는 실측일 때만 세대 막대를 그리고, 추정뿐이면 '실측 자료 없음 (조사 때의 추정: …)' 으로 말한다.

### 2단계 – Pinterest (사용자: 개발자 앱 만들기)

- 사용자가 Pinterest 개발자 앱을 만들고 토큰을 `.env`(`PINTEREST_ACCESS_TOKEN`)에 넣는다. 저장소에는 넣지 않는다.
- `collectors/pinterest_trends.py`: 나라마다 `growing` 목록을 나이대별로 부른다. 표제어와 **같은 표기**인 검색어만 받는다(`match.mentions`, 뜻으로 찾지 않음).
  받은 것은 나이대별 비율로 usage(`pinterest`)에 저장하고, 링크·근거로 이용자에게 내지는 않는다(지표만).
- 영어권 표제어(US·GB·CA·AU…)부터 시작한다. 걸리는 표제어가 적으면(생활·패션 밖의 밈은 거의 없을 것) 그 수를 이 문서에 적고 멈춘다.

### 3단계 – Google Trends API 알파 (사용자: 신청)

- 사용자가 [신청 페이지](https://developers.google.com/search/apis/trends)에서 알파를 신청한다. 허락이 나오면 표제어별 관심 추이(5년, 하위 지역)를 BigQuery 급상승 목록 대신 표제어마다 직접 잰다.

## 완료 기준

- 이용자 화면에서 해외 표제어의 세대가 실측과 추정으로 구별된다. 추정이 실측처럼 보이는 곳이 0이다.
- 해외 표제어 가운데 페이지뷰 추이가 붙은 수와, 그중 별도 검색 관심 표시가 생긴 수를 이 문서에 기록한다. 페이지뷰만으로 생애주기를 바꾸지 않는다.
- 2단계를 하면 나라별로 Pinterest 나이대가 붙은 표제어 수를 기록한다.

## 하지 않는 것

- 화면을 긁어 오는 비공식 수집(TikTok Creative Center, pytrends 류).
- 모델에게 세대를 '판정' 시키는 것. 모델 추정은 추정으로만 표시한다.
- 유료 데이터(DS.INSIGHT 등) – 결제는 사용자 결정.
