## 목적

개발자 PC에서 Gemma 4로 트렌드 사전과 국가별 해석의 초안을 만든다. 근거 대조·규칙 검증·필요한 사람 검수를 통과한 결과만 Cloud SQL에 게시한다. SaaS 사용자는 Cloud Run 웹·API에서 게시된 자료를 읽고, 사용자별 실시간 생성이 필요한 경우 Vertex AI Gemini를 사용한다. **사용자 기기에 모델을 설치하는 구조가 아니다.**

대회는 Gemini 또는 Gemma 등 Google AI 모델의 활용을 허용한다. Gemma의 역할은 공개 트렌드 자료를 작은 오픈 모델로 가공해 여러 사용자에게 재사용 가능한 지식 자산을 만드는 것이다. 모델 이름보다 원자료·근거·검수·게시 결과를 연결해 보여 준다.

## 범위와 역할

| 작업 | 실행 위치·방법 | 게시·요청 경계 |
| --- | --- | --- |
| 공개 자료 수집, 검색어·밈 후보 분류, 텍스트 초안 | 개발자 PC의 현행 파이프라인 + Gemma 4 | 임시 초안은 공개하지 않음 |
| 쇼츠 직접 해석, Google Search grounding | 개발자 PC 파이프라인이 Vertex AI Gemini 호출 | 모델 호출 예산·근거 기록 유지 |
| 검증된 뜻의 ko·en 언어판, 국가별 해석 초안 | 개발자 PC의 Gemma 4 | 원어 표제어·근거·스키마 검증 후 게시 |
| 뜻의 검증 상태·생애주기·리스크 | 코드 규칙과 사람 검수 | 모델의 단독 판정 금지, 뜻 버전 유지 |
| 지도·사전·리포트 열람 | Cloud Run 웹·API와 Cloud SQL | 마지막 성공 게시본 제공, 갱신 시각 표시 |
| 신규 사진·홍보 문구 이해, 카피·대본 생성 | Cloud Run API가 Vertex AI Gemini 호출 | 요청 시 처리, 호출 예산 적용 |
| 새 메시지 재작성·사전 질문 응답 | 저장된 근거·규칙 우선, 필요 시 Gemini | Gemma 로컬 PC에 실시간 의존하지 않도록 별도 구현·평가 |

현재 `USE_LOCAL_GEMMA=1` 라우팅은 `pipeline/gemini.py`의 텍스트 작업과 `pipeline/translate.py` 등에 적용된다. 운영 API에 같은 값을 켜면 로컬 PC에 연결되는 것은 아니다. 운영 웹·API의 Gemma 경로는 기본으로 사용하지 않는다. `/explain`, `/ask`, Plan 07·08의 사용자별 설명·검사 경로는 클라우드 전용으로 조정하고 실데이터에서 검증해야 한다.

## 구현 순서

1. **운영 DB와 게시 경계.** Plan 05의 Cloud SQL과 서비스 계정을 준비한다. 로컬 파이프라인이 바로 운영 표를 변경할지, 검수 후 게시 단계를 거칠지 결정하고 구현한다. 공개 자료·초안·검증 상태를 구분하고, 실패 배치와 재실행이 마지막 정상 게시본을 손상시키지 않게 한다.
2. **로컬 실행.** `apps/trend-api/scripts/run_pipeline.py`의 실행 단계와 실제 모델 라우팅을 검증한다. PC의 Gemma 모델 ID·버전, 배치 시간, 단계별 결과 수를 기록한다. 영상·검색 grounding은 Gemini 경로로 유지한다. 현행 기본 모델 `gemma4:12b`의 실측을 과거 GPU 계획의 E2B 실측으로 대체하지 않는다.
3. **운영 DB 접속.** PC에서 Cloud SQL에 접속할 방법과 최소 쓰기 권한을 정한다. Cloud SQL Auth Proxy를 사용할 수 있으나 private IP라면 별도 네트워크 경로가 필요하다. DB 비밀번호·사용자 문장·생성 결과 전문을 로그나 Git에 기록하지 않는다.
4. **서비스 분리.** Cloud Run 웹·API는 PC가 꺼져 있어도 게시된 자료를 읽어야 한다. 운영 `USE_LOCAL_GEMMA=0`을 기본으로 하고, 요청 시 필요한 자유 서술은 Gemini 또는 사전 기반 규칙으로 구현한다. 갱신 시각과 오래된 자료 안내를 화면·운영 상태에 반영한다.
5. **보존·감시.** 해석 캐시 7일, 미해결 질문 30일 삭제를 로컬 전체 파이프라인의 `collect.retention`에만 의존하지 않게 분리한다. 마지막 정상 게시 시각과 오래된 게시본에 대한 경보를 PC와 독립적으로 운영한다.
6. **품질 평가와 시연.** 같은 원자료에 대해 Gemma 초안, 근거 게이트, 사람 수정, 게시본을 추적한다. 언어별 뜻 보존·국가별 차이·출처에 없는 주장·처리 시간을 측정하고 Plan 09 평가에 넣는다.

## 완료 기준

- 개발자 PC의 Gemma 4가 검증된 사전 언어판과 국가별 해석 초안을 만들고, 모델 ID·실행 시각·근거·검수 상태를 추적할 수 있다.
- 검증되지 않은 초안은 공개 API에 노출되지 않고, 같은 배치를 다시 실행해도 뜻 버전과 게시 데이터가 손상되지 않는다.
- PC가 꺼진 상태에서도 공개 지도·사전·게시 결과가 열리고, 마지막 갱신 시각과 오래된 자료 상태가 정확하다.
- 실시간 사용자 기능은 PC 또는 Cloud Run GPU Gemma 없이 작동하며, 사용자 원문은 PC로 보내지 않는다.
- 보존 기간 정리와 운영 건강 점검은 PC의 배치 성공 여부와 독립적으로 동작한다.
- 대표 사례의 근거 일치와 품질을 평가해, Gemma 사용을 대회 제출물에서 실제 결과로 설명할 수 있다.

## 제외한 계획

- `builder-cup-gemma` Cloud Run GPU 서비스, vLLM 이미지, GPU IAM·알림 예산·인스턴스 경보는 만들지 않는다.
- `LOCAL_LLM_BASE_URL`로 Cloud Run API가 개발자 PC의 Ollama에 직접 접속하는 경로를 만들지 않는다.
- Cloud Run GPU 비용이 Gemini API보다 낮거나 E2B가 PC의 12B와 같은 품질이라는 주장은 실측 전까지 하지 않는다.
