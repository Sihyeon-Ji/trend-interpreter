근거·검증 범위와 구현 적절성은 [10-03 점검 보고서](구현-완료도-실측-점검-2026-10-03.md)를 따른다. 아래 날짜별 결과는 당시 기록으로 보존한다.

## 목표

사용 흐름의 3단계 "만들기"를 만듭니다. 추천에서 고른 밈으로 바로 쓸 수 있는 결과물을 만듭니다.

## 출력

| 결과물 | 내용 |
| --- | --- |
| SNS 카피 | 인스타그램 캡션(해시태그 포함), X 게시글. 각 2안 |
| 숏폼 대본 | 틱톡·릴스용 15~30초. 장면별 화면·자막·대사·길이 |
| 썸네일 구성안 | 주요 문구, 배치, 색, 인물·제품 위치 |

모든 결과물은 입력 언어가 아니라 **목표 지역의 언어**로 만들고, 한국어 설명을 함께 붙입니다.

## 호출 구조

요청 시 모델 호출은 기본적으로 Gemini 생성 한 번입니다([ADR 0002 §3](../adr/0002-고도화-방안.md)).

1. **생성.** Gemini 한 번의 구조화 호출(`pipeline/gemini.py`의 `generate`, JSON schema). 입력은 Plan 07의 제품 설명, 고른 밈의 사전 뜻·뉘앙스·리스크, 톤, 목표 지역.
2. **사전 대조 검사.** 게시된 사전 뜻·리스크와 코드 규칙으로 표현 사용을 대조합니다. 규칙으로 판단할 수 없는 뉘앙스는 Gemini 추가 검사의 필요성과 품질을 Plan 09에서 평가합니다. 어긋나면 한 번 다시 생성하고, 두 번째도 어긋나면 해당 안을 빼고 이유를 표시합니다. 개발자 PC의 Gemma에 실시간으로 연결하지 않습니다.

## 구현

- API: `POST /generate`. 입력은 추천 결과의 용어 ID와 제품 설명이며, 생성 결과는 저장하지 않습니다.
- 웹: 추천 화면에서 밈을 고르면 생성 화면으로 이어지고, 결과마다 복사 버튼을 둡니다.
- 기본 개발 환경에서는 고정된 예시 결과를 돌려줍니다.
- 결과 화면에 "AI가 만든 초안이며 게시 전 확인이 필요합니다"를 표시합니다.

## 완료 기준

- 고른 밈 하나로 세 가지 결과물이 모두 나옵니다.
- 사전 대조 검사에서 걸린 안은 화면에 나오지 않는 테스트가 있습니다.
- 기본 경로의 모델 호출은 1회, 재생성 시 최대 2회인 것을 테스트로 확인합니다. 추가 모델 검사를 도입하면 한도를 다시 정합니다.

## 구현 (2026-09-29)

- `pipeline/generate.py`, API `POST /generate`(JSON: 고른 밈 1~3개·추천이 읽어 낸 제품 설명·목표 지역 하나·톤·화면 언어), 웹은 추천 결과에서 밈을 골라 '카피·대본 만들기'.
- **호출 구조 (09-29 모델 배치 변경 반영).** 생성은 `gemini.structured(prefer_gemini=True)` 한 번 – Gemini 가 설정돼 있고 예산이 남았으면 로컬 Gemma 가
  켜져 있어도 Gemini 가 만든다. 요청 때의 Gemma 검사는 없앴다(develop 504d04c: 개발자 PC 의 Gemma 에 실시간으로 기대지 않는다). 걸린 안이 있으면
  문제를 적어 한 번 다시 만들고, 두 번째도 걸린 안은 빼고 이유를 보인다. 호출은 1회, 다시 만들어도 2회(`test_one_model_call_when_everything_passes`,
  `test_failed_items_are_regenerated_once_then_dropped` 가 센다). 다시 만들기가 실패해도(예산·장애·형식 오류) 첫 안에서 통과한 것은 돌려준다.
- **검사는 규칙.** 카피는 고른 밈이 글에 실제로 있어야 하고(`mentions`), 어떤 안도 욕설·선정 표현(`unsafe`)·제품 설명이 피하라고 한 말이 없어야 하며,
  X 게시글은 복사 버튼이 만드는 글(본문+해시태그) 그대로 X 가중치(한글·가나·한자·이모지 2)로 280 이내여야 한다. 뺀 안은 코드(`Dropped.code`)로 알려
  두 화면 언어 모두 이유를 보인다. 규칙으로 가를 수 없는 뉘앙스(뜻대로 썼나)는 Plan 09 사람 평가('뜻 정확성')로 추가 검사가 필요한지 정한다.
- **말.** 결과물은 목표 지역의 말(한국어·일본어·번체 중국어·태국어·베트남어·인도네시아어·말레이어, 필리핀·싱가포르는 영어). 설명 칸(노트·배치·위치·색)만
  화면 언어 – 다른 말로 온 설명 칸은 비운다. 해시태그는 한 낱말로(공백·기호 제거, 태국어 결합 부호는 남김).
- **쓸 수 있는 밈.** 확인된 것, 사용 자제 제외, 그리고 `writable` – 그 지역에서 쓰이고 그 말로 쓴 글에 넣을 표기(표제어·별칭이 그 말의 글자이거나 로마자)가
  있는 것. 일본에서도 쓴다고 조사된 한글 표기 밈(럭키비키·건어물녀)은 가타카나 별칭이 없으면 일본 카피에 쓰지 않는다. 추천 결과의 `write_regions` 가 같은 규칙.
- **주의 밈.** '쓸 때 조심' 은 사전 뜻풀이의 주의점과 근거 문장의 위험 유형으로만 만든다 – 검수 화면용 이유는 남의 글을 그대로 인용하고 있어 생성
  프롬프트에 들어갔다(검토 3차). 검수자가 정한 주의는 "검수자가 주의로 정함" 으로 전한다. 제품 설명은 `<제품>` 칸에 넣고 그 안의 지시는 따르지 말라고 둔다.
- 결과는 저장하지 않는다. 모델이 아예 설정되지 않은 개발 환경만 고정 예시(화면이 '예시' 라고 알린다) – 설정된 모델이 꺼져 있으면 예시 대신 503.
  분당 10회, 모델을 부르는 요청은 인스턴스당 동시에 둘. 몸통 16KB 까지(제품 설명은 백엔드·웹 모두 120·200자로 자른다).
- 로컬 Gemma(개발 PC)가 만들 때 thumbnail 을 script 안에 넣는 모양 실수(18번 중 7번)는 `ContentDraft` 가 모양만 바로잡는다. 재질문에는 어느 키가 틀렸는지 적는다.
- 테스트: 호출 수 1·2, 다시 만든 안 채택, 다시 만들기 실패 시 통과한 안 유지, 규칙 네 가지, X 가중 글자 수, 쓸 수 있는 밈, 주의 안내가 인용하지 않음,
  설명 칸 언어, 해시태그, 모양 바로잡기, 몸통 한도, 모델 없는 예시와 설정된 모델 장애. e2e 는 추천 → 밈 고르기 → 만들기까지(복사 버튼 이름·초점 이동).

**고친 것.** 처음에는 고른 밈을 지역과 상관없이 썼다. 한국 밈(오살힘)으로 일본 카피를 만들자 가타카나로 옮겨 적어(オサルヒム) 읽히지도 않고,

다른 표기(별칭)를 프롬프트에 함께 준다. 또 `prefer_gemini` 가 문자열 프롬프트를 로컬로 돌리던 버그(구조화 결과 없음)를 고쳤다.

**남은 일(Plan 09).** Gemini 경로가 85초로 길다 – 다시 만들 때 걸린 안만 다시 만들게 하면 절반으로 줄 수 있다. 20개 사례 평가로 잰다.

### 과거 상태와 당시 남은 일 (2026-09-29 실측)

완료 기준 셋을 모두 테스트로 충족했다.

- **세 결과물:** `tests/test_generate.py` 가 밈 하나로 카피 4·대본·썸네일이 한 번에 나오는 것을, `e2e/sample-flow.spec.ts` 가 추천 → 만들기 → 대본·썸네일 탭·복사 버튼·AI 초안 안내를 확인한다.
- **걸린 안은 화면에 없음:** 사전 대조에 걸린 안은 코드(`no_meme` 등)로 빠지고 3개가 남으며, 다시 만들기가 실패해도 통과한 안은 유지된다(같은 파일).
- **호출 1회·재생성 시 최대 2회:** `generate.py` 의 논리 호출 수가 그렇다. 한 논리 호출 안에서는 기본 Gemini → 폴백 모델 → 로컬 Gemma 를 차례로 시도할 수 있다(`gemini.py`).
- 부적절한 안은 결과에서 빠지므로 모든 요청에서 세 결과물이 반드시 나온다는 보장은 아직 없다.

남은 일(모두 [Plan 09](09-generation-quality-evaluation.md) 와 이어진다):

1. 현재 구조에서 실제 Gemini 로 지연 p50·최대, 호출 수, 뺀 코드, 뜻 충실도를 잰다. 위 표의 Gemini 수치(85초·4호출)는 지금은 없는 로컬 Gemma 검사가 섞인 것이다.
2. 걸린 안만 다시 만들게 한다. 지금 두 번째 호출은 피드백을 붙여 `ContentDraft` 전체를 다시 요청한다. 걸린 id 만 다시 만드는 스키마·프롬프트를 더하고 2회 한도 테스트를 유지한다.
3. **팀 판정 대기:** 사람이 '뜻대로 썼나' 를 판정해 Gemini 뜻 검사가 필요한지 정한다(첫 실행에서 일본 카피가 サイゼで喜ぶ彼女 를 'テンション上がる' 의 뜻으로 쓰고, 대만 카피가 한글 오살힘을 번체 문장에 넣은 사례가 있었다. 뒤의 것은 `generate.writable` 이 이제 막는다).
4. 선택: `/api/generate` 를 가로채 뺀 안을 돌려주고 이유 목록만 보이는지 확인하는 e2e.
5. Gemini 실측 뒤 위 '실모델 확인' 표를 새 수치로 바꾼다.

### 뺀 안의 화면 테스트 (2026-09-29)

완료 기준 2('걸린 안은 화면에 나오지 않는다')는 백엔드 테스트만 있었다. e2e `a draft left out by the checks shows only its reason, never its text`는
`/api/generate`를 가로채 통과한 안 하나와 뺀 안 하나(`code: avoid_word`, 운영 기록용 `reason`에 걸린 글을 담음)를 돌려주고,
화면에 통과한 안과 '검사에서 뺀 안 1건'·코드의 문구만 보이며 `reason`에 든 글은 어디에도 나오지 않는 것을 본다.
