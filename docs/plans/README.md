수치는 **10-01 22:45 KST 고정 사본을 10-03에 점검한 결과**다. 로컬 검사 통과와 사람 품질·운영 완료를 구분하며, 상세 판정은 [점검표의 빠른 요약](구현-완료도-실측-점검-2026-10-03.md#빠른-요약)을 따른다.

순서를 정한 기준은 다음과 같습니다.

- 대시보드·추천이 쓰는 생애주기와 리스크 데이터를 먼저 만듭니다(01~03).
- 첫 화면(04)이 생기면 바로 배포해, 인프라 문제를 마감 직전이 아니라 중간에 발견합니다(05).
- 추천·생성이 참조할 검증된 사전과 국가별 해석 게시 경계를 먼저 마련합니다(06). 요청 시 검사는 운영 데이터·규칙 코드로 처리합니다.
- 공개 저장소 전환(11)은 제출 1~3일 전 마지막에 합니다. Collaborator 목록 정리는 이미 끝나 다시 하지 않습니다.
- 사람이 둘 이상이면 05의 Cloud SQL·배포와 06의 Kaggle 실험·편집·게시 검증을 02부터 병행할 수 있습니다.
- 12는 [사전 등재 기준](../adr/0003-사전-등재-기준.md)(2026-09-29)으로 더한 데이터 작업입니다. 번호는 마지막이지만 다른 계획을 기다리지 않고 바로 시작할 수 있습니다.
- 13은 공모전 제출 이후에도 Trend 서비스가 중지되지 않도록 체험 종료 전에 실행하는 운영 계획입니다.

2026-09-28에는 전체 파이프라인 Cloud Run Job과 Gemma 전용 GPU 배포를 철회했습니다. 2026-10-01에는 하이브리드 아키텍처를 채택해 **Gemma 운영 서빙을 GCE GPU로 결정**했습니다([Plan 17](17-hybrid-infrastructure.md)). 전체 수집은 현재 서버에서 계속하고 승인한 자료를 게시합니다. 이전 [Gemma 로컬 편집 엔진 결정](../AI-개발/Gemma-로컬-편집-엔진-결정.md)은 당시 기록으로 보관합니다.

2026-09-29에는 [Plan 06](06-gemma-on-cloud-run-gpu.md)의 Gemma 실행 위치를 Colab GPU 중심으로 변경했고, 무료 Colab에서 GPU를 받을 수 없어 2026-10-01에 Kaggle 노트북으로 다시 옮겼습니다. 팀원별 Kaggle 노트북과 비공개 Dataset을 사용하며, 현재 리스크 추론 노트북과 별도 미세조정 실험을 구분합니다. 실표본 실험은 Plan 01의 데이터 준비 범위에서 시작하고, 운영 게시에는 Plan 05가 필요합니다.

2026-09-28에 `prototype/trend`를 메인 앱(`apps/trend-api`, `apps/trend-web`)으로 승격했고, 이전 실습 앱의 배포 job은 제거했습니다.
아래 archive의 계획은 **번호가 같아도 현재 계획과 별개**이며 구현과 운영 검증을 마친 기록입니다.

## 공통 원칙

- `develop`에서 작업하고 `release/gcp` push만 실제 GCP 배포를 시작합니다.
- 배포 전에 Compose 전체 검사와 인프라 검증을 통과시킵니다.
- 운영 로그와 알림에 원문, 생성 결과, API key를 포함하지 않습니다.
- GitHub와 GCP 설정을 바꾸면 문서의 현재 상태와 검증 결과도 함께 갱신합니다.
