# 주제 선정 전 공통 개발 기반 계획

작성일 **2026-09-21** · 최종 갱신 **2026-09-22** · 상태 **Plan 01 구현 완료·현재 Mac 통과, Plan 02~04 미착수**

[종합 보고서](../ai-lab-report.md) · [완료한 1~5단계 실습](../ai-lab-plan.md) · [현재 실행 명령](../commands.md)

## 목적

대회 주제가 정해지기 전에, 어떤 작은 AI 기능을 만들더라도 재사용할 수 있는 개발·검증·기록·데이터 관리 기반을 보완합니다.
1~5단계에서 이미 확인한 동작은 유지하고, 실습에서 드러난 불편과 미검증 영역을 대상으로 합니다.

이 문서의 항목은 다음 작업을 위한 계획입니다. 새 명령·옵션·파일명 제안은 아직 구현된 기능이 아닙니다.
이번 계획 작성으로 앱 설정·DB·모델·외부 서비스를 변경하지 않습니다.

| ID | 우선순위 | 작업 | 지금 필요한 이유 | 선행 조건 |
| --- | --- | --- | --- | --- |
| [01](01-environment-reproducibility.md) | 현재 Mac 완료·팀원 Mac 대기 | 개발환경 재현성과 진단 | 검증 PC의 상태와 새 팀원 PC의 상태를 구분하고 설치 실패 원인을 쉽게 찾기 | Docker 사용 가능한 Mac |

권장 순서는 **01 → 02 → 03**이며, **04는 01 이후 독립적으로 진행**할 수 있습니다.
다른 팀원 Mac을 당장 사용할 수 없어도 01의 진단과 격리된 checkout 검증, 02의 평가 형식 정리는 시작할 수 있습니다.
다른 PC 검증은 실제 결과가 확보될 때까지 완료 처리하지 않습니다.
담당자와 날짜는 팀에서 배정하며 임의의 일정이나 업무 배정을 만들지 않습니다.

## 이번에 지킬 공통 범위

- 기본 `docker compose up -d`와 CI는 Mock을 유지합니다.
- 실제 모델 실행은 사용자가 고른 로컬 실습 명령에서만 수행합니다.
- 실행 진입점은 Compose로 유지하고 Makefile이나 별도 작업 실행 도구를 추가하지 않습니다.
- 합성 데이터만 사용하고 원문·생성 결과·인증정보를 운영 로그에 남기지 않습니다.
- 기존 개발 DB와 볼륨을 지우지 않으며 복원 검증은 별도 대상에서 수행합니다.
- 설치 진단이 모델 다운로드·의존성 업데이트·DB 초기화를 자동 실행하지 않게 합니다.
- GCP 리소스 생성·과금 활성화·`release/gcp` push는 보류합니다.

## 각 계획을 완료했다고 판단하는 방법

1. 문서에 적은 완료 기준을 실제 실행이나 의미 있는 자동 테스트로 확인합니다.
2. 실행 명령, 대상 환경, 커밋, 기대 결과와 실제 결과를 기록합니다.
3. 로컬 확인·다른 PC 확인·Mock 테스트·실제 모델 측정을 구분합니다.
4. 기존 흐름에 영향이 있는 검사만 수행하고 결과를 해당 계획과 명령어 문서에 반영합니다.
5. 미검증 항목이 있으면 그 범위를 명시하고 계획 전체를 완료로 표시하지 않습니다.

## 주제 선정 후 결정할 일

도메인 테이블·최종 제품 화면·사용자 인증 방식·정답 데이터와 품질 합격선은 실제 사용 시나리오에 맞춰 정합니다.
그래프 DB·RAG·벡터 검색·다중 에이전트·작업 큐는 구체적인 요구가 생겼을 때 검토합니다.
별도의 ‘모든 주제에 대응하는 범용 플랫폼’은 이번 계획에 포함하지 않습니다.

이번 공통 작업의 완료 목표는 **팀원이 재현할 수 있고, 모델 변경의 영향을 비교하며, 실행과 데이터를 추적·복구할 수 있는 기반**입니다.
모든 AI 답변의 정확성이나 외부 서비스 운영 준비 완료를 의미하지는 않습니다.
