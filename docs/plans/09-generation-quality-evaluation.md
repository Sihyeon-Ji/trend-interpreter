# Plan 09. 추천·생성 품질 평가와 제출 데모 준비

작성일 **2026-09-28** · 상태 **진행 (1차 측정 · 사람 판정 전)** · 근거 [ADR 0002 결과와 후속 작업](../adr/0002-고도화-방안.md) · 목표일 **2026-10-15** · 선행 [Plan 07](07-meme-recommendation.md), [Plan 08](08-content-generation.md)

## 목표

검사 통과는 AI 품질의 근거가 아닙니다. 제출 전에 실제 모델로 추천과 생성 품질을 한 번 측정하고, 데모에 쓸 사례를 정합니다.

## 할 일

1. **평가 사례.** 목표 지역 5곳(한국, 일본, 대만, 태국, 인도네시아) × 제품 4종(식품, 화장품, 패션, 앱) = 20개 사례를 만듭니다. 사진은 저작권 문제가 없는 직접 촬영본이나 자유 이용 이미지만 씁니다. 별도로 로컬 Gemma가 편집한 사전·국가별 해석의 대표 사례를 고릅니다.
2. **평가 기준.**

   | 기준 | 판정 |
   | --- | --- |
   | 추천 적합도 | 상위 5개 중 제품과 어울리는 밈 수(사람 판정) |
   | 수명 타당성 | 추천 밈의 확산 단계가 근거와 맞는가 |
   | 리스크 누락 | 사람이 보기에 위험한 밈이 `none`으로 추천된 수 |
   | 뜻 정확성 | 생성 결과의 밈 사용이 사전 뜻과 맞는가 |
   | Gemma 편집 품질 | 근거에 없는 주장, 원어 표제어 훼손, 국가별 차이 오류와 사람 수정률 |
   | 바로 쓸 수 있는가 | 카피·대본을 수정 없이 쓸 수 있는가(3단계) |
   | 응답 시간 | 추천·생성 각각의 p50·최대 |

3. **실행.** 로컬 편집 단계의 Gemma와 요청 시 Gemini를 각각 실제 모델로 한 번씩 평가합니다. 결과는 Git 제외 `artifacts/`에 두고 요약 수치만 이 문서에 기록합니다. PC를 끈 상태에서도 게시본 읽기와 사용자 요청이 동작하는지 확인합니다.
4. **개선.** 가장 많이 틀린 유형 하나를 골라 규칙이나 프롬프트를 고친 뒤 같은 사례로 다시 측정합니다.
5. **데모.** 평가 사례 중 잘 된 3개를 데모 시나리오로 정하고, 제출 영상과 발표 자료의 흐름(살펴보기 → 추천받기 → 만들기)에 맞춥니다.

## 완료 기준

- 20개 사례의 평가 결과와 개선 전후 수치가 이 문서에 있습니다.
- 데모 시나리오 3개가 배포된 서비스에서 재현됩니다.
- 제출 자료에 평가 방법과 한계(측정하지 않은 것)를 적습니다.

## 1차 측정 (2026-09-29, 원작자 서버 실데이터 · 로컬 Gemma 4 · 사람 판정 전)

`apps/trend-api/scripts/eval_recommend.py`(20개 사례, `--local`). 요청 때 Gemma 검사를 없애기 **전** 구조(추천 이유·만들기 검사를 모델이
하던 때)로 쟀다. 규칙으로 잴 수 있는 것만 적는다 — 추천 적합도·리스크 누락·뜻 정확성·바로 쓸 수 있는가는 사람이 `-judge.csv` 를 채운다.

| 항목 | 값 |
| --- | --- |
| 끝까지 된 사례 | 20개 중 8 (한국 4·일본 1·대만 3) |
| 추천 0 | 태국 4·인도네시아 4 — 두 나라 카드가 2·3개뿐이고, 대부분 '주의 + 식상' 이거나 쓰임 낱말이 비어 규칙을 넘지 못했다 |
| 만들기 실패 | 4 (일본 3·대만 1) — 로컬 모델이 `thumbnail` 을 `script` 안에 넣는 모양 실수(생성 18번 중 7번) |

| 추천 28개의 리스크 | 없음 22 · 판단 보류 6 |
| 추천 28개의 생애주기 | 꾸준함 19 · 줄어드는 중 9 |

**가장 많이 틀린 유형과 고친 것(할 일 4).**

1. 만들기 실패 — 재질문에 어느 키가 틀렸는지 적고(`local_chat._problem`), 모양 실수는 `ContentDraft` 가 바로잡고, 다시 만들기가 실패해도
   통과한 안은 돌려준다. 같은 일본 사례를 10번 돌리자(재질문·통과안 유지까지 넣은 뒤) 실패가 1번이었고, 그 1번도 `thumbnail` 이 `script`
   안에 든 같은 모양이라 모양 바로잡기가 막는다 — 바로잡기를 넣은 뒤의 수치는 다음 측정에서 잰다. 요청 때 Gemma 검사는 09-28 결정으로 없앴다.
2. 근거가 딴 글 — '오살힘' 추천의 근거 링크가 한국 배우·KBS 드라마 위키백과 문서였다. 주제 단계가 검색 결과를 거르지 않고 저장해
   근거 9,738건 중 1,882건에 표제어가 없었다. 표제어가 든 근거만 쓰고·보이도록 고쳤다(`match.evidence_mentions`).
3. 한글 표기 밈을 일본 카피에 — 일본에서도 쓴다고 조사된 한글 표기 밈(럭키비키·건어물녀)은 그 말로 쓸 표기가 없으면 만들기 후보에서 뺀다(`generate.writable`).

**다음 측정.** 새 구조(요청 때 모델은 이해·생성 한 번씩, 이유는 저장된 데이터)로 요청 시 Gemini 를 한 번(`eval_recommend.py`, 요청 장부 안에서),
로컬 편집 단계 Gemma 를 한 번 잰다. 태국·인도네시아는 카드 수가 모자라 추천 품질이 아니라 자료 양을 재게 되므로, 그 두 나라의 자료가
늘기 전에는 결과를 따로 적는다.
