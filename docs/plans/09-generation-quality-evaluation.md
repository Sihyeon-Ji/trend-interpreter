# Plan 09. 추천·생성 품질 평가와 제출 데모 준비

작성일 **2026-09-28** · 상태 **대기** · 근거 [ADR 0002 결과와 후속 작업](../adr/0002-고도화-방안.md) · 목표일 **2026-10-15** · 선행 [Plan 07](07-meme-recommendation.md), [Plan 08](08-content-generation.md)

## 목표

검사 통과는 AI 품질의 근거가 아닙니다. 제출 전에 실제 모델로 추천과 생성 품질을 한 번 측정하고, 데모에 쓸 사례를 정합니다.

## 할 일

1. **평가 사례.** 목표 지역 5곳(한국, 일본, 대만, 태국, 인도네시아) × 제품 4종(식품, 화장품, 패션, 앱) = 20개 사례를 만듭니다. 사진은 저작권 문제가 없는 직접 촬영본이나 자유 이용 이미지만 씁니다. 별도로 로컬 Gemma가 편집한 사전·국가별 해석의 대표 사례를 고릅니다.
2. **평가 기준.**

   | 기준 | 판정 |
   | --- | --- |
   | 추천 적합도 | 상위 5개 중 제품과 어울리는 밈 수(사람 판정) |
   | 수명 타당성 | 추천 밈의 확산 단계가 근거와 맞는가 |
   | 리스크 누락 | 사람이 보기에 위험한 밈이 `none`으로 추천된 수 |
   | 뜻 정확성 | 생성 결과의 밈 사용이 사전 뜻과 맞는가 |
   | Gemma 편집 품질 | 근거에 없는 주장, 원어 표제어 훼손, 국가별 차이 오류와 사람 수정률 |
   | 바로 쓸 수 있는가 | 카피·대본을 수정 없이 쓸 수 있는가(3단계) |
   | 응답 시간 | 추천·생성 각각의 p50·최대 |

3. **실행.** 로컬 편집 단계의 Gemma와 요청 시 Gemini를 각각 실제 모델로 한 번씩 평가합니다. 결과는 Git 제외 `artifacts/`에 두고 요약 수치만 이 문서에 기록합니다. PC를 끈 상태에서도 게시본 읽기와 사용자 요청이 동작하는지 확인합니다.
4. **개선.** 가장 많이 틀린 유형 하나를 골라 규칙이나 프롬프트를 고친 뒤 같은 사례로 다시 측정합니다.
5. **데모.** 평가 사례 중 잘 된 3개를 데모 시나리오로 정하고, 제출 영상과 발표 자료의 흐름(살펴보기 → 추천받기 → 만들기)에 맞춥니다.

## 완료 기준

- 20개 사례의 평가 결과와 개선 전후 수치가 이 문서에 있습니다.
- 데모 시나리오 3개가 배포된 서비스에서 재현됩니다.
- 제출 자료에 평가 방법과 한계(측정하지 않은 것)를 적습니다.
