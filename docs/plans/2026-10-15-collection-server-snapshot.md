## 1. 왜 하나

10-16에 수집 서버의 최신 스냅숏(`db/latest`)으로 운영 DB를 마지막으로 새로 만든다. 그 전에 서버 파이프라인이 질 낮은 쓰임 낱말을 채우지 않게 하고, 일본 시장 후보를 보강하고, 스냅숏을 제때 올려야 한다.

## 2. 지금 상태 (10-10, 운영 DB 사본 기준)

- 쓰임 낱말(`term_fit`)이 붙은 말 7,893개 중 7,599개는 로컬 `gemma4:e4b`가 붙인 옛 값이라 `audience`(누가 알아듣나)·`kind`(밈 종류) 칸이 비어 있다. 두 칸은 10-09에 생겼다(커밋 f0959b1·e89a3a5).
- fit 단계는 두 칸이 빈 행을 다시 붙인다. 서버에서는 로컬 Gemma로 **매 실행 40개씩** 붙는다.
- 추천 후보는 이미 Gemini Flash(233개)와 사람 고정(61개, `human:지시현`)으로 붙어 있다. 10-09에 몰아 붙이기는 Gemini로 하기로 정했다(`fit_backfill.py --gemini`, 사용자 결정). 운영 갱신은 이 값을 운영 DB에서 이어 받는다(`refresh_production.carry_fits`).
- **문제:** 서버가 e4b로 채운 값은 칸이 차 있어 다시 붙지 않고, `--gemini` 몰아 붙이기도 건너뛴다. e4b는 사용층 판정이 거의 나오지 않았다(210개 중 niche 1개). 10-16 스냅숏에서 새로 추천 후보가 된 말이 이 값으로 남는다.

## 3. 할 일

1. **develop 받기.** 최신 develop을 받는다. 서버와 관련된 변경은 쓰임 낱말의 `audience`·`kind` 칸, 리스크 민감 소재 규칙 수정, 쓰임 낱말 몰아 붙이기 옵션(`--gemini`·`--batch`)이다.
2. **fit 단계 빼고 돌리기 (10-16 갱신까지).** 파이프라인을 fit 없이 돌린다.
   ```
   uv run scripts/run_pipeline.py --loop --stages collect,classify,spikes,interpret,candidates,spot,namu,trendaword,hunt,research,crosscheck,audit,track,risk,naver,translate,topics,board,dashboard
   ```
   이미 e4b로 새로 채운 행이 있으면 개수를 알려 준다.
   ```
   SELECT count(*) FROM term_fit WHERE model LIKE 'local:%' AND json::json->>'kind' IS NOT NULL;
   ```
3. **일본 후보 보강 (할 수 있으면).** 일본 뉴스·pixiv 백과·위키백과 분류에서 화장품·패션·금융·생활 분야의 지금 쓰이는 말을 더 모은다. 지금 일본 카드는 46개이고 27개가 식어 가는 말, 나머지도 대부분 엔터 분야다. 상세는 [밈 추천 남은 일 §2.1](ktwoo-meme-recommendation-remaining.md#21-빈-시장--일본-화장품러닝화가계부-한국-화장품-추천-0).
4. **스냅숏 올리기 – 10-15 밤까지.** 3을 하면 그 수집·조사가 끝난 뒤 `db/latest`를 올리고, 올린 시각(`updated_at.txt`)을 shji에게 알린다. 그 뒤 10-16 갱신까지는 올리지 않는다(갱신 중에 바뀌지 않게).

## 3-1. 10-12 수집 서버에서 한 것

- **fit 빼기.** cron 이 `run_pipeline.py --skip fit` 로 돈다(트윈 719cd9d). 10-10 뒤 fit 단계가 로컬 e4b 로 붙인 값은 46개다. 수집 서버는 트윈 저장소(SQLite)라 `term_fit` 에 `audience`·`kind` 칸이 없다 – 7,905개 모두 `local:gemma4:e4b` 이고 두 칸이 비어 있어, 갱신 때 `fit_backfill --gemini --relabel-local` 이 다시 붙일 수 있다.
- **업로드 보류.** `data/upload_hold` 파일이 있으면 하루 두 번(12:45·22:45) 자동 업로드를 건너뛴다. 10-15 밤 마지막 업로드 직후 만들고, 갱신이 끝났다는 연락을 받으면 지운다.
- **밈이 아닌 말 정리.** 로컬 판정(참고 문서가 밈으로 쓰인다고 하지 않음)과 밈 카드(개별 밈이 아님)가 둘 다 '밈 아님'인 906개와, 운영에서 사람이 뺀 Know Your Meme·relatable 을 검수 대기(needs_review)로 내렸다(확정 7,560 → 6,652). 표본 45개 중 43개가 노래·영화·게임·인물·장소였다. 운영에서 사람이 손댄 말은 덮어 얹기(overlay)가 운영 값으로 되돌린다. 스냅숏의 확정 수가 줄었으니 `compare`·12사례 재측정을 볼 때 참고한다.
- **일본어 뜻.** 일본 시장 말(뜻의 나라에 JP 가 있거나 원문이 일본어) 816개 중 791개에 로컬 Gemma 로 `translations.lang='ja'` 를 만들었다. 한글이 섞여 나온 25개는 저장하지 않았다(화면은 '翻訳なし').
- **생애주기.** 늘 모으는 원본의 모양을 다 찬 주끼리 견주게 고쳤다 – 덜 찬 이번 주 때문에 주 초에 꾸준한 말이 '지는 중'이 됐다. 10-12 기준 40여 개가 바뀌었다. 같은 수정이 이 저장소 `pipeline/track.py` 에도 들어갔다.
- **쇼츠 해석.** 10-07 부터 지워진 영상 하나(맨 앞)의 403 이 매 실행 단계를 멈췄다. 볼 수 없는 영상만 건너뛰게 고쳤다.
- **일본 후보 보강(10-12~13).** 2025~2026 일본 유행어 발표·사전·트렌드 보고서(커뮤니티 글 제외)에서 90개를 후보로 넣고 조사했다. 게이트를 통과한 15개 밖의 검수 대기 77개는 사용자 위임(10-13 "사람 승인 기다리지 말고 조사해서 올릴 만하면 올려")으로 Claude 가 말마다 서로 다른 출처 2곳 이상과 원문 문장(내려받은 쪽과 글자 대조)을 확인해 61개를 실었다.
  - 결정 기록의 이름은 `ktwoo(위임·Claude 조사 10-13)` 이다. 뜻 55개는 출처에 맞게 고친 새 판이다(초안 오류: 'M!LK' 를 'LK' 로 자른 문장 나누기 버그, 일본어 줄임말 풀이의 한글 받아쓰기, 동음이의 문서 내용, 글자 섞임).
  - 상품군·개념어·한 곳에서만 확인되는 말 15개와 차별 뿌리 논란이 있는 自認○○ 는 검수 대기에 남겼다. 지금 90개 중 74개가 확정이다.
  - 새 말은 쓰임 낱말이 없어(fit 단계 꺼짐) 갱신 때 Gemini 로 붙이고, 리스크가 비어 있으면 갱신 때 사람 판정 대상이다. 주의할 점(노래·애니 대사의 권리, 地雷系 를 사람에게 쓰면 비하, 腸活·リカバリーウェア 의 효능 표현 규제 등)은 뜻의 '쓸 때 알아 둘 점'에 적었다.
- **시나리오 리허설(10-12).** 수집 서버 DB 사본을 이 저장소의 `migrate_sqlite_to_postgres.py --fresh --skip-user-data` 로 새 PostgreSQL 에 옮기고 `refresh_production.py recompute` 를 돌린 판(사람 결정 얹기는 운영 DB 가 필요해 뺐다)에서 데모 시나리오 v3 를 장면 순서대로 돌렸다.
  - **이관이 멈췄다.** 위키에서 옮긴 조사 메모 한 줄에 NUL(0x00)이 있어 PostgreSQL 이 거부했다. 이관 스크립트가 NUL 과 JSON 의 `\u0000` 을 지우고 옮기게 고쳤고(10-16 갱신과 같은 단계), 수집 서버 업로드도 올리는 사본에서 NUL 을 지운다.
  - **재계산은 18분**(로컬 PostgreSQL, 표제어 1만 1천여 개). 위키 밈 분류로 들어온 말 3,538개는 생애주기 '모름' 이 된다 – 검색 관심도를 생애주기로 쓰지 않는 10-06 결정(Plan 02) 그대로다.
  - **첫 화면에 걸린 말을 정리했다.** 밈이 아닌 일반 낱말·기술 용어(MZ세대·멀티·Deepfake)와 10-09 번역 검토에서 원문 뜻이 틀렸다고 본 말(FAIL·ON AIR)을 검수 대기로 내렸다. 첫 화면 무대는 시장마다 제 글자로 된 말만 세운다(일본 칸에 한글 표기 건어물녀가 섰다).
  - **추천 후보의 쓰임 낱말.** 수집 서버의 쓰임 낱말은 모두 로컬 e4b 값이라 밈 종류(`kind`)·사용층(`audience`)이 비어, 리허설에서는 라떼에 줄게·あるある·Just the Way You Are 가 골렸다(노래·일반 낱말 거르기가 듣지 않음). 갱신 때 `fit_backfill --gemini --relabel-local` 이 새 추천 후보를 빠짐없이 다시 붙여야 시나리오의 고른 말이 정상이 된다.
- **표제어 읽기·뜻 번역(10-13, 사용자 결정).** 원문 곁에 화면 언어로 읽는 법을 작게 붙인다(장원영 → チャン・ウォニョン · Jang Won-young, 推し活 → 오시카쓰). 이용자에게 보이는 읽기와 영어·일본어 뜻은 모델 하나(Sonnet)로 만든다.
  - 같은 표본에서 로컬 Gemma 12B 는 읽기 40개 중 7개(가타카나), 일본어 뜻 18개 중 사실 오류 3개(平壌 → 平陽 등)·저장 실패 3개였고 Sonnet 은 0개였다.
  - 수집 서버는 cron 의 번역 단계를 빼고(`--skip fit,translate`) 파일 작업 큐로 채운다(확정 표제어 읽기 3,310개, 뜻 6,724개). 다른 글자가 섞인 것·원문 그대로인 것은 규칙이 버린다.
  - 스냅숏에 `term_readings` 표(마이그레이션 026)가 새로 들고, `translations` 의 영어·일본어 판이 `claude-sonnet-5-5` 로 바뀐다. 이관은 이 저장소 코드의 표 목록으로 옮기므로 **026 이 든 코드가 develop 에 들어간 뒤 이관해야** 읽기가 옮겨진다. 사람이 손댄 말의 뜻 번역은 덮어 얹기가 운영 값으로 되돌린다.
  - **그 뒤 새로 실리는 말은 자동(10-13 사용자 결정).** 파이프라인의 `translate`·`readings` 단계가 로컬 Gemma 4 로 만든다. 읽기는 소리를 규칙이 적고(표준 발음 근사 → 로마자 표기법·일본식 가타카나, 가나 → 외래어 표기법·헵번식) Gemma 는 외래어의 원어 표기와 한자 읽기만 정한다 – Sonnet 판과 견주어 Gemma 혼자보다 가타카나 40 → 49/80, 한글 23 → 34/40 이 같아졌고 뚜렷이 틀린 것은 160개 중 1~2개. 뜻 번역은 일본어 20개 중 19개·영어 10개 중 9개를 저장했고 틀린 곳은 모델이 모르는 이름뿐이었다. 둘 다 규칙 검사를 통과한 것만 싣는다. 있던 말의 Sonnet 판은 덮어쓰지 않는다.

## 4. 서버에서 하지 않는 것

- 쓰임 낱말 몰아 붙이기(`fit_backfill.py`)를 로컬 모델로 돌리지 않는다. 새 추천 후보는 갱신 때 shji가 Gemini로 붙인다.
- 리스크 규칙 수정은 갱신 때 규칙 단계를 다시 돌리면 반영된다.
- 운영에서 사람이 정한 것(사전에서 뺀 말, 리스크 결정, 쓰임 낱말 고정, 뜻 수정)은 갱신 때 운영 DB에서 이어 받는다.

## 5. 완료 기준

- 10-15 밤까지 `db/latest`가 올라왔고, 그 스냅숏에 fit 단계가 10-10 뒤로 붙인 e4b 값이 없다(또는 개수를 알렸다).
- 일본 보강을 했다면 보강 전후 일본 카드 수를 알렸다.
