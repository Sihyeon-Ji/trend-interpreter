작성일 **2026-10-10** · 담당 **ktwoo(김태우)** · 상태 **시작 전** · 코드 동결 **10-14** · 제출 **10-18**

[계획 목록](README.md) · 이어받은 계획 [Plan 20](archive/20-copy-check-localization-flow.md)(방향·흐름·화면 원칙, §5 일본어) · 데모 [데모 영상](sng_j-demo-video.md)(sng_j) · 수집 서버 [마지막 갱신 전 준비](2026-10-15-collection-server-snapshot.md)

두 일을 한 문서로 둔다. 같은 사람이 같은 파일(`components/stage/`, `lib/i18n.ts`)을 고치고 마감도 같다. 순서는 **A의 1·2(승인 기록, 재검사) → B(일본어) → A의 나머지**다. 화면 문구를 먼저 정해 두고 일본어로 옮기면 새 문구까지 한 번에 번역된다.

## A. 문구 검사·현지화 흐름의 남은 일

### 1. 방향 (Plan 20에서 정한 것)

제품의 중심은 **마케터가 낼 문구를 시장에 맞게 검사하고 고쳐 쓰는 흐름**이다. 트렌드·지도는 그 재료다. 시장은 한국·일본·영어권. 판정은 규칙, 문장은 모델, 근거 인용, 사람 승인을 유지한다. 흐름은 ① 넣기 → ② 검사 → ③ 제안 → ④ 시장별 고쳐 쓰기 → ⑤ 승인 → ⑥ 모르는 말 조사다. 이유와 테마·심사 근거는 [Plan 20 §2](archive/20-copy-check-localization-flow.md#2-왜-이-방향인가)에 있다.

화면은 10-08 r-stage('무대')로 바뀌었다(`apps/trend-web/components/stage/`, `app/stage.css`). Plan 20 §10의 n-redesign 원장은 `/lab/n-redesign`에만 남았고, 그 '누가 정했나' 표지는 `stage/bits.tsx`의 Actor(rule·ai·human)로 이어졌다.

### 3. 우선순위

데모 영상([데모 영상](sng_j-demo-video.md))이 쓰는 장면부터 한다.

1. **⑤ 승인 기록 서버 저장.** 영상의 '사람이 승인해야 나간다' 장면이 실제 기록이 되게 한다. 로그인한 검수자만 승인, 승인한 문구·시장·밈·시각·검수자를 저장, `/admin`에 목록. 공유 링크는 여유가 있으면.
2. **④ 재검사 범위.** 모든 카피를 다시 검사하고, 걸린 카피는 승인 버튼을 막거나 고쳐 쓰기를 제안한다.
3. **`/check`와 `/drafts` 정리.** 옛 화면을 남길지, 새 흐름으로 합칠지.
4. 여유가 있으면 ⑥, 워드 클라우드 규칙, '지도에서 보기'.

### 4. 정할 것

- 승인 권한(검수자만 / 로그인한 누구나), 공유 링크 공개 여부, 승인 기록 보존 기간.
- 첫 화면에서 문구 입력을 검사로 보낼지(Plan 20 원안), 지금처럼 모두 초안으로 보낼지.
- 포스터 생성을 켤지(비용).
- 밀린 검수 큐(Plan 20 §9, 당시 1,739건)를 정리할 규칙.

### 5. 지키는 것

- 이용자 화면에 내부 용어·모델 이름·점수를 내지 않는다(`apps/trend-api/AGENTS.md`).
- 승인 기록과 운영 로그에 이용자 문구 원문을 남기지 않는다. 저장이 필요하면 접근 통제한 표에 두고 보존 기간을 정한다.
- 디자인은 r-stage 규칙을 따른다.

### 6. 완료 기준

- 배포본에서 문구를 넣으면 검사 → 시장별 고쳐 쓰기 → 모든 카피 재검사 → 검수자 승인까지 가고, 승인 기록이 서버와 `/admin`에 남는다.
- `docker compose run --rm --build check`와 `e2e`가 통과하고, `release/gcp` 배포 뒤 운영에서 한 번 확인했다.

## B. 일본어 화면

### 1. 왜 하나

일본은 이번 대회 운영 시장(한국·일본·영어권)의 하나다. 화면 언어는 지금 한국어·영어뿐이다. 데모 영상은 영어 화면으로 찍고 일본어는 첫 장면에서 언어 전환으로 한 번 보이는 정도로 쓴다([데모 영상](sng_j-demo-video.md)).

### 2. 지금 상태 (10-12)

`feat/japanese-ui`(develop 3beaa54에서 갈라짐)에 들어갔다. 용어·문체 규칙과 확신 없는 문구 목록은 [일본어 용어집](../트렌드/일본어-용어집.md)에 있다.

| 대상 | 10-10 | 10-12 |
| --- | --- | --- |
| 화면 문구 `apps/trend-web/lib/i18n.ts` | `Locale = "ko" \| "en"`, 언어마다 약 1,080키 | `ja` 사전 1,130키(새 키 `gloss_ja_pending` 포함). 빠지면 형 검사가 잡는다 |
| 무대 화면 문구 `apps/trend-web/components/stage/copy.ts` | `{ ko, en }` 약 260키 | `ja` 284키(새 키 `tm_untranslated` 포함), 언어 이름·퍼진 정도·밈 종류·분야의 일본어 |
| 데이터 라벨 `apps/trend-web/lib/labels.ts` | ko·en | `ja` 라벨, 출처 이름, 나열 쉼표 「、」, 시각 `ja-JP`(2026/10/12 14:30) |
| 언어 전환·`<html lang>` | 한국어·EN | 머리 막대에 日本語, 쿠키 값은 `isLocale` 화이트리스트, 오류 화면도 `<html lang>` 을 읽는다 |

| API | `TermRecord.ko·en`, 카드 `gloss_ko·gloss_en` | `TermRecord.ja`, 카드·추천·카피 검사에 `gloss_ja`·`ja_pending`(원문에 가나가 없고 일본어판이 없으면 참) |

### 3. 할 일

1. ~~`Locale`에 `ja`를 더하고 `i18n.ts`·`stage/copy.ts`·`labels.ts`에 일본어 사전을 넣는다.~~ 10-12. 영어판을 바탕으로(한국어판과 뜻이 다르면 한국어판) 옮겼다. **일본어 화자 검토는 남았다** – 먼저 볼 것은 [용어집 §8](../트렌드/일본어-용어집.md#8-확신이-없는-문구)의 76개.
2. ~~언어 전환(헤더)에 日本語를 더한다. 날짜·숫자 형식을 `ja-JP`로.~~ 10-12. 로그인한 사람의 저장값(`lib/reader.ts`)에는 언어 칸이 없다 – 언어는 계정이 아니라 `locale` 쿠키 하나에 있고, 그 화이트리스트(`i18n.isLocale`)에 `ja` 를 넣었다.
3. 뜻 번역: ~~`translate.py`에 `ja`를 더한다.~~ 10-12, 데이터가 들어올 길만 열었다. **번역 데이터 만들기는 남았다** – 수집 서버가 `USE_LOCAL_GEMMA=1`로 파이프라인을 돌리면 translate 단계가 영어·한국어 다음에 일본어판을 만든다(실행마다 12개 한도 공유). 운영 반영은 승인 배치 게시(`export-translations` → 생산자 `TRANSLATE_TARGET=ja` → `pack-translations --lang ja` → 승인 → 게시)로 한다. 대상은 데모에 나오는 말 → 일본에서 살아 있는 말 순서.
4. ~~사전 항목에 일본어 뜻이 없으면 원문 뜻과 '번역 없음' 안내를 보인다.~~ 10-12. 사전 항목은 원문 뜻 위에 「翻訳なし：日本語訳がまだないため、原文の意味を表示しています。」, 목록 카드는 영어 화면처럼 원문 대신 「翻訳なし（日本語の説明は準備中）」. 원문 뜻이 이미 일본어(가나)면 안내하지 않는다.
5. ~~e2e에 일본어 전환 한 장면을 더한다.~~ 10-12, `e2e/japanese.spec.ts`(첫 화면 → 日本語 → 초안·둘러보기·사전 항목, 번역 있는 말과 없는 말).

검증(10-12, 로컬): API pytest 518 통과·1 실패(`test_track_does_not_trust_mentions_of_a_word_mostly_used_in_another_sense` – 오늘 날짜에 따라 갈리는 시험으로, 손대기 전 develop에서도 같게 실패), 웹 단위 38·lint·production build 통과, e2e 48 통과(새 일본어 장면 포함). 일본어 화면을 1440·390 폭으로 찍어 넘침·잘림을 고쳤다(용어집 §7). 도커 check·e2e 이미지는 이 서버에서 돌리지 않았다(도커가 SSH를 끊는다). 실제 Gemini는 부르지 않았다.

**남은 일**

- 일본어 화자 검토(§4의 정할 것) – 용어집 §8 목록부터.
- 일본어 뜻 번역 데이터 – 위 3의 길로. 데모에 나오는 일본 시장 말은 사람 확인 뒤 게시.
- 화면 언어로 모델이 쓰는 글(카피 설명·제품 요약·사전에 묻기의 답·'やさしく言い換えると'·카피 검사 의견)은 일본어 화면에서 영어로 나온다. 일본어로 쓰려면 `generate`·`recommend`·`ask`·`explain`·`copycheck` 의 프롬프트와 화면 언어 검사(`generate.in_ui_language`)에 `ja` 를 넣고 실제 모델로 확인해야 한다.
- 승인 기능(A의 1, 다른 브랜치)이 ko·en에만 더한 키는 합칠 때 일본어를 채운다 – 비면 형 검사가 잡는다.
- 배포본 확인(§5 완료 기준)은 `release/gcp` 배포 뒤.
- 알게 된 것(고치지 않음): 프론트 `lib/explain.ts` 의 `termPattern` 경계가 유니코드 글자(`\p{L}`)라서 일본어 문장 속 일본어 밈(예: 「週末は推し活で」의 推し活)을 찾지 못한다. 백엔드 `match.term_pattern` 은 ASCII 경계라 찾는다 – 메시지 해석에서 서버가 찾은 말을 화면이 다시 걸러 낸다.

### 4. 정할 것

- 일본어 화자 검토를 누가 하나.
- 뜻 번역을 데모 말만 할지, 일본에서 살아 있는 말 전체(약 46개 카드)까지 할지.

### 5. 완료 기준

- 배포본에서 日本語를 고르면 첫 화면·초안·둘러보기·사전 항목·검수 화면이 일본어로 나오고, 빠진 키가 없다.
- 데모에 나오는 일본 시장 말의 일본어 뜻이 사람 확인을 거쳐 운영에 게시됐다.
- `check`·`e2e` 통과, `release/gcp` 배포 뒤 운영에서 확인.
