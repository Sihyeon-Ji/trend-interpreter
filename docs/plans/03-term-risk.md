# Plan 03. 용어별 리스크 필드와 근거 기반 판정

작성일 **2026-09-28** · 상태 **대기** · 근거 [ADR 0002 §2](../adr/0002-고도화-방안.md) · 목표일 **2026-10-04** · 선행 [Plan 02](02-lifecycle-stages.md)

## 목표

마케터가 밈을 쓰기 전에 "브랜드 공식 계정 사용 주의" 같은 경고를 받게 합니다. 경고는 근거에서 나와야 하고, LLM이 혼자 "안전함"을 붙이면 안 됩니다.

## 재료

| 재료 | 위치 |
| --- | --- |
| 영상 해석의 `risk_flags`(조롱, 정치, 비하 기원 등) | `interpretations` 표 |
| 뉘앙스·주의점 서술 | `meanings.json`의 `nuance` |
| 근거 문장 | `evidences.excerpt` |
| 검수자 결정 | `review_queue` |

## 할 일

1. **스키마.** 용어에 `risk_level`(`none`·`caution`·`avoid`), `risk_reasons`(목록), `risk_checked_at`을 추가합니다(마이그레이션).
2. **근거 문장 분류.** 파이프라인에 `risk` 단계를 추가해, 용어별 최근 근거 문장을 Gemma로 분류합니다. 결과는 문장마다 `positive·neutral·negative`와 위험 유형(혐오·조롱·성별 갈등·정치·선정성·없음)입니다. 이 분류는 Plan 04의 긍정·부정 뉘앙스에도 씁니다.
3. **규칙 판정.** 코드가 다음 규칙으로 수준을 정합니다.

   | 수준 | 규칙 |
   | --- | --- |
   | 사용 자제 (`avoid`) | 위험 유형이 붙은 근거가 3건 이상, 또는 영상 `risk_flags`에 비하·혐오 기원, 또는 검수자가 제외 |
   | 주의 (`caution`) | 부정 근거 비율이 30% 이상, 또는 위험 유형 근거가 1~2건, 또는 확산 단계가 `fading` |
   | 없음 (`none`) | 위 조건에 해당하지 않고 근거가 5건 이상 |
   | 판단 보류 | 근거가 5건 미만. 화면에 "근거 부족"으로 표시 |

4. **이유 서술.** 이유는 해당 근거 문장을 인용하는 템플릿으로 만듭니다. 근거 링크를 함께 돌려줍니다.
5. **검수 화면.** 관리자 화면(`/admin`)에서 리스크 수준을 사람이 바꿀 수 있게 하고, 사람의 결정이 규칙보다 우선합니다.

## 완료 기준

- 검증 용어 전체에 리스크 수준 또는 판단 보류가 붙어 있습니다.
- 규칙마다 테스트가 있고, 표본 20개를 사람이 검토한 일치율을 이 문서에 기록합니다.
- 기본 개발 환경(모델 호출 없음)에서는 분류 단계가 건너뛰어지고 기존 판정이 유지됩니다.
