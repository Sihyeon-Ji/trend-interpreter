## 감사 실패 재시도 후속 구현

같은 뜻 판의 `error`는 1시간, `no_doc`는 7일 뒤 자동 감사 대상으로 돌아간다. 완료된 `ok`·`flagged`·`rewritten`은 자동으로 다시 돌리지 않는다. 처음 보는 뜻을 먼저 처리하고 재시도는 회차의 기존 한도 안에서 수행한다. 사람이 승인한 뜻·제외한 말·사람이 검수 중인 수정 제안은 선택과 실행 직전 모두 보호한다.

문서 접근이나 모델 형식 실패도 감사 기록에 남아 반복 호출을 막으며, 실패 기록에는 예외 유형만 남긴다. 운영 출력은 표제어 대신 내부 ID와 처리 결과를 쓴다. 장애 해소 뒤 즉시 재검사할 때는 `apps/trend-api`에서 `uv run scripts/audit_daemon.py --retry-failures --once`를 사용한다. 이 경로는 실패 건만 최대 20개 처리하고 종료하며, 실제 모델 실행 환경에서만 담당자가 실행한다. 이번 구현 검증은 합성 자료와 가짜 모델로 수행하며 운영 DB 감사나 유료 호출을 실행하지 않는다. `docker compose run --rm --build check`가 종료 코드 0으로 통과했다(API 410개, 신규 재시도/CLI 검사 6개 포함; 웹 단위 21개·lint·production build 통과).

## 2026-10-06 재점검

성향 CLI 기본 연결을 `db.connect_read_only()`로 바꾸고 `--sqlite`·`--out`을 추가했다. PostgreSQL은 DDL·마이그레이션 없이 쓰기 거부·REPEATABLE READ로 분석한다. 동일 합성 자료의 SQLite/PostgreSQL 집계 비교, 쓰기 거부·빈 사본 검사를 추가했다. 조회수 최고 연도는 조회 관심으로 표시한다. 실제 운영 자료 재집계·분류 최종 처리·뜻 품질 검수는 아직 남는다.

최신 계획별 판정과 우선순위는 [10-06 재점검](구현-완료도-실측-점검-2026-10-06.md)을 따른다. 아래 날짜별 기록은 당시 범위로 보존한다.

## 남은 일

1. 나무위키 분류 4,902행의 최종 처리 결과를 용어 중복 제거 기준으로 정리한다. 고정 사본의 조사 중 29개와 전체 실패(`catalog_failed`) 189행은 원인·출처별로 확인하고, 재실행 뒤 실린 수·나라별 수·검수 대기 사유를 기록한다.
2. **위키에서 온 날짜로 생애주기 보강.** 위키에서 들어온 말은 언급 기록이 없어 생애주기가 unknown 이고 리스크가 '판단 보류' 로 남는다([Plan 09](09-generation-quality-evaluation.md) 3차: 추천 60개 중 unknown 48·보류 51).
   Trend A Word 호 날짜, 나무위키 수정 시각, 위키데이터 연도, 위키백과 월별 페이지뷰로 규칙이 시기를 정한다([Plan 15](15-overseas-generation-signals.md)).
3. 현재 verified 뜻의 감사 '사람 확인 표시'(flagged) 3,093개를 우선순위·검수 결과와 연결한다. 과거 17개는 당시 수치이며, 모델 제안만으로 자동 제외하지 않는다. error·no_doc의 같은 뜻 판 재시도 경로도 보완한다.
4. **시기 보강(위키백과).** 나무위키 연도 분류는 459개뿐이고 대부분 2020년대다.
   나무위키 문서 역사(`/history/`)는 robots.txt 가 허용하지만 화면을 스크립트로 그려 날짜를 읽을 수 없었다.
   대신 위키백과 월별 페이지뷰(2015~, 공식 API)로 '가장 많이 본 달' 을 뜬 시기로 쓴다. 조사가 위키백과 문서를 찾은 말만 해당한다.
5. 성향 분석 첫 결과를 이 문서와 관리 화면(또는 API)에 싣는다. 판정은 규칙(비율 차)이고 모델은 서술만 한다.
6. 위키백과 밈 분류(`collectors/wiki_memes.py`, ko·en·ja·id·zh)도 같은 길로 넣는다.
