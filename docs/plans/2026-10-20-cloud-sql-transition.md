`trend-project`는 무료 체험 인스턴스다(종료 예상 10-29경). 만료 전에 업그레이드하지 않으면 요청 처리를 멈춘다. 자동 유료 전환 설정은 없고 콘솔의 **지금 업그레이드**로 사람이 실행한다. 비용 비교와 대안은 [옛 Plan 13](archive/13-cloud-sql-trial-to-paid-transition.md#비용과-서비스-연속성-비교)에 있다.

## 10-10 확인

- 인스턴스 `trend-project`: PostgreSQL 18, Enterprise Plus `db-perf-optimized-N-8`, SSD 100GB(자동 증가 꺼짐), 단일 영역, 백업 꺼짐, 삭제 보호 꺼짐. 생성 09-29 – 체험 30일이면 10-29경 끝난다. **API에는 체험 만료 시각이 나오지 않는다.** 콘솔의 인스턴스 화면에서 정확한 시각을 확인해 여기에 적는다.
- DB 크기: `trend_20261009`(운영) 404MB, `trend_20261005` 323MB, `trend` 283MB. 셋을 합쳐도 1GB가 안 된다. 연결은 16개(최대 800).
- 실제 사용량에 비해 사양이 매우 크다(체험용 기본값). 유료 전환보다 작은 인스턴스(공유 코어 소형·월 상한 약 $30, [Plan 17 실행 기록](archive/17-hybrid-infrastructure-실행기록.md)의 사용자 결정)로 옮기는 쪽이 맞다. 옮길 때 지금 운영 DB 하나만 옮기고, 이전 DB들은 `pg_dump` 사본을 Git 밖에 둔 뒤 지운다.

## 절차

1. 10-20~22: 콘솔의 정확한 만료 시각, DB 크기·연결 수·부하를 확인하고 견적을 다시 만든다.
2. 10-24까지: 월 비용 상한과 경로(유료 전환 또는 작은 인스턴스로 이전)를 정한다. `pg_dump` 사본을 Git 밖에 두고 복원을 확인한다.
3. 10-26까지: 실행하고 API·웹·DB 연결, 게시·백업 Job을 확인한다. 새 인스턴스로 옮기면 [10-16 운영 DB 갱신](2026-10-16-final-db-refresh.md)의 전환 절차와 게시 역할 준비를 그대로 거친다.

만료 전 전환을 확인할 때까지 종료 알림을 일정에서 지우지 않는다. 미리 할 수 있는 것: 콘솔의 정확한 만료 시각 확인은 지금도 된다.
