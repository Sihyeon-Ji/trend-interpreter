# 배포 시간 단축 제안

작성일 **2026-10-06** · 상태 **제안 – 팀 검토 전, 워크플로는 바꾸지 않았다** · 관련 [배포·복구](배포-복구.md) · [GCP 운영](GCP-운영.md)

`release/gcp`에 push한 뒤 운영에 반영되기까지 보통 6~9분이 걸린다. 어디서 시간이 드는지 실측하고, 줄일 수 있는 방법을 효과가 큰 순서로 적는다.

## 실측

최근 `Release GCP` 실행 7번의 job 시간이다. 시각은 GitHub Actions 기록, 단계 안의 시간은 job 로그의 타임스탬프로 쟀다.

순서는 `scope`(약 10초) → 검사 5개와 `trend_images`를 동시에 → 둘 다 끝나면 `trend_app`이다. 시간을 정하는 것은 **가장 늦은 검사 + `trend_app`**이다.

| job | 단계 | 시간 |
| --- | --- | --- |

**검사 job 시간의 절반가량이 캐시 없는 이미지 빌드다.** `trend_images`와 `checks / images`는 `type=gha` 캐시를 쓰지만, `docker compose run --build check`와 e2e 빌드는 매번 처음부터 만든다.

## 방법

| 안 | 내용 | 예상 효과 | 비용·위험 |
| --- | --- | --- | --- |
| **A. 검사 이미지 캐시** | `check`·`e2e` 빌드에 `trend_images`와 같은 GitHub Actions 캐시(`type=gha`)를 쓴다. `docker buildx bake` 또는 compose `build.cache_from`/`cache_to`와 runtime 토큰 노출 action이 필요하다 | 검사 job 4분 안팎 → 2분 30초 안팎(추정). 전체 6분 → 4분 30초 안팎 | 캐시가 오래되면 검사가 낡은 의존성으로 돌 수 있다. 잠금 파일이 바뀌면 그 층부터 새로 빌드되므로 위험은 작다 |
| **B. develop에서 미리 검사하고 결과 재사용** | `develop` push에도 CI를 돌리고, `release/gcp`의 `checks`는 같은 커밋 SHA의 CI가 성공했으면 건너뛴다 | 검사가 빠지면 `trend_images`(1~4분)가 가장 늦다. 전체 6분 → 4분 안팎 | runner 사용량이 늘어난다. SHA가 정확히 같을 때만 건너뛰어야 하고, 판정 코드가 틀리면 검사 없이 배포된다. 검사·배포 경계를 바꾸므로 팀 합의가 필요하다 |
| **C. API·웹 동시 배포** | `deploy-trend.sh`에서 두 서비스를 동시에 배포한다 | 30~40초 | 웹 새 판이 API 새 판보다 먼저 트래픽을 받을 수 있다. 지금 순서가 의도인지 먼저 확인해야 한다 |
| **D. runner 대기** | 대기 자체는 GitHub 쪽 사정이다. 동시에 여러 번 push하지 않는 것 말고는 손댈 곳이 적다 | – | – |

**A를 먼저 권한다.** 배포 경계와 검사 내용을 그대로 두고 빌드만 빨라진다. 그 뒤에도 느리면 B를 검토한다. A와 B를 함께 해도 `trend_images`가 남아 4분 안쪽으로 내려가기는 어렵다.

이미지 빌드를 `develop`에서 미리 해 두고 release가 그 digest를 쓰면 `trend_images`도 뺄 수 있다. 다만 `develop`에 Artifact Registry 쓰기 권한(WIF)을 줘야 하므로 이 제안에 넣지 않았다.

## force push 뒤 전체 범위

`scripts/release_scope.py`는 직전 `release/gcp` 커밋과 새 커밋의 차이로 범위를 정한다. 10-06에 커밋 메시지를 고치려고 force push했을 때는 직전 커밋(`e345202`)이 어느 브랜치에도 남지 않아 runner가 받아 오지 못했다. 이때 차이를 구할 수 없으니 전체(`full`·`infra`·`app`·`relay`)로 잡는다. 코드상 그렇게 동작하며, 실행 37395937157에서 인프라 검사와 알림 중계기 배포가 돈 것과 맞다. 안전한 쪽으로 넓게 잡는 것이라 고칠 대상은 아니다.

## 정할 것

- [ ] A 적용 여부와 담당
- [ ] B를 할지. 한다면 `develop` CI의 runner 사용량 허용 범위
- [ ] C: API→웹 순서가 의도인지 확인
