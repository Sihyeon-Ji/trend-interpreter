이는 패턴 검사 결과이지 비밀정보 부재의 절대적인 증명이 아닙니다. 공개 직전에 새 commit을 포함한 전체 이력을 다시 검사하고, GitHub secret·GCP 키·사용자 원문이 들어간 이력이 없는지 최종 확인합니다. 경고를 무시하도록 전역 예외를 추가하지 않았습니다.

검사를 다시 실행할 때는 결과에 비밀값이 포함될 수 있으므로 보고서를 저장소에 만들거나 원문을 공유하지 않습니다. `gitleaks git --log-opts='--all' --redact=100`으로 시작하고 발견 항목은 비공개로 확인합니다.

**컨테이너로 검사할 때 주의(10-06).** 로컬 `.git/config`의 노트북 diff(`diff.ipynb.textconv`)가 개발 PC의 `.venv` 경로를 가리켜, 컨테이너에서는 오래된 커밋의 diff가 실패하고 gitleaks가 오류 없이 일부만 검사한다(10-06 첫 실행은 368개 중 185개). 검사할 때만 그 설정을 `cat`으로 바꾸고, 끝난 뒤 `commits scanned`가 `git log --all --no-merges` 중 줄이 더해진 커밋 수와 비슷한지 확인합니다.

```bash
docker run --rm -u "$(id -u):$(id -g)" \
  -e GIT_CONFIG_COUNT=2 \
  -e GIT_CONFIG_KEY_0=diff.ipynb.textconv -e GIT_CONFIG_VALUE_0=cat \
  -e GIT_CONFIG_KEY_1=filter.nbstripout.clean -e GIT_CONFIG_VALUE_1=cat \
  -v "$PWD":/repo ghcr.io/gitleaks/gitleaks:v8.30.1 \
  git /repo --log-opts="--all" --redact=100 --no-banner
```
