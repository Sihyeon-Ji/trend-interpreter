# 방향성 — 세대·문화 간 트렌드 통역 에이전트

> AI Builder Cup 2026 · Media, Content & Digital Experiences · 갱신 2026-09-14 오후 · 상태: **엔진 로컬 검증 완료(수집·해석·사전 계층), 프론트 보류**

## 한 줄

에이전트 팀이 JAPAC 각국의 쇼츠·뉴스·검색 데이터를 상시 수집하고, Gemini 가 쇼츠를 **직접 보고** 유행어·밈을 해석한다. 리서치·검증 에이전트가 그 결과를 **버전 이력이 있는 검증된 사전(지식 그래프)** 으로 쌓고 생애주기를 추적한다. 사용자에게는 검증된 항목만 근거와 함께 "이 표현이 어느 세대·어느 나라에서 어떻게 읽히는가"로 통역한다.

## 원안 대비 무엇을 바꿨나

| 원안 | 문제 | 조정 |
|---|---|---|
| 대시보드 + 설명 챗봇 + 대화 브리핑 + 카피 세대 감지 (제품 4개) | 5주에 4개는 전부 얕아짐. UX 는 10점뿐 | **엔진 하나를 깊게.** 앞문은 나중에 하나만 |
| 결과가 "이해·설명"에서 끝남 | 심사단이 반복 지적한 "조회·요약 챗봇" | 앞문 1순위를 **카피·공지 세대 감지 → 리라이트 → 승인 → 발행** 으로. 실행·승인·연동이 생김 |
| "축적된 데이터 기반" (해석 로그를 쌓는다는 뜻) | 로그는 자산이 아니다. 트렌드는 빨리 바뀌고 뜻도 변한다 | **검증된 사전**으로 승격. 버전 이력 + 생애주기 + 재검증 주기 + 사람 검수 큐. 에이전트가 사전을 돌본다 |
| "실시간" | 수집은 배치가 현실적 | 수집 6시간 주기, 리서치는 생애주기별(2~60일), 판정 단계만 실시간 |

앞문(B2B 카피 체커 vs B2C 메시지 통역)은 **아직 확정하지 않는다.** 사전이 어느 쪽이든 그대로 쓰이므로 사전을 먼저 채우고 데모가 더 잘 터지는 쪽을 고른다. 기울기는 B2B (정량 임팩트, 실행 단계).

## 시스템 구조

```

  네이버 데이터랩 (연령대별 곡선)     │                          │
  GDELT (BigQuery 공개 데이터셋)     ─┘                          ▼
                                            분류 에이전트 (Gemma 4, 로컬/엣지) · 태깅 · 중복 제거 · 쿼터 절약
                                                                  │ 신규 쇼츠만
                                                                  ▼
                                            해석 에이전트 (Gemini 3.8 Flash, YouTube URL 직접) → memes[] · 세대 · 리스크

[사전을 돌보는 에이전트 4개]                                        ▼
  ① 발견   해석 memes[] · 뉴스 · 데이터랩 급상승 → 후보 Term (정규화·임베딩 대조)
  ② 리서치 Gemini + Google Search grounding → MeaningDraft + 출처 URL + 우리 1차 근거
  ③ 검증   규칙 게이트: 독립출처≥2 · 1차근거≥1 · 자기확신≥0.5 · 무충돌 → verified_auto / 아니면 사람 검수 큐
  ④ 추적   주간 언급수 → 생애주기(규칙) → 재검증 주기 · 의미 변화 감지 → 새 version, 이전 version 닫기
                                                                  ▼
                              사전 지식 그래프 · Spanner Graph (GQL · 벡터 검색)
                              Term ─HAS_MEANING→ Meaning(v1,v2…) ─SUPPORTED_BY→ Evidence(short·news·datalab·web)
                              Term ─VARIANT_OF→ Term · Term ─USED_BY(first_seen)→ Segment(세대×국가)
                              시계열 · BigQuery (조회수 스냅샷 · 데이터랩 · 뉴스 언급 · GDELT · eval)
                                                                  │
        ┌─────────────────────────────────────┼─────────────────────────────────────┐
        ▼                                     ▼                                     ▼
 [앞문 A · B2B]                        [앞문 B · B2C]                          [근거 뷰]
 카피·공지 → 세대 판정 → 리스크 플래그    메시지 붙여넣기 → verified 뜻·출처·뉘앙스   Term 별 생애주기 곡선 · 확산 경로 · 버전 이력
```

## 저장소 결정

**Spanner Graph(사전) + BigQuery(시계열·GDELT). Neo4j 는 쓰지 않는다.** 비교표와 이유는 `docs/research/04`. 요지: 순수 Google 스택, 90일 무료 체험이 Graph·벡터 포함으로 파이널까지 커버, Google 공식 GraphRAG 참조 아키텍처(Agent Platform + Spanner Graph + Cloud Run) 를 그대로 따를 수 있음, 에뮬레이터로 로컬 실측 완료. 폴백은 Firestore(같은 논리 스키마). 참고 아키텍처(MCTI, Neo4j)에서는 설계 원칙과 실패 교훈만 이식.

## 오픈 이슈

- 요청당 영상 10개 배치의 해석 품질 (기본 3, 실측 후 결정).
- 세대 라벨(10s/20s/30s/40s/50s+)의 국가별 적합성 — 일본·동남아는 라벨 매핑 필요. Segment 를 세대×국가로 둔 이유.
- 후보 용어 정규화: 띄어쓰기·활용형(자만추/자만추하다/자만추러) → VARIANT_OF. 임베딩 유사도 임계값은 실데이터로.
- 검증 게이트의 "독립 출처" 정의: 같은 기사 인용 재배포를 독립으로 볼 것인가 → 도메인 + 본문 유사도로.
- Spanner 에뮬레이터는 인메모리이고 GQL 내부 ORDER BY 를 무시한다. 정렬이 필요한 질의는 `GRAPH_TABLE(...)` SQL 래핑으로 (클라우드 인스턴스에서 GQL ORDER BY 재확인).
- 저작권: 영상 URL 참조만. 개인정보: 앞문 B 입력은 로컬 마스킹. 덱 한 페이지씩.
