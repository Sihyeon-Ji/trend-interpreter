# 챌린지 대조 — 문제 설명 · 솔루션 방향 · 기반 기술

챌린지 원문 각 항목에 **우리가 해결하려는 문제**와 **지금 구현된 것**을 붙였습니다.
구현 상태는 2026-09-21 기준 실측이고, 아직 없는 것은 없다고 적었습니다.

---

## 1. 문제 설명

> **챌린지:** 개인과 조직이 **지식에 접근**하고, **협업**하고, **의사 결정**을 내리고,
> **일상 업무를 완료**하는 방식을 혁신하는 AI 기반 솔루션을 구축하십시오. 솔루션은
> **생산성, 효율성, 지식 접근성 또는 워크플로 실행** 측면에서 의미 있는 개선을 보여주어야
> 합니다.

### 우리가 해결하려는 문제

**업무를 하는 시간보다 업무를 관리하는 시간이 더 드는 구간이 있습니다.**

프로젝트의 진짜 상태는 네 군데에 흩어져 있습니다 — Jira 에 상태, GitHub 에 실제로
일어난 일, 달력에 시간이 어디로 갔는지, Notion 에 무엇이 결정됐는지. **어느 하나도 혼자서는
"이거 왜 멈췄나요?"에 답하지 못합니다.** 그래서 PM 은 네 개를 열어 놓고 손으로 맞춰 보고,
그래도 모르면 스탠드업에서 묻습니다.

더 정확히는, 이 조율 업무의 **존재 이유가 보고**입니다. 티켓 상태를 갱신하고, 회의 결정을
보드에 반영하고, 새 일이 들어오면 등록하고, 끝나면 완료 처리하는 일 — 이건 **관리자와
임원이 보기 위해** 하는 일이지 만드는 사람이 필요해서 하는 일이 아닙니다. 그래서
**자동화되어야 할 영역**입니다.

### 네 축에 대응

| 챌린지 축 | 우리가 하는 것 | 상태 |
|---|---|---|
| **지식 접근** | Jira·GitHub·Outlook·Notion 을 한 답으로 합치고, **티켓 키 없이** 회의록 문장과 커밋을 작업에 연결. 특이사항 레지스터가 "그때 그 이슈"를 기억 | 구현됨 |
| **협업** | 이슈가 생기면 **의존 그래프를 걸어** 알아야 할 사람을 짚고 초안까지 작성. 보내는 건 사람 | 구현됨 |
| **의사 결정** | "왜 멈췄나"에 네 도구를 합쳐 답하고, **설명 못 한 몫을 명시**. 옮기면 며칠 당겨지는지 계산 | 구현됨 |
| **일상 업무 완료** | 회의록·메모·음성 → 보드 수정안. **보드와 다른 것만** 제안 | 구현됨 |

### 개선을 어떻게 보이는가

| | 측정값 |
|---|---|
| **생산성** | 조율 업무 자동화 — 회의록 20건이 제안 20건이 아니라 **보통 2건**. 그 2건을 손으로 찾는 게 번거로운 부분 |
| **효율성** | 사람은 **에이전트의 판단만 승인**. 제안은 전부 `applied:false` 로 나오고 체크한 것만 반영 |
| **지식 접근성** | 커밋↔작업 연결 **precision 1.00 / recall 0.85** (8개 날짜, 약 490커밋, 오답 0건) |
| **워크플로 실행** | 의존성만 보면 10/13, 사람 제약까지 넣으면 **11/09 — 19영업일 차이**. 대부분의 도구가 앞 숫자에서 멈춤 |

### 차별점 — 안 하는 것으로 정의됩니다

- **모델은 숫자를 만들지 않습니다.** 모든 날짜와 일수는 `schedule.py`/`capacity.py` 에서
  나옵니다. 모델은 읽고 고를 뿐입니다
- **설명 못 한 몫을 채우지 않습니다.** "13일 중 3.5일만 설명됨, 나머지 9.5일은 안 됨"
- **"안 왔다"와 "안 보인다"를 구분합니다.** 다른 곳에 흔적이 있는 날과 어디에도 없는 날은
  다른 문제고, 후자는 이유가 아니라 **사각지대**입니다
- **쓰기 경로가 하나뿐이고 모델이 닿지 못합니다.** 저장소·달력·회의록 어댑터에는 쓰는
  메서드가 **아예 없습니다**

## 2. 솔루션 방향

> **챌린지:** 기업 지식 도우미, AI 기반 조종사, 문서 인텔리전스, **회의 인텔리전스**,
> **워크플로 자동화**, 연구 도우미, 지능형 검색

| 제안 방향 | 우리 구현 | 상태 |
|---|---|---|
| **회의 인텔리전스** | 회의록(Notion)·메모·손글씨 사진·**음성 파일** → 보드 수정안. 음성은 전사를 근거로 남기고, 못 알아들은 구간의 주장은 질문으로 강등 | **구현됨** |
| **워크플로 자동화** | 회의록↔보드 대조, 특이사항 추적, 알림 대상 산출, 리포트 발행. 전부 **큐에 쌓을 뿐 실행하지 않음** | **구현됨** |
| **문서 인텔리전스** | 손글씨·PDF 멀티모달 판독. 리포트를 docx/pptx/xlsx 로 발행 | 구현됨 (손글씨는 합성 이미지로만 검증) |
| **기업 지식 도우미** | 특이사항 레지스터가 무엇이 언제부터 누구에게 영향을 줬는지 기억. 같은 원인의 반복을 집계 | 구현됨 |
| **AI 기반 조종사** | 모델이 도구를 골라 부르고 설명. 다만 **숫자는 만들지 않음** | 구현됨 |
| 지능형 검색 | 과거 특이사항 검색 | **미구현** (Vertex AI Search 후보) |
| 연구 도우미 | — | 해당 없음 |

### 우리가 택한 방향, 한 문장

> **번거롭고 까다로운 업무 관리 작업을 대신하되, 판단은 사람에게 남기는 에이전트.**

선정 기준은 하나였습니다 — *사람이 지금 무엇을 하고 있는가.*

| 에이전트가 하는 일 | 사람이 지금 하는 일 |
|---|---|
| 회의록 ↔ 보드 대조 | 회의록 읽고 티켓 짚고 보드 열어 비교 |
| 음성 → 수정안 | 30분 회의 다시 듣고 결정만 추려 옮기기 |
| 특이사항 기억 | "그때 그 이슈 어떻게 됐더라" 찾다 못 찾기 |
| 알림 대상 산출 | 의존 그래프를 머리로 훑다 빠뜨리기 |
| 임원 롤업 | 프로젝트 5개 취합해 한 장 만들기, 매주 |
| 리포트 3종 발행 | 같은 내용을 형식만 바꿔 세 번 만들기 |

## 3. 기반 기술

> **챌린지 권장:** Gemini on Vertex AI, Vertex AI Search/Agent Search, Document AI,
> Vertex AI Agent Engine 및 ADK, Cloud Run, BigQuery, AlloyDB 또는 Firestore

| 권장 기술 | 우리 상태 | 비고 |
|---|---|---|
| **Gemini** | **사용 중** | 함수 호출 · JSON 모드 · 멀티모달(이미지/PDF/오디오). `gemini-3.6-flash`, 폴백 `3.5-flash` |
| **Gemini on Vertex AI** | **코드 경로 있음, 실호출 미검증** | `GEMINI_BACKEND=vertex` + ADC. 지금은 AI Studio API. 팀의 GCP 프로젝트(`stunning-crane-508614-c1`, 도쿄)에 Cloud Run 실배포가 이미 있어 옮길 자리는 준비됨 |
| **Cloud Run** | **Dockerfile 준비됨, 미배포** | 팀이 Terraform 25개 리소스 + Workload Identity + 배포 파이프라인 구축 완료 |
| **Firestore** | **미사용** | 특이사항 레지스터가 지금 JSON 파일. 세션 간 지속이 필요한 첫 기능이라 여기가 다음 자리 |
| **BigQuery** | **미사용** | 프로젝트 롤업 집계. 지금은 프로젝트 2개라 계산으로 충분 |
| **Document AI** | **미사용** | 지금은 Gemini 멀티모달이 PDF·손글씨를 직접 처리 |
| **Vertex AI Search** | **미사용** | 과거 특이사항 검색의 후보 |
| **Agent Engine / ADK** | **미사용** | 자체 함수 호출 레이어(`tools.py`)로 구현 |

### 현재 스택 (실제로 돌고 있는 것)

| 계층 | 기술 | 의도 |
|---|---|---|
| 프론트엔드 | 순수 HTML/CSS/JS | **프레임워크·CDN 없음** |
| 백엔드 | FastAPI · uvicorn · Pydantic | Python 3.12 |
| AI | Gemini | 함수 호출 · JSON 스키마 · 멀티모달 |
| **계산** | **표준 라이브러리만** | CPM·용량·연결·원인. **의존성 0** |
| 문서 출력 | python-docx · python-pptx · openpyxl | 선택적. 없으면 그렇다고 말함 |
| 데이터 | JSON 파일 | Firestore 가 다음 자리 |
| 품질 | pytest · ruff · mypy | **641 테스트, 네트워크 없음** |

**계산 계층에 의존성이 없는 건 의도입니다.** 이 프로젝트의 주장이 *"모든 숫자가
`schedule.py` 에서 나왔다"* 인데, 그걸 읽는 사람이 확인할 수 있어야 하니까요. 프론트엔드에
프레임워크가 없는 것도 같은 이유입니다.

### 정직하게 적어야 할 것

- **Vertex AI 는 코드가 있을 뿐 실호출로 검증된 적이 없습니다.** 있는 것처럼 쓰면 안 됩니다
- **Outlook 달력은 구조만 있고 실계정 미검증**입니다 (Azure 앱 등록 필요)
- **손글씨는 합성 이미지로만 검증**했습니다
- **Notion 은 실연결됐지만** 그 데이터베이스를 이 에이전트가 직접 만들었습니다. 남이 만든
  워크스페이스는 더 지저분할 겁니다

설명 못 한 일수를 지어내지 않기 — 전부 *하지 않는 것*을 검사합니다.
