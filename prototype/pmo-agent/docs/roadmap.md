# 기능 정의 검토 – 지금 있는 것, 비는 것, 무엇을 더할지

작성 근거: 2026-09-21 기준 코드 실측. 숫자는 전부 실행해 확인한 값입니다.

---

## 1. 챌린지 적합도 재판단

> *"transforms how individuals and organizations **access knowledge**, **collaborate**,
> **make decisions**, and **complete everyday work**"*

네 개 축으로 지금을 채점하면:

| 축 | 현재 | 근거 |
|---|---|---|
| **make decisions** | **강함** | `cause.py` 가 네 도구를 합쳐 "왜 멈췄나"에 답하고, 설명 못 한 몫을 명시 |
| **complete everyday work** | 보통 | 메모/사진 → 수정안 → 승인. 다만 입구가 좁고, 회의록은 제안으로 이어지지 않음 |
| **access knowledge** | **약함** | Notion 을 읽지만 용도가 하나뿐(멈춘 이유 설명). 검색도, 축적도, 재사용도 없음 |
| **collaborate** | **거의 없음** | 사람에게 무언가를 알린다는 개념 자체가 없음. 전부 혼자 보는 화면 |

**말씀하신 요구는 정확히 약한 두 축을 겨냥합니다.**

- 특이사항 기록/추적 → *access knowledge*
- 구성원 동기화 → *collaborate*
- 회의록·음성 → 수정안 → *meeting intelligence + workflow automation* (챌린지가 명시한 방향)
- 템플릿 리포트 → *document intelligence* (역시 명시된 방향)

즉 **기능을 늘리자는 얘기가 아니라, 비어 있는 축을 메우자는 얘기**입니다. 방향이 맞습니다.

### 제안 기술 스택과의 관계

지금 억지로 끼워 맞출 필요가 없다는 점이 중요합니다. 새 요구를 제대로 만들면 필요해서
쓰게 됩니다:

| 요구 | 자연스럽게 따라오는 기술 |
|---|---|
| 음성 회의록 | Gemini 멀티모달 (오디오 네이티브) |
| 문서/PDF 회의록 | Document AI |
| 특이사항 축적·추적 | **Firestore** (contextual data) |
| 여러 프로젝트 롤업 | **BigQuery** |
| 과거 특이사항 검색 | **Vertex AI Search** |
| 다단계 자동 작업 | Agent Engine / ADK |

## 2. 말씀하신 항목 vs 실제 구현

| 말씀하신 것 | 상태 | 실제 |
|---|---|---|
| 보드 ↔ 실제 어긋난 지점 | ✅ 있음 | `signals.py`, 5종 탐지 |
| 회의록 → 일정 수정안 제안 | ⚠️ **절반** | 회의록을 읽고 작업에 연결까지 하지만, **설명에만 쓰고 제안으로 만들지 않음** |
| 짧은 메모(텍스트) → 수정안 | ✅ 있음 | `ingest.py` |
| 짧은 메모(이미지) → 수정안 | ⚠️ 합성 이미지로만 검증 | 실제 손글씨 미검증 |
| **음성 파일** → 수정안 | ❌ **없음** | `MIME` 에 오디오 없음 |
| 주간 리포트 발행 | ✅ 있음 | Markdown 고정 |
| **리포트 템플릿(프롬프트 기반)** | ❌ 없음 | 형식 하나 고정 |
| **docx / pptx / xlsx 출력** | ❌ 없음 | Markdown 만 |
| **프로젝트별 특이사항 기록/추적** | ❌ 없음 | 저장 계층 자체가 없음 |
| **구성원 동기화** | ❌ 없음 | 알림·전파 개념 없음 |
| **프로젝트 유형별 대시보드** | ❌ 없음 | 개발 프로젝트 가정 하나 |
| **임원용 롤업 뷰** | ❌ 없음 | 단일 프로젝트 상세만 |

### 구조적 전제 하나

**지금은 프로젝트가 하나뿐입니다** (`JIRA_PROJECT_KEY=ECHO`). 특이사항 추적 · 구성원
동기화 · 임원 롤업 · 유형별 뷰 – **네 개 모두 여러 프로젝트를 전제**합니다. 이걸 먼저
세우지 않으면 넷 다 반쪽이 됩니다. 순서의 문제가 아니라 전제의 문제입니다.

## 3. 제안 – "사람이 하기 번거로운 일" 기준

각 항목에 **왜 사람이 하기 싫은 일인지**를 붙였습니다. 그게 선정 기준이었습니다.

### A1. 회의록이 보드와 어긋나면 수정안을 낸다 ★ 최우선

> **사람이 하는 일:** 회의록을 읽고, 어느 티켓 얘긴지 짚고, 보드를 열어 지금 상태와
> 비교하고, 다른 곳만 골라 고친다. 회의마다. 매주.

이미 있는 조각: 회의록 읽기(Notion), 키 없이 작업에 연결(`linking.mentions`),
보드 상태 읽기. **없는 것은 "이 둘이 다르다 → 이렇게 고치자" 한 단계뿐입니다.**

```
회의록: "인증은 IdP 스펙 확정 전까지 다음 스프린트로 미루기로 함"
보드  : ECHO-16 기한 2026-09-02 (이미 지남), 상태 To Do

→ 제안  ECHO-16 기한 → 다음 스프린트 종료일
   근거  Incident response – 2026-09-14, Maya Okonkwo
   확신  0.81 (어휘 겹침으로 연결, 티켓 키 없음)
```

**정직성 규칙:** 회의록에 키가 없으므로 연결은 추론입니다. 확신도가 임계 미만이면
제안이 아니라 **질문**으로 냅니다 – 지금 `ingest.py` 가 하는 것과 같은 규칙.

**비용:** 작음. 기존 부품 조립.

---

### A2. 음성 회의 파일을 받는다 ★

> **사람이 하는 일:** 30분 회의를 다시 듣고, 결정만 추려 적고, 티켓에 옮긴다.

`ingest.py` 는 이미 멀티모달이고 Gemini 는 오디오를 네이티브로 받습니다.
`MIME` 에 `.m4a .mp3 .wav .ogg` 를 더하고, 전사(transcript)를 **증거로 남기는** 것이
핵심입니다 – 제안 옆에 "이 문장에서 나왔습니다"가 붙어야 승인할 수 있습니다.

**정직성 규칙:** 잘 안 들린 구간은 추측하지 않고 `[불명확]` 으로 남기고, 그 구간에서
나온 제안은 질문으로 강등합니다.

**비용:** 작음. Document AI 를 쓰면 PDF 회의록도 같은 입구로 들어옵니다.

---

### A3. 프로젝트 특이사항 레지스터 ★★ 새 축

> **사람이 하는 일:** "그때 그 이슈 어떻게 됐더라"를 슬랙·회의록·메일에서 찾는다.
> 대개 못 찾는다.

특이사항 = 프로젝트에서 **정상 흐름을 벗어난 사건**. 지금 시스템은 이걸 *발견*은
하는데(멈춤, 사고, 기록된 결정) **기억하지 못합니다.** 매번 처음부터 다시 계산합니다.

레지스터가 하는 일:

| 필드 | 어디서 오나 |
|---|---|
| 무슨 일이 | 회의록 문장 / 탐지된 신호 |
| 언제부터 | `cause.window.since` |
| 어느 작업에 | 추론된 연결 + 확신도 |
| 누구에게 영향 | 그 작업의 후행 작업 담당자들 |
| 며칠 잡아먹었나 | `cause.explained_days` |
| 지금 상태 | 열림 / 해소 / 방치 |

**이게 있으면 새로 되는 것:**
- 같은 원인이 **반복**되는지 (외부 스펙 변경이 이번 분기에 3번째)
- 특이사항이 **몇 일**을 먹었는지 누적
- **아직 안 닫힌** 것 목록

**비용:** 중간. **Firestore** 가 필요한 첫 기능입니다.

---

### A4. 알아야 할 사람에게만 알린다 ★★

> **사람이 하는 일:** 이슈가 생기면 누구에게 말해야 하는지 머릿속으로 의존 그래프를
> 훑는다. 빠뜨린다.

A3 의 "누구에게 영향"을 계산으로 냅니다 – **후행 작업 담당자 + 같은 영역 커밋 이력이
있는 사람**(`familiarity.py` 가 이미 계산). 화면에 알림으로 띄우고, 초안까지만 씁니다.

**정직성 규칙:** 에이전트는 **보내지 않습니다.** 대상과 초안을 제시하고 사람이 보냅니다.
`approve.py` 와 같은 게이트.

**비용:** 작음 (A3 위에).

---

### A5. 임원용 롤업 ★★

> **사람이 하는 일:** 프로젝트 5개 상태를 취합해 한 장으로 만든다. 매주.

**임원이 묻는 건 차트가 아니라 한 문장입니다** – "뭐가 문제고, 왜, 언제 풀리나".
그건 이 시스템이 이미 만들고 있습니다. 새 계산이 필요한 게 아니라 **프로젝트별로 돌려
정렬하면** 됩니다.

```
프로젝트      상태   종료일 변화        한 줄
────────────────────────────────────────────────────────────
Echo PMO      위험   10/13 → 11/09     외부 IdP 스펙 변경으로 인증이 13일째 멈춤
Disease       주의   09/30 → 10/02     리뷰 대기 2건
Kaneo         정상   11/20 → 11/20     –
```

**정직성 규칙 (여기가 제일 중요):** 임원 화면일수록 **설명 못 한 몫을 숨기고 싶어집니다.**
숨기면 이 프로젝트의 논지가 무너집니다. "13일 중 3.5일만 설명됨"을 접어두더라도
**펼치면 반드시 나와야** 합니다.

**비용:** 중간. 멀티 프로젝트 전제 필요. 롤업 집계에 **BigQuery** 가 맞습니다.

---

### A6. 프로젝트 유형별 뷰 ★

운영과 개발은 **보는 숫자가 다릅니다.**

| | 개발 | 운영 |
|---|---|---|
| 핵심 질문 | 언제 끝나나 | 지금 안정적인가 |
| 일정 | 임계 경로, 종료일 | 해당 없음 (상시) |
| 대신 볼 것 | – | 미해결 건수, 처리 시간, 재발률 |
| 코드 신호 | 멈춤, 상태 미갱신 | 핫픽스 빈도, 롤백 |

지금 화면은 **개발 프로젝트를 가정**하고 있어서, 운영 프로젝트에 대면 "종료일"이라는
말 자체가 무의미합니다.

**비용:** 중간. 계산은 대부분 재사용되고 어느 것을 보여줄지가 달라집니다.

### A7. 리포트 템플릿과 파일 형식 ★

> **사람이 하는 일:** 같은 내용을 임원용 PPT, 팀용 문서, 관리용 엑셀로 세 번 만든다.

프롬프트로 템플릿을 정의하고(`"임원 보고용, 1장, 위험 프로젝트만, 각 3줄"`)
docx / pptx / xlsx 로 냅니다.

**정직성 규칙:** 형식이 바뀌어도 **숫자는 같은 계산에서** 나와야 합니다. 템플릿은
배치와 분량만 정하고, 모델이 수치를 다시 쓰지 않습니다.

**비용:** 작음~중간. 파일 생성은 기성 라이브러리.

---

### A8. 에이전트가 스스로 도는 일 ★★

지금 에이전트는 **물어봐야 답합니다.** 번거로운 일의 상당수는 "물어볼 생각을 못 해서"
놓치는 것들입니다.

| 언제 | 무엇을 | 왜 사람이 못 하나 |
|---|---|---|
| 매일 아침 | 보드·코드·회의록 3자 대조 → 어긋난 것만 큐에 | 매일 40개 티켓을 세 군데와 대조할 사람이 없음 |
| 회의 **전** | 참석자들이 맡은 작업 중 멈춘 것 브리핑 | 회의 5분 전에 준비할 시간이 없음 |
| 회의 **후** | 음성/메모 → 수정안 | A1 + A2 |
| PR 정체 | 리뷰어에게 보낼 초안 | 누가 며칠째 막혀 있는지 추적이 안 됨 |
| 주 1회 | 리포트 발행 | 취합이 반나절 |
| 특이사항 발생 | 영향받는 사람 목록 | 의존 그래프를 머리로 훑어야 함 |

**정직성 규칙:** 전부 **큐에 쌓을 뿐 실행하지 않습니다.** 자동으로 도는 것은 *읽기와
계산*까지고, 쓰기는 언제나 사람이 누릅니다.

## 4. 안 하는 게 낫다고 보는 것

- **범용 챗봇 인터페이스.** "무엇이든 물어보세요"는 이 제품의 강점(정직한 회계)을
  흐립니다. 질문이 정해져 있는 게 장점입니다.
- **예측·추천 고도화** (ML 로 지연 예측 등). 논지가 *"모델은 숫자를 만들지 않는다"*
  인데 정면으로 충돌합니다.
- **자동 쓰기.** 승인 게이트를 없애면 남는 차별점이 없습니다.
- **Excel/PPT 를 먼저 만드는 것.** 데모는 잘 되지만 논지에 보태는 게 없습니다.
  A1~A5 뒤가 맞습니다.

## 5. 제안 순서

**0단계 – 전제** (멀티 프로젝트). A3·A5·A6 이 전부 여기 걸려 있습니다.

**1단계 – 지금 있는 걸 완성** (A1 회의록→제안, A2 음성). 부품이 다 있고, 챌린지가
명시한 *meeting intelligence* 에 바로 닿습니다.

**2단계 – 비어 있는 축** (A3 특이사항 레지스터, A4 동기화). *access knowledge* 와
*collaborate* 를 메웁니다. Firestore 가 들어옵니다.

**3단계 – 보는 사람에 맞추기** (A5 임원 롤업, A6 유형별 뷰).

**4단계 – 출력** (A7 템플릿/파일 형식).

**상시 – A8**(자동 실행)은 각 단계에서 만들어진 것을 스케줄에 얹는 것이라 따로 두지
않고 그때그때 붙이는 게 맞습니다.

## 6. 하나만 고른다면

**A1(회의록 → 수정안).** 이유:

1. 부품이 이미 다 있어서 가장 빨리 됩니다
2. 챌린지가 명시한 *meeting intelligence* 에 정확히 닿습니다
3. **"티켓 키 없는 회의록 문장을 작업에 연결한다"** 는 이미 측정된 강점(precision 1.00)을
   설명이 아니라 **행동**으로 바꿉니다
4. 데모에서 가장 잘 보입니다 – 회의록 한 문장이 보드 수정안이 되는 장면
